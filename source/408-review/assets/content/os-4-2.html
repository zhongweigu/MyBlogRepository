分页要解决的是“连续分配留下的外部碎片”。把进程地址空间切成等长的页，把主存切成同样大小的页框，页可以离散地放进任意空闲页框；再用一张页表记录“第几页放在第几框”。地址转换的核心只有一句：页号换成页框号，页内偏移不变。

一、页、页框、页表项、页表

概念含义注意
页进程逻辑地址空间中的等长块页号是逻辑概念
页框/物理块主存中的等长块页框号是物理概念
页表项 PTE记录“页号 → 页框号”及控制位存的是页框号，不是页号
页表一个进程一张，由页表项组成起始地址放 PCB/页表基址寄存器

一个进程有多少页，页表里就有多少个页表项；页表项按页号索引，所以页表项本身不需要再存页号。页表放在主存内核区，因为主存被划分为页框，页表也占页框；普通页表可以跨多个页框。

二、逻辑地址怎么切

页大小是 2 的幂。设页大小 4KB（2¹²），逻辑地址就切成：

页号 VPN = 逻辑地址 >> 12
页内偏移 offset = 逻辑地址 & 0x0FFF

页号位数决定页表项数：页号 n 位 → 2ⁿ 个页表项。页内偏移位数决定页大小：offset 12 位 → 4KB。多级页表则把页号再切：页目录号 | 页号 | 页内偏移。

三、地址转换与 TLB

  1. CPU 给出逻辑地址，拆成页号 + 页内偏移；
  2. 先查 TLB（快表）：命中直接得到页框号；
  3. 未命中，用页表基址寄存器 + 页号 × 页表项大小，找到 PTE；
  4. 检查页号是否越界（页表长度）、PTE 是否有效/权限是否允许；
  5. 取页框号，拼上页内偏移，得到物理地址；
  6. 把该映射填入 TLB，继续访问。

TLB 是页表项的高速缓存，不是“页表本身”。TLB 未命中不一定缺页：可能只是缓存没命中，查页表就能解决；PTE 的 present 位为 0 才是缺页。进程切换时 TLB 要刷新或切换 ASID，否则会用到别的进程的映射。

页表、TLB、cache 各自在查什么

同一个虚拟地址在访存过程中会被切成不同粒度：按页切得到“页号 + 页内偏移”，按 cache 块切得到“块号 + 块内偏移”。两者不是一回事：

结构查什么粒度位置/作用
页表页号 → 页框号页（通常 4KB）主存；完成虚拟地址到物理地址的转换
TLB页号（+ASID）→ 页表项页CPU 内；缓存页表项，减少查页表
cache物理地址的块号 → 数据cache 块（通常 64B）CPU/缓存层次；缓存主存数据，减少访存

典型顺序是：CPU 给虚拟地址 → TLB 查页号，命中得到页框号；未命中查页表；拼成物理地址后，再用物理地址的块号查 cache；cache 未命中才访问主存。页表/TLB 解决“地址在哪里”，cache 解决“数据在不在缓存”。把页当成 cache 块、或认为“查了页表就不用查 cache”，都会把两个层次混在一起。

基本分页和请求分页的区别

基本分页：进程的所有页在运行前一次性装入内存，页表项主要存页框号；没有“页不在内存”的缺页处理（至少不是虚拟存储意义上的按需调页）。它解决的是连续分配的外部碎片，地址转换仍然是“页号查页表”。

请求分页：只装入部分页，页表项增加有效位/存在位、修改位、访问位、外存地址等；访问到不在内存的页时触发缺页中断，由 OS 调入，再重新执行指令。请求分页是虚拟存储的实现方式，后面页面置换一节展开。两者都可能有页表/TLB，但“是否按需调页、是否有缺页中断”是分界。

TLB 是全局的，怎么区分不同进程？

每个进程有自己的页表，页号是“进程内”的；但 TLB 是 CPU 内的一个全局硬件结构，不能只靠页号区分进程。常见做法有两类：

  • 进程切换时刷新 TLB：把旧进程的映射全部清掉，简单但每次切换都有 TLB 冷启动开销；
  • 给 TLB 表项加 ASID/PCID 标签：TLB 命中时同时比较“页号 + 地址空间标识”，不同进程即使页号相同也不会串；切换进程只改 ASID，不必全刷新。

所以“TLB 全局只有一个”不等于“所有进程共享同一套页表映射”。全局的是硬件表项，区分靠刷新或 ASID；页表本身仍是每进程一份。

四、多级页表

单级页表在地址空间很大时会占太多连续内存：例如 32 位地址、4KB 页、4B PTE，页表有 2²⁰ 项，共 4MB，还要连续存放。多级页表把页表本身再分页，用一张页目录（顶级页表）记录各二级页表的位置。

  • 逻辑地址：页目录号 | 页号 | 页内偏移；
  • 页目录号查页目录，得到二级页表所在页框；
  • 页号查二级页表，得到目标页框；
  • 目标页框 + 页内偏移 = 物理地址。

多级页表的关键约束：每张页表最多占一个页框，这样页表可以离散存放，不需要一大片连续内存。页目录项个数 = 二级页表个数；二级页表项个数 = 每个二级页表能容纳的页数。页目录号 n 位 → 2ⁿ 个目录项；页号 n 位 → 每张二级页表 2ⁿ 项。

多级页表节省的是“未使用页表”的空间，不是免费：每增加一级就多一次访存（TLB 未命中时），所以级数不是越多越好。

考试题通常默认“所有页表都在主存”，但真实系统里，建立多级页表后，一些用不到的二级页表可以放在磁盘，页目录项的有效位为 0，需要时再调入。这样节省的是主存，不是页表项数量；缺页不只是数据页缺页，页表本身也可能缺页。

五、页表占多少内存

常用公式：

页表项数 = 2^(页号位数) = 进程页数
页表大小 = 页表项数 × PTE 大小
页表占页框数 = ceil(页表大小 / 页大小)

多级页表要逐级算：页目录大小 = 页目录项数 × 目录项大小；每个二级页表大小 = 二级页表项数 × PTE 大小；再分别除以页大小，向上取整。

题目给什么先算什么
逻辑地址位数、页大小页内偏移位数、页号位数、页数
页表项大小页表字节数、占多少页框
多级地址结构每级索引位数→每级表项数→每级表大小
PTE 的物理地址页表起始物理地址 + 索引 × PTE 大小

六、一个 32 位例子

32 位逻辑地址、4KB 页、PTE 4B：

  • offset 12 位，页号 20 位 → 2²⁰ 页；
  • 单级页表 2²⁰ × 4B = 4MB，占 1024 个页框；
  • 若改成二级页表：页目录号 10 位、页号 10 位、offset 12 位；
  • 页目录 2¹⁰ 项 × 4B = 4KB，正好一页；每个二级页表 2¹⁰ 项 × 4B = 4KB，也正好一页。

这样每张表都只占一个页框，页表可以离散存放；代价是 TLB 未命中时要访问页目录、二级页表，再多一次访存。

七、页表项里还有什么

页表项不只有页框号，还常有：

  • 有效位/present：页是否在内存；
  • 修改位 dirty：换出时是否需要写回；
  • 访问位：供 CLOCK/LRU 等算法使用；
  • 保护位：读/写/执行、用户/内核；
  • 外存地址：缺页时从哪调入。

这些位是请求分页/虚拟存储的基础；普通分页题如果只问“页框号”，不要把这些位和页框号混在一起算。

八、易错点与收束

  • “页表项存页号”：页表项存页框号，页号是索引。
  • “每个进程只有一张页表”：每个进程有自己的页表；多级页表还有页目录和多张二级页表。
  • “多级页表每张可跨多个页框”：多级页表的设计目标之一是每张表最多占一个页框，便于离散存放。
  • “TLB 未命中就是缺页”：TLB 未命中可以查页表；PTE 无效才是缺页。
  • “页表大小 = 页数 × 页大小”：页表大小 = 页表项数 × PTE 大小，不是页数 × 页大小。

把这一节收成一句话：页号查页表得页框号，偏移不变；多级页表把页表再分页，用页目录索引，每张表最多一页框。
