文件系统要随时知道“哪些磁盘块还能分配”。空闲表、空闲链表、位示图、成组链接是四种典型方法；它们不是互斥的“谁替代谁”，而是针对不同规模和分配方式的组织手段。

一、空闲表法

为所有空闲区建立一张表，每个表项记录起始盘块号 + 空闲盘块数，类似内存动态分区的空闲表。分配时找足够长的空闲区，回收时与相邻空闲区合并。

二、空闲链表法

把所有空闲盘块/盘区拉成链表：

  • 空闲盘块链：一个盘块一个结点，分配/回收以块为单位；
  • 空闲盘区链：一个连续空闲区一个结点，结点记录起始块号和块数。

三、位示图法

用一位表示一个盘块是否空闲（0/1 的约定要看清题目）。所有位组成位示图，字号和位号由盘块号换算：

字号 = 盘块号 / 字长
位号 = 盘块号 % 字长

位示图占用空间小，容易判断连续空闲块；但分配连续区时需要扫描位图，盘块数很大时扫描开销不可忽略。

四、成组链接法

成组链接把空闲盘块分组，每组用一个“栈”管理：

  • 栈顶记录本组可分配的空闲盘块号；
  • 栈底记录下一组所在的盘块号；
  • 栈底为 0 表示没有下一组；
  • 栈是临界资源，分配/回收要互斥。

栈里到底有什么

设一个栈最多存 100 个盘块号，当前有效项数为 S.n。其中栈底那一项不是普通数据块号，而是“下一组栈所在的盘块号”；其余 99 项才是本组可直接分配的空闲盘块号。

S.free[0]      = 300     // 栈底：下一组在盘块 300
S.free[1..99]  = 本组 99 个空闲盘块号
S.n            = 100     // 当前栈里共有 100 项

因此“栈满”是 100 项，“只剩栈底”是 S.n=1；这两个状态是分配流程的分界点。

分配流程：先看 S.n，再决定是否加载下一组

  1. S.n > 1：还有本组空闲块。从栈顶取出一个块号 b，S.n 减 1，把 b 分配给用户。这一步不需要读磁盘。
  2. S.n = 1：只剩栈底项，它指向下一组。先检查栈底值：
    • 若栈底为 0：说明没有下一组，系统已无空闲块，分配失败；
    • 若栈底为 b（非 0）：把磁盘块 b 中保存的“下一组栈内容”读入内存，替换当前栈；然后把 b 本身分配给用户。
  3. 读入下一组后，S.n 变成该组实际项数（通常又是 100），后续分配继续从新栈顶取。

关键点：栈底块 b 既是指向下一组的“链接块”，又是本组最后一个可分配的空闲块。所以不能先把 b 分配掉再读它——必须先读 b 的内容，把下一组栈调入内存，再分配 b；否则下一组的盘块号就丢了。

例子：当前 S.n=100，栈底为 300，其余 99 项是本组空闲块。

  1. 连续分配 99 次：每次取栈顶、S.n 减 1，最后 S.n=1，栈里只剩 300。
  2. 第 100 次分配：不能直接拿走 300。先把盘块 300 的内容读入内存，得到下一组栈（假设又有 100 项）；再把 300 分配给用户。
  3. 下一次分配从新栈顶取块；如果新栈底又是另一组，重复“读下一组 → 分配栈底块”。

回收流程：栈未满直接压，栈满先“搬家”

  1. S.n < 100：把回收块号压入栈顶，S.n 加 1。
  2. S.n = 100：栈已满。把当前这 100 项整体写入刚回收的盘块 b，然后把内存栈重置为“只有栈底 b、S.n=1”。这样 b 保存了旧的一组，同时成为指向旧组的链接块。
  3. 以后分配走到 S.n=1 时，再读 b，把旧组调回内存。

整个空闲盘块号栈是临界资源：分配和回收都要互斥，否则两个进程可能同时取到同一个栈顶块，或把栈计数改乱。

五、对比与易错点

方法组织单位优点缺点
空闲表连续空闲区适合连续分配，合并直观空闲区多时表大
空闲链表盘块/盘区分配回收简单链长时检索慢
位示图一位/盘块省空间，易找连续块大磁盘扫描慢
成组链接分组 + 栈适合大容量，内存占用可控栈操作要互斥，逻辑复杂
  • “位示图一位对应一个字节”：一位对应一个盘块；要按字长换算字号/位号。
  • “成组链接的栈底也是普通空闲块”：栈底存下一组位置，分配时要特殊处理。
  • “空闲表法适合离散分配”：空闲表按连续区记录，天然适合连续分配。

把这一节收成一句话：空闲表管连续区，空闲链表管块/区，位示图用一位管一块，成组链接用“分组栈”把大磁盘的空闲块号压进有限内存。
