调度算法不是一堆名字，而是在“先来后到、短作业优先、响应比、优先级、时间片、多队列”这些规则里做选择。每个算法都要回答四个问题：怎么选、能不能抢占、对谁有利、会不会饥饿。这一节把常见算法放在同一张表里比较，再用一组小例子算一遍。

一、FCFS：先来先服务

按进程到达就绪队列的先后顺序调度，非抢占。实现最简单，但会出现护航效应：一个长作业先到，后面所有短作业都要等它跑完。

  • 对长作业、CPU 繁忙型进程有利；
  • 对短作业、I/O 繁忙型进程不利；
  • 平均等待时间通常较差，但不会饥饿。

二、SJF / SRTN：短作业优先

SJF（Shortest Job First）每次选估计运行时间最短的作业，通常是非抢占。若新到作业比当前作业的剩余时间更短就抢占，则是 SRTN（Shortest Remaining Time Next）。

SJF 在“所有作业同时可运行、非抢占”的前提下，平均等待时间最优：把短作业放前面，后面所有作业的等待时间都会减少。这个结论可以用交换相邻作业的顺序证明，但前提是运行时间已知、没有抢占和 I/O 干扰。

  • 优点：平均等待/周转时间短；
  • 缺点：需要预知运行时间（通常只能估计），长作业可能饥饿；
  • SRTN 响应更好，但抢占和估计误差的代价更大。

三、HRRN：高响应比优先

HRRN 每次选择响应比最高的作业：

$$R = \frac{\text{等待时间} + \text{要求服务时间}}{\text{要求服务时间}}$$

等待时间越长，响应比越高；要求服务时间越短，响应比也越高。这样既照顾短作业，又让长作业随着等待变久而“涨价”，缓解 SJF 的长作业饥饿。HRRN 通常是非抢占的，在当前作业结束/阻塞时重新计算。

  • 优点：兼顾短作业和长作业，不会无限饥饿；
  • 缺点：每次调度都要计算响应比，且仍需预知服务时间。

四、优先级调度

每个进程有一个优先级，调度器选优先级最高的。优先级可以是静态（创建时确定）或动态（随等待时间/运行情况调整）；可以是抢占或非抢占。

  • 优点：能体现任务重要性，适合实时/交互系统；
  • 缺点：低优先级进程可能饥饿；
  • 解决：老化（aging）——等待越久，优先级逐渐提高。

“优先级高”不等于“运行时间短”；优先级调度和 SJF 是两套不同的选择标准，不要混。

五、时间片轮转 RR

就绪进程排成队列，每个进程执行一个时间片 q；时间片用完，时钟中断把进程排到队尾，调度下一个。RR 是抢占式的，但抢占只由时间片触发。

  • q 太大 → 退化为 FCFS，响应变慢；
  • q 太小 → 切换/分派开销占比高，吞吐量下降；
  • 适合分时/交互系统，响应较公平；
  • 对短作业友好，但所有进程都要排队，长作业也不会饥饿。

RR 的“公平”是就绪队列层面的公平，不是按优先级；如果系统有优先级，通常会把优先级和时间片结合（多级队列/MLFQ）。

六、多级队列与多级反馈队列

多级队列把不同类型的进程放进不同就绪队列，例如前台交互队列用 RR、后台批处理队列用 FCFS；队列之间固定优先级，只有高优先级队列空时才调度低优先级队列。它的问题是低优先级队列可能饥饿。

多级反馈队列（MLFQ）让进程在队列之间动态移动：

  • 设置多个就绪队列，优先级从高到低；
  • 优先级越高的队列，时间片越小；优先级越低的队列，时间片越大；
  • 每个队列内部通常用 FCFS；
  • 新进程进入最高优先级队列；
  • 仅当第 1～i−1 级队列为空时，才调度第 i 级队列；
  • 进程用完整个时间片还没完成，就降入下一级队列；
  • 因 I/O 阻塞的进程，阻塞结束后通常回到原队列（具体规则看题目）；
  • 如果更高优先级队列来了新进程，当前进程被抢占，放回本级队尾。

MLFQ 兼顾交互响应和吞吐量：交互型短作业在高优先级队列很快完成；CPU 密集型长作业逐级下降，用更大的时间片减少切换。代价是规则复杂，低优先级队列仍可能饥饿，需要定期提升（boost）所有进程的优先级来兜底。

九、作业调度还是进程调度

同一个算法名字，放在“作业调度”和“进程调度”里，输入队列和代价不一样。作业调度从外存选作业进入内存，频率低、要分配资源；进程调度从就绪队列选进程上 CPU，频率高、只切换 CPU。

算法作业调度进程调度说明
FCFS常用可用按到达顺序；作业/进程都可
SJF常用可用需要预知/估计运行时间；作业调度更典型
HRRN常用可用响应比需要等待时间和服务时间
优先级常用常用作业优先级和进程优先级可以分开设
RR不常用常用作业没有“时间片轮转”的语义；RR 面向就绪进程
多级队列/MLFQ不常用常用按进程类型/行为动态调整，属于进程调度

所以“FCFS、SJF、HRRN 适合批处理作业调度；RR、优先级、MLFQ 更适合分时/交互的进程调度”是常见搭配，但不是绝对禁令：SJF 也能做进程调度，只是要估计 CPU burst。

十、SJF 最优的前提

“所有作业同时到达、运行时间已知”时，SJF 的平均等待时间和平均周转时间最优。原因可以用交换论证：如果两个相邻作业中长的在前、短的在后，交换它们不会影响前面作业的完成时间，但会让短作业提前完成，后面作业的等待时间总和减少；不断交换，直到短作业在前。

这个结论有条件：

  • 所有作业在 t=0 同时到达（或都可立即运行）；
  • 运行时间已知且不变；
  • 非抢占、无 I/O 阻塞、切换开销忽略；
  • 平均周转 = 平均等待 + 平均服务时间，服务时间总和固定，所以两者同时最优。

如果到达时间不同，非抢占 SJF 不一定最优（CPU 可能先跑一个长作业，而短作业马上就到）；抢占式 SRTN 在“已知剩余时间”的前提下更优。考试如果说“同时到达”，就按上面的前提用 SJF；如果说“随时到达”，要看清是否允许抢占。

十一、切换和新进程同时发生

调度题有时会让“时间片用完”和“新进程到达”落在同一时刻。算法本身没有规定事件顺序，所以必须先约定：

  • 抢占式优先级：新进程优先级更高就抢占；更低就让当前进程继续/按时间片处理。优先级相同再按队列规则。
  • RR：时间片用完的进程和新到进程都要入就绪队列；常见约定是“先处理时间片到期，把当前进程放队尾，再让新进程入队”，但也可反过来。题目没规定时，写清你的假设。
  • SJF/SRTN：比较服务时间/剩余时间；相同则按到达先后，仍相同用 PID 等确定性规则。
  • FCFS：按到达先后；完全相同则任意/按 PID。

考试通常避免“完全同时”的歧义，或者明确“同时到达按编号/按到达先处理”。真正实现里用事件队列和时间戳排序，保证确定性；不要在两个约定之间反复横跳，否则同一组数据会算出不同答案。

十二、多处理机调度

多处理机/多核调度要多考虑两件事：把任务放哪个 CPU，以及任务在 CPU 之间迁移的代价。

1. 非对称 vs 对称

方式做法优点缺点
非对称多处理（AMP）一个主处理器负责调度/I/O，其他处理器执行任务实现简单，控制集中主处理器瓶颈/单点故障，扩展性差
对称多处理（SMP）每个 CPU 都运行调度器，共享就绪队列/锁可扩展、负载更均衡并发访问队列要加锁，缓存一致性/迁移开销

2. 处理器亲和性

亲和性是“尽量让任务继续在同一个 CPU 上跑”，因为该 CPU 的 Cache/TLB 还留着它的数据。软亲和允许迁移，只是优先留在原 CPU；硬亲和用绑定把任务钉在某个 CPU 上，不再迁移。硬亲和适合实时/性能敏感任务，但会降低负载均衡能力。

3. 就绪队列：公共 vs 私有

队列负载均衡亲和性问题
公共就绪队列好：空闲 CPU 直接取队首弱：任务可能被任意 CPU 取走全局队列锁竞争、缓存冷启动
私有就绪队列差：某个 CPU 可能空闲，另一个积压好：任务倾向留在本 CPU需要迁移机制来平衡

注意别记反：公共队列“好平衡、弱亲和”，私有队列“好亲和、难平衡”。公共队列不是“亲和性好”，它恰恰容易让任务换 CPU。

4. 推迁移与拉迁移

  • 推迁移（push migration）：某个 CPU 发现自己负载过高，主动把任务推到其他 CPU 的就绪队列；
  • 拉迁移（pull migration）：某个 CPU 空闲，主动从忙 CPU 的队列拉任务；
  • 实际系统常两者结合，周期性检查 + 事件触发；迁移要考虑亲和性、NUMA 距离和迁移成本。

十三、易错点

  • “SJF 一定最好”：只在平均等待时间这个指标、特定前提下最优；长作业会饥饿。
  • “FCFS 对短作业友好”：长作业先到会拖住后面短作业，产生护航效应。
  • “HRRN 是抢占式”：通常非抢占，当前进程结束/阻塞时才重新计算。
  • “RR 时间片越小越好”：太小导致频繁切换，分派开销占比升高。
  • “MLFQ 优先级越高时间片越大”：通常相反，高优先级队列时间片更小。
  • “多级队列 = 多级反馈队列”：前者队列固定、进程不移动；后者进程会降级/提升。

把这一节收成一句话：FCFS 看到达，SJF 看服务时间，HRRN 看等待/服务比，优先级看重要程度，RR 看时间片，MLFQ 看“多队列 + 动态降级”。
