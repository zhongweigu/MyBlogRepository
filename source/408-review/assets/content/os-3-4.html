哲学家进餐考的不是“怎么吃”，而是一个进程需要同时占有多个资源才能继续时，资源申请顺序会不会形成环。每个哲学家先拿左筷子、再拿右筷子；如果五个人同时拿起左筷子，再等右筷子，就形成循环等待。

一、问题与死锁根因

五位哲学家围圆桌，五根筷子放在两两之间；吃饭需要左右两根，思考不需要。若每个人先拿左、再拿右：

  • 五个人同时拿起左筷子，每人都持有一根；
  • 每个人再请求右筷子，而右筷子在右边的人手里；
  • 形成 P0 等 P1、P1 等 P2……P4 等 P0 的循环等待。

死锁四条件里，互斥（筷子只能一个人用）通常不能破坏；真正要破坏的是请求并保持或循环等待。三种经典解法分别从“限制人数”“原子拿两只”“改变申请顺序”入手。

二、方法 1：最多 4 人

增加一个计数信号量 count=4，限制同时参与抢筷子的人数：

semaphore count = 4;                 // 最多 4 人同时竞争
semaphore chopsticks[5] = {1,1,1,1,1};

philosopher(int i) {
    while (1) {
        think();
        P(count);                     // 拿到“就餐资格”
        P(chopsticks[i]);             // 左
        P(chopsticks[(i + 1) % 5]);   // 右
        eat();
        V(chopsticks[i]);
        V(chopsticks[(i + 1) % 5]);
        V(count);                     // 归还就餐资格
    }
}

为什么不会死锁？五个人里最多四个能同时参与，至少一个人拿不到左筷子；不可能出现“五个人各持一根左筷子”的闭环。最终至少有一人能拿到两只、吃完释放，其他人再继续。

代价：限制并发度；它不保证公平，某个哲学家仍可能长期抢不到。

三、方法 2：原子拿两只

用一个 mutex 把“拿左 + 拿右”包成原子操作：要么两只都拿到，要么不拿：

semaphore chopsticks[5] = {1,1,1,1,1};
semaphore mutex = 1;                 // 保护“拿两只”的过程

philosopher(int i) {
    while (1) {
        think();
        P(mutex);
        P(chopsticks[i]);
        P(chopsticks[(i + 1) % 5]);
        V(mutex);                    // 两只都拿到后释放入口锁
        eat();
        V(chopsticks[i]);
        V(chopsticks[(i + 1) % 5]);
    }
}

它破坏“请求并保持”：哲学家不会拿着一只筷子去等另一只，因为拿两只的过程被串行化了。代价是拿筷子阶段完全串行，并发度低；如果右筷子不可用，当前哲学家会持有 mutex 阻塞，其他人也不能尝试，直到筷子释放。

四、方法 3：奇偶顺序

奇数号哲学家先左后右，偶数号先右后左：

semaphore chopsticks[5] = {1,1,1,1,1};

philosopher(int i) {
    while (1) {
        think();
        if (i % 2 == 1) {
            P(chopsticks[i]);             // 奇数：先左
            P(chopsticks[(i + 1) % 5]);   // 再右
        } else {
            P(chopsticks[(i + 1) % 5]);   // 偶数：先右
            P(chopsticks[i]);             // 再左
        }
        eat();
        V(chopsticks[i]);
        V(chopsticks[(i + 1) % 5]);
    }
}

相邻哲学家的拿取顺序相反，不会出现“所有人都先拿左、再等右”的环。它破坏的是循环等待，实现也简单；但编号必须固定，且仍不解决饥饿。

五、三种方法对比

方法破坏什么优点代价
最多 4 人限制同时竞争，避免五人各持一根简单，易记并发度降低，不保证公平
原子拿两只请求并保持不会出现“拿一只等另一只”拿筷子串行，吞吐低
奇偶顺序循环等待并发较好，代码简单依赖编号，不保证公平

六、怎么判断方案对不对

判断一个哲学家方案，不要只看“能不能吃”，要看：

  1. 是否可能出现每个人都持有一根筷子、再等另一根？
  2. 如果出现等待，是否一定有人能推进并释放资源？
  3. 筷子的 P/V 是否成对？异常路径是否释放？
  4. 是否限制了资源数量/申请顺序，而不是只加了一个没用的 mutex？

例如“只给每个人加一把 mutex 保护拿左筷子”并不能防止五个人各持一根；互斥只保护单个筷子的操作，不改变“持有并等待”的结构。

七、易错点与收束

  • “最多 4 人一定公平”：只保证不死锁；某个哲学家仍可能饥饿。
  • “奇偶顺序改变了筷子数量”：筷子仍是 5 根，每人仍要 2 根；改变的是申请顺序。
  • “原子拿两只没有代价”：mutex 串行化拿筷子，并发度下降。
  • “哲学家问题只考死锁”：也可能问资源数量、P/V 顺序、饥饿与公平。

把这一节收成一句话：哲学家死锁的根因是“持有并等待 + 循环等待”；限制人数、原子拿两只、奇偶顺序分别从不同角度破环。
