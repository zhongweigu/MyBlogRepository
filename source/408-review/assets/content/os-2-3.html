CPU 调度只做一件事：在若干可运行的进程/线程里，选一个把 CPU 交给它。但“选谁”会同时影响响应速度、吞吐量、公平性和切换开销，所以调度题的核心不是背算法名字，而是先明确调度发生在什么时候、用什么指标评价、哪些时刻不能切。

一、调度分几层

操作系统里的“调度”不止一种，按对象和频率可以分成：

层次调度对象频率作用
高级调度（作业调度）作业/批处理任务低决定哪些作业进入内存、成为进程
中级调度（对换调度）进程/页中在内存与外存之间对换，调整驻留集
低级调度（CPU 调度）就绪进程/线程高从就绪队列选一个，分配 CPU

本章默认说的是低级调度。它发生在就绪队列非空、CPU 需要重新分配时；批处理系统还可能有作业调度，分时/实时系统更关注低级调度的响应。

三级调度怎么对上七状态模型

调度主要作用的状态边说明
高级调度创建 → 就绪决定作业是否被接纳、是否建立 PCB/分配内存，控制多道程度
中级调度就绪 ↔ 就绪挂起；阻塞 ↔ 阻塞挂起把整个进程映像换出/换入，缓解内存压力；不是换页
低级调度就绪 → 运行；运行 → 就绪从就绪队列选进程上 CPU；时间片/抢占造成反向边

七状态模型里的“就绪挂起/阻塞挂起”正是中级调度的落点：进程被换到外存，但 PCB 还在；事件发生时，阻塞挂起先变就绪挂起，等换入后才变就绪。高级调度决定“进不进系统”，中级调度决定“在不在内存”，低级调度决定“谁上 CPU”。

二、调度器与分派器

“调度”和“分派”经常连在一起，但不是同一件事：

  • 调度器（scheduler）：按算法从就绪队列选出下一个进程；
  • 分派器（dispatcher）：执行切换动作——保存旧现场、恢复新现场、切换地址空间/栈、从内核态返回用户态并跳到新进程的 PC。

分派器完成一次切换所需的时间叫分派延迟。它不直接提高吞吐量，反而是纯开销；所以时间片不能无限小，线程/进程切换也不能太频繁。

三、抢占式与非抢占式

方式切换条件优点缺点
非抢占进程运行完、主动阻塞、异常终止才切换实现简单，切换少，内核数据更稳定一个长作业/死循环会拖住其他进程，响应差
抢占时间片用完、更高优先级到达、紧急事件响应快，适合分时/实时切换开销大，共享数据要加锁，调度更复杂

“抢占”不是随便打断指令：通常发生在指令边界或安全点；内核临界区、中断处理、原子操作中一般不能切。

常见抢占原则有三类：更高优先级到达、更短剩余时间到达（SRTN）、时间片用完。前两类是“新任务更该跑”，第三类是“当前任务跑够了”；优先级相同/剩余时间相同再按到达顺序或队列规则。

四、什么时候调度，什么时候不能切

1. 会触发调度的时机

  • 主动放弃：进程正常结束、异常终止、请求 I/O 而阻塞、调用 yield；
  • 被动放弃：时间片用完、更高优先级进程进入就绪队列、发生需要立即处理的紧急事件。

注意“阻塞”是进程主动请求 I/O 导致的；“时间片用完”是时钟中断导致的；“更高优先级到达”是抢占。三者都可能触发调度，但原因不同。

2. 不能切换的情况

  • 正在处理中断：中断上下文还没保存/恢复完，切换会破坏现场；
  • 进程处于内核临界区：正在修改内核共享数据结构，切走可能导致别人看到半成品；
  • 执行原子操作/关中断期间：临界区必须一次完成。

这些情况下，内核会设置“需要调度”的标志，等退出临界区/中断处理后再调度，而不是强行切走。

五、五个评价指标

指标定义说明
CPU 利用率CPU 忙碌时间 / 总时间希望高，但受 I/O 等待限制
吞吐量单位时间完成的作业/进程数批处理系统关心
周转时间完成时刻 − 到达时刻从提交到完成的总时间，含等待和运行
等待时间在就绪队列中等待的总时间不含运行时间，也不含阻塞等待 I/O 的时间
响应时间首次响应时刻 − 提交/到达时刻交互系统关心，首次响应不是完成

常用公式：

$$T_{\text{周转}} = T_{\text{完成}} - T_{\text{到达}},\qquad T_{\text{等待}} = T_{\text{周转}} - T_{\text{实际服务}}$$

平均周转时间、平均等待时间就是对所有进程求平均。响应时间只看到“第一次被响应”，不要求作业完成；分时系统更关心它。

上面的等待时间公式默认只考虑 CPU 调度、进程没有 I/O 阻塞；如果进程中途等待 I/O，周转时间还包含阻塞时间，不能直接用“周转 − 服务”当成就绪队列等待时间。

六、目标冲突与线程调度

调度目标通常包括：CPU 利用率高、吞吐量大、周转时间短、等待时间短、响应快、公平、开销低。这些目标经常冲突：

  • 时间片小 → 响应快，但切换开销大、吞吐量下降；
  • 优先短作业 → 平均等待时间短，但长作业可能饥饿；
  • 优先高优先级 → 重要任务及时，但低优先级可能长期得不到 CPU。

所以没有“万能算法”，只有“在某个目标下合适”。考试给出一组进程和算法，就是让你按该算法的规则算指标，而不是比较哪个算法绝对最好。

线程调度方面：KST 由内核直接调度线程；ULT 则由内核先调度进程，再由用户空间线程库调度线程。多核上 KST 能把同一进程的多个线程分到不同 CPU，ULT 通常做不到。

七、进程切换：保存现场和中断有什么不同

“保存现场”不是中断的专利，但两者保存的范围和目的不同。中断响应是硬件/内核入口保存“能回到被打断指令”的最小状态；进程切换是操作系统决定换一个进程，要保存“整个进程下一次还能继续”的完整上下文。

对比中断响应/处理进程切换
触发外部中断、异常、陷入调度器决定换进程（可能由中断触发）
保存者CPU 硬件保存 PC/PSW；处理程序按需保存通用寄存器操作系统保存完整现场到旧 PCB
保存内容断点、PSW，必要时通用寄存器通用寄存器、PC、PSW、SP、浮点/SIMD、页表基址等
地址空间通常不换，仍是被中断进程切到新进程的页表/TLB/栈
结果处理完可返回原进程当前进程变成另一个进程

一次时钟中断可能只让内核记一笔账，然后返回原进程；也可能在中断返回前触发调度，变成进程切换。所以“中断”是入口，“切换”是调度决策的结果，不能画等号。

进程切换的 PCB 流程

  1. 保存当前进程的 CPU 现场到它的 PCB（或内核栈）；
  2. 把当前进程的 PCB 状态改为就绪/阻塞，插入相应队列；
  3. 调度器按算法从就绪队列选下一个进程；
  4. 更新被选进程的 PCB 状态为运行；
  5. 切换地址空间：加载新进程的页表基址，刷新/切换 TLB、切换内核栈；
  6. 从新进程的 PCB 恢复寄存器、PC、PSW、SP；
  7. 返回用户态，跳到新进程的断点继续执行。

现场保存的细节各架构不同：有的用硬件保存 PSW/PC，有的用一条指令保存全部寄存器；浮点/SIMD 状态可能惰性保存。但“旧 PCB 存现场、新 PCB 取现场、更新队列/页表”这个骨架不变。

八、闲逛进程、保证调度与公平分享

1. 闲逛进程（idle process）

当就绪队列为空时，调度器不能“不选”。系统通常保留一个闲逛进程（idle，PID 0/swapper）：优先级最低、永远就绪，只有在没有其他可运行进程时才被选中；它执行 halt/低功耗循环，顺便做统计或回收。它不是用户进程，也不参与普通优先级竞争；有活干时立刻被抢占。

2. 保证调度（guaranteed scheduling）

保证调度给每个进程一个“应得份额”：如果有 n 个进程，每个应得约 1/n 的 CPU。系统记录每个进程实际已用 CPU / 应得 CPU，优先选比值最小的进程，让实际份额追上应得份额。进程数变化时重新计算 1/n；新进程加入后，老进程的份额会被稀释。

3. 公平分享调度（fair-share scheduling）

公平分享不是按“进程”平均，而是按用户/组/权重分配 CPU。例如两个用户，A 有 9 个进程、B 有 1 个进程；如果按进程平均，A 会拿到 90% CPU；公平分享让 A、B 各得约 50%，再在 A 的内部 9 个进程之间分配。实现上可用权重、虚拟运行时间（如 CFS 的 vruntime）或彩票/份额算法。

保证调度和公平分享都不是“绝对平均”：前者保证每个进程的应得份额，后者保证用户/组的份额；它们都会考虑权重，避免“进程多的人占便宜”。

九、为什么要调度；分时与实时怎么选

为什么要 CPU 调度：CPU 只有一个（或少数几个），进程数通常远多于 CPU；通过调度把 CPU 在就绪进程间复用，才能提高利用率、吞吐量和响应速度，并保证重要任务/用户之间的公平。没有调度，一个进程会独占 CPU，其他进程永远等不到。

场景首选原因
批处理FCFS、SJF、HRRN吞吐量/平均周转优先，交互性要求低
分时/交互RR、MLFQ、优先级+老化要快速响应、防止单个进程长时间占用
实时优先级抢占、RM/EDF必须在截止期内完成，确定性比平均吞吐更重要

分时系统适合时间片轮转/多级反馈队列，因为每个进程都能在较短时间内被响应；实时系统适合优先级抢占（周期任务用速率单调 RM，动态截止期用最早截止期优先 EDF），因为错过截止期的代价可能比吞吐量下降大得多。FCFS/SJF 不适合硬实时，因为无法保证新到高优先级任务的响应时间。

十、易错点与收束

  • “等待时间 = 周转时间”：等待时间只算在就绪队列里等 CPU 的时长，不含运行时间；周转时间从到达算到完成。
  • “响应时间 = 周转时间”：响应只看第一次被响应，作业可能还没完成。
  • “非抢占一定更好”：切换少但响应差，长作业会拖住其他进程。
  • “任何时刻都能切换”：中断处理、内核临界区、原子操作期间通常不能切。
  • “调度只发生在进程结束时”：时间片用完、更高优先级到达、阻塞都会触发调度。
  • “调度是用户态做的”：低级调度由内核完成，需要内核态权限和现场切换。

把这一节收成一句话：调度 = 选谁 + 何时选 + 用什么指标评价；先分清抢占/非抢占和不能切的区间，再谈具体算法。
