死锁不是“某个进程等太久”，而是一组进程互相等待对方手里的资源，没有外力介入就永远推进不了。它和饥饿的区别、四个必要条件的用法、银行家算法怎样判断安全状态，是这一节的主线。

一、死锁的定义与饥饿的区别

死锁：一组进程中的每一个进程都在等待一个事件，而这个事件只能由该组中的其他进程引发。直白地说，大家各自占着一些资源，又在等别人释放，形成闭环，谁都动不了。

饥饿：进程长期得不到 CPU 或某类资源，推进被明显延迟，但系统仍然可能推进；只要调度策略改变或资源到来，它还有机会。死锁是“没有外力就永远无法推进”，饥饿是“可能永远轮不到，但不是互相等待的闭环”。

对比死锁饥饿
本质循环等待，进程互相卡死长期得不到资源/CPU
能否自行恢复通常不能，需要外部干预调度策略改变后可能恢复
涉及进程至少两个（单进程也可能自锁）可以只有一个
典型原因资源分配不当、P 顺序相反优先级/短作业优先导致低优先级长期等待

二、四个必要条件

条件含义破坏思路
互斥资源一次只能被一个进程占用尽量把资源改造成可共享（如 SPOOLing），但很多资源不能
请求并保持已持有至少一个资源，又请求新资源且不释放旧的一次性申请全部资源；或请求新资源前先释放已有资源
不可抢占已分配的资源不能被强行夺走允许剥夺，或要求进程回退
循环等待存在进程—资源的循环等待链给资源编号，按序申请

四个条件是“必要条件”不是“充分条件”：同时满足才可能死锁；破坏其中一个就不会因这四个条件组合而死锁。预防就是付出资源利用率/并发度的代价去破坏其中一个。

三、资源分配图与化简

资源分配图：进程画成圆圈，资源画成方框，方框里的圆点表示该类资源的实例数；请求边是进程 → 资源，分配边是资源 → 进程。

  • 单实例资源：图中出现环 → 一定死锁；没有环 → 一定无死锁。
  • 多实例资源：有环不一定死锁，要看能否把所有边都消掉（化简）。

化简方法：找一个“请求量不超过当前可用资源”的进程，假设它运行完并释放资源，删除它的边、增加可用资源；重复。若最后能消掉所有边，图可完全简化，无死锁；否则死锁。

四、死锁预防：破坏条件

  • 破坏互斥：把独占资源改造成共享（如打印机的 SPOOLing 队列）。但很多资源本质上不能共享，通用性差。
  • 破坏请求并保持：进程一次性申请所有资源；或申请新资源前释放已持有的资源。前者资源利用率低，后者可能反复申请/释放。
  • 破坏不可抢占：允许抢占资源，被抢的进程回退/重试。实现复杂，可能丢失工作。
  • 破坏循环等待：给资源编号，所有进程按递增顺序申请，不能反向。简单有效，但编号可能与实际使用顺序冲突，降低并发。

预防是静态的策略：在分配前就限制请求方式，保证死锁不会发生，代价是资源利用率/并发度。

五、安全状态与不安全状态

系统处于安全状态：存在一个进程推进顺序（安全序列），按这个顺序，每个进程都能获得它尚需的资源并顺利完成。安全状态一定不会死锁。

不安全状态：找不到安全序列。它只是“可能死锁”，不是“已经死锁”；系统仍可能因为实际请求顺序不同而完成，但无法保证。

状态是否存在安全序列是否一定死锁说明
安全存在不会可按安全序列分配
不安全不存在可能可能死锁，也可能侥幸完成
死锁不存在已经已经形成循环等待

六、银行家算法

银行家算法属于死锁避免：每次请求时先“试分配”，再用安全性算法检查是否仍存在安全序列；安全才真正分配，不安全就回滚并让进程等待。

需要的矩阵：

  • Available：当前可用资源向量；
  • Max：每个进程的最大需求；
  • Allocation：已分配；
  • Need = Max − Allocation：尚需。

安全性算法：令 Work = Available，反复找一个 Need_i ≤ Work 且未完成的进程，假设它完成并释放 Allocation_i，令 Work += Allocation_i；能找完所有进程就安全，否则不安全。

请求处理：检查 Request_i ≤ Need_i 且 Request_i ≤ Available；试分配后运行安全性算法；安全则提交，不安全则回滚、让进程等待。

一个安全例子

进程Allocation (A,B,C)Need (A,B,C)
P1(1,0,0)(1,0,0)
P2(0,1,0)(2,1,0)
P3(0,0,1)(1,0,1)

当前 Available = (2,2,0)。按 P1 → P2 → P3：

  • P1 需要 (1,0,0) ≤ (2,2,0)，完成后 Work = (3,2,0)；
  • P2 需要 (2,1,0) ≤ (3,2,0)，完成后 Work = (3,3,0)；
  • P3 需要 (1,0,1) ≤ (3,3,0)，完成后 Work = (3,3,1)。

所以安全序列是 P1, P2, P3（可能不唯一），系统安全。

八、检测与解除

检测：定期检查资源分配图/等待图。单实例资源可用等待图找环；多实例资源用化简算法。检测频率越高，发现越早，但开销越大。

解除：

  • 资源剥夺：从某些进程强行拿走资源，分配给死锁进程；被剥夺者回退/重试；
  • 撤销进程：终止一个或多个死锁进程，释放资源；
  • 进程回退：让进程回退到某个检查点，重新执行。

选择“受害者”要综合考虑优先级、已运行时间、剩余工作量、资源类型和回退代价，避免同一进程反复被选中而饥饿。

九、易错点与收束

  • “有环一定死锁”：单实例资源图有环一定死锁；多实例有环不一定，需化简。
  • “不安全一定死锁”：不安全只是可能死锁；系统仍可能完成。
  • “死锁 = 饥饿”：死锁是循环等待、无法推进；饥饿是长期得不到资源但可能推进。
  • “破坏互斥最容易”：很多资源必须互斥；通常从请求并保持、不可抢占、循环等待入手。
  • “银行家算法能预防所有死锁”：它要求预知 Max，只保证不进入不安全状态；实际系统未必采用。
  • “安全序列唯一”：安全序列可能不唯一，找到一个就说明安全。

把这一节收成一句话：死锁看四个条件和循环等待；预防靠破坏条件，避免靠银行家算法保持安全，检测靠资源图化简，解除靠剥夺/撤销/回退。
