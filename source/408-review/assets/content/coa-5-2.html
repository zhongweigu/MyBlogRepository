中断与异常

中断通常指外中断：I/O 设备完成、时钟中断、键盘等来自 CPU 外部的事件。它一般在下一条指令执行前被检查；可屏蔽中断可以用 IF 标志屏蔽，不可屏蔽中断（如电源故障）不能。

异常（内中断）由当前指令的执行引起：缺页、除零、非法指令、断点、系统调用等。按恢复方式分为故障（fault，处理后重新执行当前指令）、陷阱（trap，处理后执行下一条指令）和终止（abort，无法恢复）。

中断向量表保存各中断服务程序的入口地址。多个请求同时到达时，按中断优先级排队；高优先级可以打断低优先级的服务程序，形成中断嵌套。

中断响应过程

CPU 在一条指令执行结束后检查中断请求。响应过程可以概括为：

  1. 关中断：防止响应过程被新的中断打断；
  2. 保存断点：把当前 PC（下一条指令地址）压栈或存入指定单元；
  3. 保存现场：保存通用寄存器和程序状态字等，服务程序返回后要恢复；
  4. 识别中断源：通过中断向量或排队器确定服务程序入口；
  5. 转中断服务程序：执行设备服务，结束后恢复现场、开中断、返回。

关中断、保存断点等由硬件自动完成，称为中断隐指令；它不是一条真正的机器指令，而是响应中断时硬件执行的一组微操作。保存通用寄存器通常由服务程序用指令完成。

中断响应发生在指令执行结束之后，而不是任意一个时钟周期；DMA 请求则通常在总线周期结束时响应，这是两者最容易混的时序差别。

三种 I/O 方式

方式CPU 参与数据传送适用
程序查询不断读状态，循环等待CPU 在查询循环里搬运简单、低速、CPU 空闲多
程序中断启动设备后并行；服务时参与CPU 在中断服务程序里搬运随机、中低速 I/O
DMA只在开始和结束介入DMA 控制器直接在主存与设备间搬运成块、高速 I/O

程序查询的缺点是 CPU 利用率低；程序中断把“等待”变成了“并行”，但每传一个字/字节仍要 CPU 执行服务程序；DMA 把数据搬运交给硬件，CPU 只负责初始化、启动和结束处理。

DMA 与总线占用

DMA 控制器需要和 CPU 争用总线。常见三种方式：

  • 停止 CPU 访存：DMA 工作时让 CPU 暂停访问主存，控制简单，但 CPU 可能长时间不能访存；
  • 周期挪用：DMA 在 CPU 不使用总线的周期“偷”一个周期传送数据，最常用；
  • 交替访问：CPU 与 DMA 分时使用总线，适合高速外设。

DMA 传送结束后向 CPU 发中断，让 CPU 做结束处理。DMA 适合磁盘、网卡等成块高速设备；中断适合键盘、打印机等少量随机数据。

中断与 DMA 的区别

维度程序中断DMA
数据搬运者CPU 执行服务程序DMA 控制器硬件
CPU 介入每次传送都要参与开始 / 结束介入
响应时机指令执行结束后总线周期结束后
适用数据量少量、随机成块、高速
优先级通常低于 DMA通常高于中断

常考判断：中断隐指令由硬件完成；中断响应后 PC 指向服务程序入口；断点现场要保存；DMA 传送不经过 CPU 的通用寄存器；DMA 与中断可以同时存在，但 DMA 请求通常优先级更高。

I/O 接口的基本结构

部件功能常考点
数据缓冲寄存器暂存 CPU 与设备之间传送的数据，做速度匹配和格式转换解决 CPU 与外设速度差异；DMA 也有数据缓冲寄存器
状态/控制寄存器状态位（就绪、忙、错误）供 CPU 查询；控制位（启动、中断允许）由 CPU 写入程序查询读状态、中断方式靠状态/控制位
地址译码和 I/O 控制逻辑识别 CPU 送来的端口地址，产生片选和读写控制，选择内部寄存器端口地址不同，选中的寄存器不同
外设界面控制逻辑把系统总线的并行信号转换成设备要求的时序/电平，完成串并转换、设备握手面向设备侧，处理“接口电缆”上的数据/状态/控制

主机侧看接口：CPU 通过数据线读写接口寄存器，通过地址线选端口，通过控制线发读/写命令；设备侧看接口：数据、状态、控制三组信号与设备握手。接口是“CPU 与设备之间的翻译和缓冲”。

I/O 端口及其编址

I/O 端口是接口中可被 CPU 直接访问的寄存器（数据端口、状态端口、控制端口）。CPU 用端口地址选中它，再读写其中的内容。端口不等于接口：接口是整体，端口是接口里可编址的寄存器。

编址方式做法优点缺点
独立编址（I/O 空间）I/O 端口单独编址，用专用 IN/OUT 指令访问不占主存地址空间；I/O 指令和主存指令区分明显需要专用指令和控制信号；寻址方式不如访存丰富
统一编址（存储器映射）端口和主存单元统一编址，用普通 load/store 访问可用全部访存指令和寻址方式；控制简单占用主存地址空间；需译码区分是内存还是 I/O

判断方法：看指令是 IN/OUT 还是 load/store；看端口是否占用主存地址空间。独立编址的端口地址可以和主存地址重叠，靠指令/控制信号区分。

三种 I/O 方式的流程

程序查询方式

  1. CPU 预置传送参数（内存缓冲区、设备地址、字计数）。
  2. 启动外设。
  3. 读外设状态，判断是否就绪；未就绪就循环查询。
  4. 就绪后传送一个数据，修改内存地址和字计数。
  5. 判断是否传送完；未完继续查询，完成则结束。

独占查询会让 CPU 一直忙等；定时查询是周期性地查，查询间隔与设备传输速率有关。优点是简单，缺点是 CPU 与外设完全串行，浪费 CPU。

中断控制方式

  1. CPU 启动外设后继续执行其他程序，不必等待。
  2. 外设完成一个数据单元后向 CPU 发中断请求。
  3. CPU 在满足条件时响应，转中断服务程序传送数据。
  4. 服务结束返回原程序；下一个数据再重复。

外设与 CPU 可以并行，但每传一个数据仍要一次中断和一段服务程序，适合中低速、随机 I/O。

DMA 控制方式

  1. CPU 初始化 DMA 控制器：内存起始地址、设备地址、传送长度、方向。
  2. CPU 发“启动 DMA”命令，之后不再参与数据搬运。
  3. DMA 控制器申请总线，获得后给出内存地址、发读写命令，在设备与主存之间直接传数据。
  4. 每传一次，地址计数器加 1、长度计数器减 1；计数值为 0 表示完成。
  5. DMA 向 CPU 发“DMA 结束”中断，CPU 做校验等后处理。

DMA 适合磁盘、网卡等成块高速设备；CPU 只在开始和结束介入。

中断响应与处理流程

响应条件：开中断（IF=1）、当前指令执行结束、有未被屏蔽的中断请求。三个条件同时满足才会响应。

中断隐指令（硬件自动完成，不是真正的机器指令）：关中断 → 保存断点（PC）→ 形成中断服务程序入口（中断向量）→ 修改 CPU 模式位（如进入内核态）。

单级中断处理：保护现场（通用寄存器、PSW）→ 执行中断服务程序 → 恢复现场 → 开中断 → 中断返回。单级处理期间一般不允许新的中断嵌套。

中断源识别：软件查询法按优先级依次查询异常/中断状态寄存器，先查到先处理；硬件向量法给每个中断源分配类型号，用类型号查中断向量表，取出服务程序入口送 PC。中断向量是入口地址，不是中断类型号本身。

多重中断与中断屏蔽

  • 硬件排队优先级：多个请求同时到达时，决定响应顺序；响应顺序不一定等于最终处理顺序。
  • 处理优先级：由中断屏蔽字体现。屏蔽字中 0 表示允许中断，1 表示屏蔽；某中断服务程序执行时，只有未被当前屏蔽字屏蔽、且满足响应条件的中断才能打断它。
  • 判断流程：先按硬件排队确定响应顺序；进入服务程序后，再看屏蔽字是否允许更高处理优先级的中断嵌套；被嵌套的服务程序在高优先级处理完后继续。
  • 执行轨迹：主程序 → 中断响应 → 服务程序 A → 更高优先级 B 嵌套 → 返回 A → 返回主程序。未被响应的中断要等 CPU 回到主程序后才能再次响应。

易错：硬件优先级高 ≠ 一定能打断当前服务程序；能不能嵌套看当前屏蔽字。屏蔽字是“处理优先级”的工具，不是响应条件本身。

DMA 传送流程与控制器

  1. 预处理：CPU 把主存起始地址送 AR（地址计数器）、设备地址送 DAR、传送长度送 WC（字计数器），启动设备。
  2. 申请总线：DMA 控制器发 HRQ，CPU 响应后发 HLDA，DMA 获得总线控制权。
  3. 传送：DMA 给出主存地址，发读/写命令，在设备与主存之间传数据；每传一次，地址计数器 +1、长度计数器 −1。
  4. 结束：WC=0 时，DMA 发中断请求，CPU 转入中断服务程序做数据校验、结束处理。
  5. 归还总线：DMA 释放总线，CPU 继续执行主程序。

块传输：DMA 面向一整块数据，CPU 设置参数并启动后，整块交给 DMA 控制器；完成后 DMA 用中断通知 CPU。单字传输（周期挪用）：DMA 每次只申请一个总线周期，传一个字/一个基本单位，然后归还总线，下次再申请。两者不是对立关系：块传输是总任务，实际占用总线时可以按单字逐次传。

DMA 与 CPU 争总线的三种方式：停止 CPU 访存（简单但 CPU 长时间不能访存）、周期挪用（最常用）、交替访问（CPU 与 DMA 分时使用总线）。DMA 请求通常在总线周期结束时响应，优先级通常高于中断。
