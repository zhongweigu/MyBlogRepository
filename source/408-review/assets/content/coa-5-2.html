中断与异常

中断通常指外中断：I/O 设备完成、时钟中断、键盘等来自 CPU 外部的事件。它一般在下一条指令执行前被检查；可屏蔽中断可以用 IF 标志屏蔽，不可屏蔽中断（如电源故障）不能。

异常（内中断）由当前指令的执行引起：缺页、除零、非法指令、断点、系统调用等。按恢复方式分为故障（fault，处理后重新执行当前指令）、陷阱（trap，处理后执行下一条指令）和终止（abort，无法恢复）。

中断向量表保存各中断服务程序的入口地址。多个请求同时到达时，按中断优先级排队；高优先级可以打断低优先级的服务程序，形成中断嵌套。

中断响应过程

CPU 在一条指令执行结束后检查中断请求。响应过程可以概括为：

  1. 关中断：防止响应过程被新的中断打断；
  2. 保存断点：把当前 PC（下一条指令地址）压栈或存入指定单元；
  3. 保存现场：保存通用寄存器和程序状态字等，服务程序返回后要恢复；
  4. 识别中断源：通过中断向量或排队器确定服务程序入口；
  5. 转中断服务程序：执行设备服务，结束后恢复现场、开中断、返回。

关中断、保存断点等由硬件自动完成，称为中断隐指令；它不是一条真正的机器指令，而是响应中断时硬件执行的一组微操作。保存通用寄存器通常由服务程序用指令完成。

中断响应发生在指令执行结束之后，而不是任意一个时钟周期；DMA 请求则通常在总线周期结束时响应，这是两者最容易混的时序差别。

三种 I/O 方式

方式CPU 参与数据传送适用
程序查询不断读状态，循环等待CPU 在查询循环里搬运简单、低速、CPU 空闲多
程序中断启动设备后并行；服务时参与CPU 在中断服务程序里搬运随机、中低速 I/O
DMA只在开始和结束介入DMA 控制器直接在主存与设备间搬运成块、高速 I/O

程序查询的缺点是 CPU 利用率低；程序中断把“等待”变成了“并行”，但每传一个字/字节仍要 CPU 执行服务程序；DMA 把数据搬运交给硬件，CPU 只负责初始化、启动和结束处理。

DMA 与总线占用

DMA 控制器需要和 CPU 争用总线。常见三种方式：

  • 停止 CPU 访存：DMA 工作时让 CPU 暂停访问主存，控制简单，但 CPU 可能长时间不能访存；
  • 周期挪用：DMA 在 CPU 不使用总线的周期“偷”一个周期传送数据，最常用；
  • 交替访问：CPU 与 DMA 分时使用总线，适合高速外设。

DMA 传送结束后向 CPU 发中断，让 CPU 做结束处理。DMA 适合磁盘、网卡等成块高速设备；中断适合键盘、打印机等少量随机数据。

中断与 DMA 的区别

维度程序中断DMA
数据搬运者CPU 执行服务程序DMA 控制器硬件
CPU 介入每次传送都要参与开始 / 结束介入
响应时机指令执行结束后总线周期结束后
适用数据量少量、随机成块、高速
优先级通常低于 DMA通常高于中断

常考判断：中断隐指令由硬件完成；中断响应后 PC 指向服务程序入口；断点现场要保存；DMA 传送不经过 CPU 的通用寄存器；DMA 与中断可以同时存在，但 DMA 请求通常优先级更高。
