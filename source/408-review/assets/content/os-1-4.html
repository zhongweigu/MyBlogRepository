按下电源键时，CPU 执行的第一条指令并不在操作系统里。操作系统还躺在磁盘上，必须先由固件和一小段一小段的引导程序把它“接力”送进内存。理解 OS 引导，关键是把固件、MBR、PBR、OS 引导程序、内核这五个层次分开：它们各自在什么位置、由谁加载、负责哪一步。

一、开机是一条接力链，不是一次跳转

加电后，CPU 从固定的复位向量开始取指。此时内存里还没有操作系统，只有主板固件（BIOS 或 UEFI）。固件做完自检、初始化必要的硬件后，按启动顺序选一个设备，读出该设备上的第一段引导代码；这段代码再去找下一段，直到把 OS 内核装进内存。

所以“OS 引导”不是“CPU 直接跳到内核”，而是一条逐级加载、逐级交接的链：

二、五个层次：固件、MBR、PBR、loader、内核

先把“谁在哪、谁加载谁”列清楚，后面就不会把 MBR 和 PBR 混在一起。

“引导程序”是一个统称，可能指 MBR 里的那一小段、PBR 里的分区引导程序，也可能指 GRUB/bootmgr 这种完整的 OS 引导器。考试问“引导程序”时，先看题目说的是哪一层，不要用一个词套所有层。

三、MBR：磁盘 LBA 0 的 512 字节

MBR（Master Boot Record，主引导记录）在磁盘的第 0 号扇区（LBA 0，传统 CHS 的 0 柱面/0 磁头/1 扇区）。一个扇区通常 512 字节，结构是：

区域大小内容
引导代码446 字节第一阶段引导程序：读分区表、找活动分区、加载 PBR
分区表64 字节4 个主分区表项，每项 16 字节（活动标志、分区类型、起止 CHS/LBA、扇区数）
结束标志2 字节0x55AA，BIOS 用来判断这确实是一个可引导扇区

注意两点：

  • MBR 不是操作系统。它只有 512 字节，装不下内核；它的任务是“找到活动分区，把 PBR 读进来并跳过去”。
  • MBR 的引导代码和分区表是两回事。引导代码执行；分区表是数据，告诉引导代码“分区从哪里开始、哪个是活动分区”。

传统 BIOS 通常把 MBR 读到内存的固定地址（如 0x7C00），检查 0x55AA，然后跳过去执行。MBR 代码再用 BIOS 的磁盘服务读出活动分区的第一个扇区（PBR），把控制权交给它。

四、PBR：活动分区自己的 LBA 0

PBR（Partition Boot Record，分区引导记录），也叫 VBR（Volume Boot Record，卷引导记录），位于活动分区自己的第 0 号扇区，不是磁盘的 LBA 0。它通常也以一个跳转指令开头，后面可能包含该分区的 BPB（BIOS Parameter Block）和一小段分区引导程序。

PBR 的职责是加载该分区里的 OS 引导程序。以 Windows 为例，PBR 可能加载 bootmgr；以 Linux 为例，GRUB 的第一阶段可能安装在 MBR 或 PBR，随后去加载 grub.cfg 和内核。不同系统的具体文件名不同，但“PBR 在分区内、负责把 loader 拉起来”这个位置关系不变。

五、流程骨架：先抓住接力链

先用一条最短的链把顺序串起来（以传统 BIOS/MBR 为例）；真正答题时，再补每一棒的职责和跳转条件：

加电 → POST → BIOS → 启动设备 → MBR → 活动分区 PBR → OS 引导程序 → 内核 → 第一个用户进程。

如果是 UEFI：加电 → POST → UEFI 固件 → 启动设备 → ESP 中的 .efi 引导程序 → OS 引导程序/内核。两条链的共同点是“固件先找到第一段引导代码，再由引导程序把内核送进内存”。

如果题目只问“OS 引导经过哪些主要阶段”，这条链就够了；如果题目问“每一段在哪、由谁加载”，再展开成下一节的详细版。

这条链不是硬背的顺序，而是能力逐层交接：固件只会用最基础的硬件接口读扇区，所以它只能把第一段引导代码搬进内存；MBR 只有 512 字节，放不下文件系统驱动，所以它只负责找活动分区并跳到 PBR；PBR 再加载OS 引导程序，后者才有能力读文件系统、把内核装进内存。每一棒都在解决“上一棒没有能力或没有必要做”的事，顺序自然就固定了。

六、详细流程：从复位向量到第一个用户进程

1. 固件阶段：POST 与启动设备

CPU 复位后从固件映射的地址开始执行。BIOS/UEFI 先做 POST（加电自检），初始化内存控制器、总线、基本外设，建立最小的运行环境；然后按启动顺序（硬盘、U 盘、网络等）选择一个可引导设备。传统 BIOS 从设备的 LBA 0 读 512 字节到内存，检查 0x55AA；UEFI 则从 FAT32 的 ESP 分区读取 .efi 引导程序。

2. MBR 阶段：读分区表，找活动分区

BIOS 把 MBR 装入内存并跳转。MBR 引导代码扫描 4 个分区表项，找到活动标志为 0x80 的分区；用 BIOS 磁盘服务读取该分区的第一个扇区（PBR），再跳到 PBR。此时仍然没有文件系统驱动，只能按扇区读。

3. PBR 阶段：加载 OS 引导程序

PBR 里的分区引导程序开始读该分区内的文件。它可能已经能识别文件系统（或至少能按固定位置读），把 OS 引导程序（bootmgr、GRUB 等）装入内存。到这一步，引导程序才具备“按文件名读内核”的能力。

4. OS 引导程序：把内核送进内存

OS 引导程序读取内核镜像和 initrd/initramfs，切换 CPU 到保护模式或长模式，建立页表，准备启动参数（命令行、内存映射、设备树等），最后跳到内核入口。它还可能显示启动菜单、选择内核版本、验证签名。

5. 内核初始化：从内核态到用户态

内核解压/重定位后，初始化页表、中断向量、时钟、调度器、驱动，挂载根文件系统，启动第一个用户进程（如 init/systemd）。从这一刻起，系统开始有“用户态进程”；之前的所有代码都在固件、引导程序或内核态运行。

七、BIOS/MBR 与 UEFI/GPT 的区别

现代机器大多使用 UEFI + GPT，不再走“MBR 引导代码 → PBR”这条传统链。两者不要混：

维度传统 BIOS + MBRUEFI + GPT
分区表MBR，4 个主分区，容量受 32 位 LBA 限制GPT，分区数多，支持大磁盘
引导程序位置磁盘 LBA 0 的 MBR + 活动分区 PBREFI System Partition（ESP，FAT32）里的 .efi 文件
固件怎么读按扇区读，使用 INT 13h 等中断服务固件自带 FAT 驱动，按文件路径读
启动方式MBR 代码链式加载 PBR固件直接加载 boot manager（如 bootx64.efi）
保护性 MBR不存在GPT 磁盘仍有一个保护性 MBR，但它不是启动代码

所以“UEFI 机器上也有 MBR”这句话要加限定：GPT 磁盘会保留一个保护性 MBR 用于兼容，但 UEFI 不从它里面的引导代码启动，而是从 ESP 加载 .efi 程序。

八、“引导由中断触发”该怎么理解

你给的导图里有一句“本质就是中断触发”。这句话要分两层看：

  • BIOS 读盘/引导时确实会用到中断服务：传统 BIOS 通过 INT 13h 读扇区、通过 INT 19h 进入引导加载；这些是固件提供给引导代码的软件中断接口。
  • 但 OS 引导本身不是一次中断：上电后 CPU 从复位向量取指，沿“固件 → MBR → PBR → loader → kernel”逐级跳转；这是取指/跳转链，不是某个设备发 IRQ 把 CPU “打断”去引导。

所以更准确的说法是：BIOS 阶段会调用中断服务来完成读盘和引导跳转，但“引导”这件事的本质是固件与引导程序的接力，不是中断事件。如果题目把“引导”与“中断”直接等同，通常是混淆了“使用中断服务”与“由中断触发”。

九、易错点与收束

  • “MBR 就是 PBR”：MBR 在磁盘 LBA 0；PBR 在活动分区自己的 LBA 0。
  • “MBR 里装的是操作系统”：MBR 只有 512 字节，装的是引导代码和分区表；内核在分区里。
  • “BIOS 就是操作系统”：BIOS/UEFI 是固件，负责自检和引导；OS 是随后被加载的软件。
  • “引导的本质是中断”：BIOS 读盘会用中断服务，但引导是上电后的取指/跳转链。
  • “UEFI 也从 MBR 引导代码启动”：UEFI 从 GPT 的 ESP 分区加载 .efi；保护性 MBR 不是启动代码。
  • “MBR 512 字节全是引导代码”：只有前 446 字节是引导代码，中间 64 字节是分区表，最后 2 字节是 55AA。

把这一节收成一句话：固件负责“找到第一段代码”，MBR 负责“找到活动分区”，PBR 负责“找到分区里的 loader”，loader 负责“把内核送进内存”，内核负责“把系统跑起来”。位置记清：MBR 在磁盘 LBA 0，PBR 在活动分区 LBA 0，内核在分区文件系统里。

内容整理自操作系统教材的通用框架；BIOS/UEFI 的具体行为随平台和固件实现而异。
