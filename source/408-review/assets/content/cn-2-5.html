以太网是数据链路层的核心实例：固定格式的 MAC 帧、CSMA/CD 的共享式历史、交换机的自学习转发，以及用 VLAN/STP 把局域网做大。无线局域网 802.11 则用 CSMA/CA。

这一节的主线是：帧决定“这一跳怎样交付”，交换表决定“从哪个端口出去”，VLAN 决定“哪些帧属于同一个广播域”，STP 决定“冗余链路中哪些端口暂时不用”。四件事各管一层，不要混在一起。

一、以太网 MAC 帧

以太网 V2 MAC 帧从“目的地址”开始计算长度：

字段长度作用
目的 MAC6B接收方硬件地址；全 1 为广播
源 MAC6B发送方硬件地址
类型/长度2B标识上层协议（如 IPv4 0x0800）或数据长度
数据46–1500B上层数据；不足 46B 要填充
FCS4BCRC 检错

帧长范围 64–1518B（不含前导码）；802.1Q 加 4B 标签后最大 1522B。前导码 7B + SFD 1B 用于同步，不计入帧长。

为什么数据字段最小是 46B？因为 CSMA/CD 要求最短帧 64B；目的/源/类型/FCS 共 18B，64−18=46。数据不足 46B 时，MAC 层要在数据字段后填充到 46B，接收端再根据上层协议长度把填充丢掉。

“类型/长度”字段要看数值：大于 0x0600（1536）通常表示上层协议类型（如 0x0800 是 IPv4）；小于等于 1500 表示数据长度。这个字段是 Ethernet V2 和 802.3 兼容留下的设计。

二、MAC 地址

MAC 地址 48 位，通常写成 6 组十六进制。前 24 位是厂商 OUI，后 24 位由厂商分配；全 1（FF-FF-FF-FF-FF-FF）是广播地址，第一字节最低位为 1 表示组播。

第一字节还有两个标志位：最低位 I/G 表示单播/组播，次低位 U/L 表示全局/本地管理。所以看到 `01-00-5E-...` 这类地址，第一字节最低位是 1，说明是组播；不要把它当普通单播地址。

MAC 地址是数据链路层地址，只在本地链路/广播域内使用；跨网段转发要靠 IP 路由。

三、交换机自学习

交换机收到帧后按“源 MAC 学习、目的 MAC 转发”工作。注意顺序：先学习源地址，再查目的地址。因为源地址告诉你“这台主机在哪个端口”，这个信息在转发当前帧时就要用到（尤其是目的端口未知时）。

  1. 记录帧的源 MAC 与入端口到交换表（有老化时间）；
  2. 查目的 MAC：若表中有且不是入端口，定向转发；
  3. 若未知/广播/组播，向除入端口外的所有端口泛洪；
  4. 目的主机回复后，交换机学习到它的端口，后续可定向转发。

“泛洪”不是“永远广播”：它只发生在目的 MAC 未知、广播或组播时，而且不会从入端口发回去。已知目的 MAC 时，交换机只往对应端口转发，其他端口收不到，这就是交换机比 Hub 高效的原因。

交换表项有老化时间：如果一台主机长时间不发帧，表项会被删除；下次再发给它时又要泛洪一次。这样主机换端口、拔掉后，旧表项不会永久误导转发。

交换机每个端口是独立的冲突域，但默认所有端口仍在同一个广播域；只有 VLAN 才能把广播域切开。这一点是“交换机隔离冲突域，不隔离广播域”的完整说法。

关键细节：普通二层交换机转发帧时不会写入自己的 MAC 作为源地址。因此当帧从交换机 1 进入交换机 2 时，交换机 2 记录的是“源主机 A 在它的端口 1”，而不是“交换机 1 在端口 1”。

四、环路与 STP

两台交换机之间若有多条冗余链路，广播帧会在环里反复兜圈，形成广播风暴，交换表也会被反复刷新（同一源 MAC 从不同端口出现，表项来回抖动）。生成树协议 STP 通过 BPDU 选举根桥、根端口、指定端口，逻辑上阻塞部分冗余端口，形成无环树；物理链路仍然保留，故障时可切换。

STP 的三步可以这样理解：

  1. 选根桥：所有交换机比较桥 ID（优先级 + MAC），最小者成为根桥；
  2. 选根端口：每台非根交换机选一个到根桥路径开销最小的端口；
  3. 选指定端口：每条网段选一个负责转发的端口；剩下的冗余端口进入阻塞状态。

阻塞端口不转发数据帧，但仍在听 BPDU；一旦拓扑变化，STP 重新计算，必要时把阻塞端口打开。所以它是逻辑断环，不是物理拔线。STP 收敛需要时间，期间可能短暂环路/中断；RSTP 是它的快速版本。

五、VLAN 与 802.1Q

VLAN 把一个物理局域网划分成多个逻辑广播域。802.1Q 在以太网帧的源 MAC 之后、类型/长度之前插入 4B 标签：

  • 标签含 2B TPID（0x8100）、2B TCI；
  • TCI 中 VID 占 12 位，可表示 4096 个 VLAN（0/4095 保留）；
  • Access 口属于一个 VLAN，收发的帧通常不带标签；Trunk 口承载多个 VLAN，跨交换机时打标签。

Access 口连接终端：交换机内部知道这个口属于 VLAN 10，收帧时给帧打上 VLAN 10 的标签，发帧时再把标签剥掉，终端感觉不到 VLAN。Trunk 口连接交换机/路由器：多个 VLAN 的帧都从这一根线过，必须保留标签，接收端才能知道它属于哪个 VLAN。

VLAN 只隔离广播域，不自动隔离 IP 子网；不同 VLAN 之间要通信，仍要经过路由器或三层交换机做路由。也就是说，VLAN 是“二层分段”，不是“三层路由”的替代品。

VLAN 隔离广播域，但不隔离 IP 子网间的路由；不同 VLAN 通信需要三层设备。

六、802.11 与 CSMA/CA

802.11 无线局域网不能照搬 CSMA/CD。有线站点可以比较“自己发的信号”和“收到的信号”来检测冲突；无线发送时，自己的发射信号会淹没接收信号，远近效应、隐藏终端也让“边发边听”不可靠。因此 802.11 用 CSMA/CA：尽量避开冲突，再用 ACK 确认。

802.11 有两种协调方式：DCF（分布式协调功能，默认，靠竞争）和 PCF（点协调功能，AP 集中轮询，可选，实际很少用）。下面讲的是 DCF。

6.1 IFS：为什么“空闲”还要再等

如果多个站同时听到“信道空闲”就立刻发，还是会一起撞。802.11 在“监听空闲”之后再加一段帧间间隔 IFS，用不同的等待长度区分优先级：

IFS长短用在哪里
SIFS（短帧间间隔）最短ACK、CTS、分片后的数据等“必须马上回应”的帧
PIFS（点协调 IFS）中等PCF 中 AP 轮询
DIFS（分布式协调 IFS）最长DCF 下普通数据帧/管理帧的竞争

关系是 SIFS < PIFS < DIFS。为什么 SIFS 最短？因为 ACK/CTS 是对上一帧的立即响应，必须比别的站的新数据更早抢到信道；如果大家都等 DIFS，ACK 就可能被新数据压住。

注意：IFS 不是“随机退避”。IFS 是固定的优先级间隔；随机退避是在 IFS 之后、为了错开多个竞争站而再加的随机等待。

6.2 一次 DCF 发送的完整流程

  1. 监听：如果信道忙，继续听；如果空闲，先等一个 DIFS（确保信道持续空闲）。
  2. 首次发送：如果这是第一次尝试，且 DIFS 期间信道一直空闲，可以直接发送整个数据帧。否则进入退避。
  3. 随机退避：从 [0, CW] 里随机选一个退避值（单位是时隙）；每经过一个空闲时隙减 1；如果信道变忙，冻结计数器，等信道再次空闲并持续 DIFS 后继续减；减到 0 才发送。
  4. RTS/CTS（可选）：先发 RTS 预约信道，AP 回 CTS；周围站听到后按 Duration 设置 NAV，主动推迟发送。
  5. DATA：发送数据帧；接收方正确收到后，等 SIFS 回 ACK。
  6. 失败重试：发送方在超时前没收到 ACK，就认为失败；把竞争窗口 CW 增大（二进制指数退避），重新选退避值再试；超过重试上限就丢弃。

这里有一个容易错的细节：退避计数器只在信道空闲时递减，信道忙时冻结，不是清零。这样多个站不会因为一次忙就全部重新随机，能保持相对的排队顺序。

6.3 什么是 ARQ

ARQ（Automatic Repeat reQuest，自动重传请求）是一类“确认 + 超时 + 重传”的可靠传输机制：接收方正确收到就回 ACK；发送方等不到 ACK 就重传。停等、GBN、SR 都是 ARQ 的不同实现。

802.11 的数据帧使用停等式链路层 ARQ：发一个数据帧，等一个 ACK；ACK 超时/丢失就重传。它和 TCP 的 ARQ 不是同一层：802.11 的 ACK 是链路层确认，只保证“这一跳/这个帧”被收到，不代表端到端应用数据已经可靠交付。

6.4 NAV、RTS/CTS 与 Duration 字段

无线还有一套“虚拟载波监听”：帧头里的 Duration（持续时间）字段告诉周围站“信道还要被占用多久”。收到帧的站把这个时间写入自己的 NAV（Network Allocation Vector，网络分配向量）；NAV 没减到 0 之前，即使物理层听到空闲，也不发送。这样不用真的听完整帧，就能提前避开。

Duration 到底包含什么？记住“从当前帧结束，到 ACK 结束”：

帧Duration 覆盖
RTSSIFS + CTS + SIFS + DATA + SIFS + ACK
CTSSIFS + DATA + SIFS + ACK
DATASIFS + ACK

为什么 RTS 的 Duration 要包含这么多？因为 RTS 是第一个预约帧，它必须把“后面整个交换过程”都算进去，其他站才会一直回避到 ACK 结束。CTS 是 AP 对 RTS 的回应，它只需要覆盖“CTS 之后到 ACK 结束”；DATA 的 Duration 只覆盖“DATA 之后到 ACK 结束”。

RTS/CTS 解决隐藏终端：A、C 都能和 AP 通信，但彼此听不到；如果同时发，会在 AP 处碰撞。A 先发 RTS，AP 回 CTS；C 听到 CTS 后按 NAV 推迟，冲突就被提前避开。RTS/CTS 不是强制的，帧很短时可能不用，因为 RTS/CTS 本身也有开销。

6.5 802.11 帧的地址字段

802.11 帧有多个地址字段（RA/TA/DA/SA），具体取决于 To DS/From DS 标志：

To DS / From DSAddress 1Address 2Address 3场景
0 / 0DASABSSID同一 BSS 内直接通信/管理帧
1 / 0BSSID（RA）SADA终端 → AP
0 / 1DABSSID（TA）SAAP → 终端
1 / 1RATADAWDS/无线网桥（还有 Address 4=SA）

不要死记“Address 1 一定是目的地址”：Address 1 永远是“当前这一跳的接收者”，在终端→AP 的场景里它是 AP 的 BSSID，不一定是最终目的主机。To DS/From DS 就是用来判断“这一帧是进分布系统还是出分布系统”的。

七、易错点与收束

  • “交换机隔离广播域”：默认不隔离；VLAN 才划分广播域。
  • “交换机记录交换机自己的 MAC”：普通二层转发不改写源 MAC；对端记录的是源主机 MAC。
  • “VLAN 标签 12 位”：标签共 4B，VID 12 位，不是整个标签 12 位。
  • “STP 物理断开链路”：STP 逻辑阻塞端口，物理链路仍存在。
  • “交换机每个端口一个广播域”：默认所有端口同一广播域；VLAN 才分割。

收束：以太网帧负责“本地交付”，交换机负责“按 MAC 转发”，VLAN 负责“划分广播域”，STP 负责“消除环路”，802.11 用 CSMA/CA 解决无线共享。
