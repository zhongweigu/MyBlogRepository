文件被“打开”之后，进程拿到的不是磁盘地址，而是一个文件描述符 fd。fd 背后是一条链：进程打开文件表 → 系统打开文件表 → 内存 inode → 数据块。理解这条链，open/read/write/close 和硬链接/软链接就不会混。

一、open 的完整流程

以 fd = open("/home/bok/a.txt", O_RDONLY) 为例：

  1. 用户进程执行 open，CPU 由用户态陷入内核态。
  2. 按路径名逐级查目录：根目录 → home → bok，每个目录项给出下一级 inode 号。
  3. 拿到目标文件 a.txt 的 inode 号，按 inode 区布局定位磁盘 inode。
  4. 检查该 inode 是否已在内存：不在则调入并建立内存 inode；已在则增加访问计数。
  5. 按打开方式检查权限、文件类型等；不满足则返回错误。
  6. 建立系统打开文件表项：记录偏移量、打开方式、inode 指针、引用计数。
  7. 在进程打开文件表中建立表项，指向系统表项，并分配 fd。
  8. open 返回 fd，CPU 回到用户态。open 只建立访问路径，不读文件正文。

二、read/write/close 在做什么

read(fd, buf, n) 的主线：

  1. fd → 进程打开文件表项 → 系统打开文件表项 → 内存 inode。
  2. 用当前文件偏移量算出要读的逻辑块号和块内偏移。
  3. 用 inode 的数据块指针把逻辑块映射为磁盘块。
  4. 若页缓存没有该块，发起磁盘 I/O 读入；再把需要的字节复制到用户 buf。
  5. 按实际读取字节数更新文件偏移量，read 返回。

write 与 read 类似，但要把用户数据写入页缓存；若写入位置超过文件末尾，还要分配新盘块、更新 inode 的文件长度和数据块指针。普通 write 不保证立即落盘，脏页之后由内核写回；需要立即持久化时用 fsync。

close(fd) 删除进程打开文件表项，系统打开文件表引用计数减 1；减到 0 才释放系统表项，再减少内存 inode 引用计数。close 本身不保证文件数据已经写盘。

三、两张打开文件表

表范围典型内容
进程打开文件表每个进程一张fd、指向系统表项的指针、进程读写偏移（有的系统偏移在系统表）
系统打开文件表全系统一张打开方式、当前偏移、inode 指针、引用计数

多个进程可以共享同一个系统打开文件表项（如 fork 后继承 fd），从而共享文件偏移；各自 open 同一文件通常会建立不同的系统表项，偏移独立。

四、硬链接与软链接

硬链接：多个目录项指向同一个 inode，inode 的链接计数加 1。删除一个名字只把计数减 1；计数为 0 且没有进程打开时才回收数据块。

软链接：新建一个独立文件，有自己的 inode，文件内容是目标路径字符串。访问软链接时，系统解析目标路径再访问目标文件。

维度硬链接软链接
inode共享同一个 inode自己有独立 inode
链接计数加 1，删除减 1目标文件的计数不变；软链接自身计数通常为 1
跨文件系统通常不可以可以
目标删除后只要还有其他硬链接，数据仍在悬空链接，访问失败

五、易错点与收束

  • “open 会把文件内容读进内存”：open 只查目录、权限、建打开文件表项；正文由 read 按需读。
  • “fd 就是磁盘地址”：fd 是进程打开文件表的索引，物理地址要经过系统表→inode→数据块指针。
  • “close 后数据一定落盘”：close 主要释放打开实例；脏页可能还在页缓存，需要 fsync。
  • “删除文件名就立即回收数据”：还有硬链接或进程打开时，inode/数据块要等链接计数和引用计数都归零。

把这一节收成一句话：open 把“路径名”变成 fd，read/write 沿 fd→系统表→inode→数据块访问，close 释放打开实例；硬链接共享 inode，软链接是独立文件。
