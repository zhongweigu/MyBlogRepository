考点1-内部排序思想

插入类的共同点是维护一个有序区，把无序区的元素逐个插进去。先看最基础的直接插入排序——后面的折半插入排序和希尔排序，都是在它上面做文章。

直接插入排序

直接插入排序的思路就是整理扑克牌：左手已经有一把排好的牌，每摸一张新牌，就从右往左找它该插的位置。

有序区和无序区：把数组看成三段——

区域 下标范围 说明
哨兵 A[0] 暂存本轮待插入的元素，不参与排序
已有序区 A[1..i-1] 内部已经有序
未排序区 A[i..n] 还没处理

初始时 A[1] 单独算作有序区（一个元素天然有序）。从 i = 2 开始，每趟把 A[i] 插入 A[1..i-1]，有序区长度加一，直到 i = n。

注：图中的灰格是哨兵位；上、下两行分别是正序（最好情况）和逆序（最坏情况）的初始序列，"已有序"只表示这一段内部有序，不表示这些元素已经在最终位置。

一趟插入的过程（设当前处理 A[i]，i ≥ 2）：

  1. 先把 A[i] 和有序区最后一个元素 A[i-1] 比较：若 A[i] >= A[i-1]，它已经在正确位置，本趟直接结束，一个元素都不用移。
  2. 否则把 A[i] 复制到哨兵 A[0]，令 j = i-1，从后往前逐个比较： - A[0] < A[j]：A[j] 比待插入元素大，把它后移一位到 A[j+1]，j 继续减一； - A[0] >= A[j]：位置找到了——A[j] 及其左边的元素都不比待插入元素大，循环停止。
  3. 把哨兵里的元素复制到 A[j+1]，这正是后移让出来的空位。

为什么从后往前：找位置和后移是同一遍完成的。若从前往后找，找到插入点后还得把后面的元素整体再挪一遍；从后往前则是"边比边挪"，最后一次后移腾出的空位正好落笔。

哨兵的两个作用：

  1. 暂存待插入元素，后移时不会把它覆盖掉；
  2. 内层循环走到 j = 0 时，A[0] < A[0] 为假，循环自动停止，省掉了 j >= 1 的越界判断。

注意：这里的哨兵存的是"当前要插入的那个元素"，不是全局最小值。顺序查找里的哨兵是另一回事——那里是把待查关键字放在表头或表尾，省掉下标越界判断。

对应的代码（下标从 1 开始，A[0] 空出来做哨兵）：

void InsertSort(ElemType A[], int n) {
    int i, j;
    for (i = 2; i <= n; i++) {
        if (A[i] < A[i - 1]) {       // 比有序区末尾还大，本来就在位
            A[0] = A[i];             // 哨兵暂存待插入元素
            for (j = i - 1; A[0] < A[j]; --j)
                A[j + 1] = A[j];     // 比哨兵大的元素依次后移
            A[j + 1] = A[0];         // 回填到腾出来的空位
        }
    }
}
展开：完整代码（0-based 暂存版） 
// 直接插入排序（0-based，用 temp 暂存）
void InsertSort(ElemType A[], int n) {
    int i, j;
    ElemType temp;
    for (i = 1; i < n; i++) {                // 把 A[i] 插入前面已排好序的序列
        if (A[i] < A[i - 1]) {               // 只有小于前驱才需要移动
            temp = A[i];                     // 暂存待插入元素
            for (j = i - 1; j >= 0 && A[j] > temp; --j)
                A[j + 1] = A[j];             // 大于 temp 的元素后移
            A[j + 1] = temp;                 // 回填
        }
    }
}

这段与上面的 1-based 哨兵版是同一个算法：这里数据放在 A[0..n-1]，用 temp 暂存；上面的代码数据放在 A[1..n]，把 A[0] 空出来当哨兵。做题时按题目给的下标约定来。

内层条件写 A[0] < A[j] 而不是 <=：遇到相等元素就停下，相等的两个记录不会交换先后，排序才是稳定的。改成 <=，相等元素也会被后移，稳定性就被破坏了。

复杂度：

情形 比较次数 移动次数 时间复杂度
最好：初始正序 $n-1$ $0$ $O(n)$
最坏：初始逆序 $\frac{n(n-1)}{2}$ $\frac{(n+4)(n-1)}{2}$ $O(n^2)$
平均 约 $\frac{n^2}{4}$ 约 $\frac{n^2}{4}$ $O(n^2)$

最坏情况的比较次数：第 $i$ 趟（$i=2,\dots,n$）要和有序区里全部 $i-1$ 个元素都比较一次，所以

$$\sum_{i=2}^{n}(i-1)=1+2+\cdots+(n-1)=\frac{n(n-1)}{2}$$

移动次数则是"哨兵存一次 + 后移 $i-1$ 次 + 回填一次"，共 $i+1$ 次：

$$\sum_{i=2}^{n}(i+1)=3+4+\cdots+(n+1)=\frac{(n+4)(n-1)}{2}$$

最好情况每个元素只和前面一个元素比一次就停，共 $n-1$ 次比较；一次移动都不需要。

口径说明：这里的比较次数按"每趟与有序区关键字比较"来数，不含外层 if 的预判，也不含哨兵自比的那一次；不同教材在常数项上可能略有出入，但最好 / 最坏的量级结论一致。

空间：只用了一个哨兵和两个循环变量，$O(1)$，是原地排序。

稳定性：稳定。所谓稳定，就是关键字相同的记录排序前后的相对次序不变。原因就是上面的严格小于——只有比哨兵大的元素才后移，和哨兵相等的元素停在它右边，相对次序不变。

适用性：

  • 顺序存储和链式存储都能用。顺序表靠"后移元素"腾位置；链表靠改指针插入，不需要移动元素，但找插入位置仍要沿链比较，时间仍是 $O(n^2)$。
  • 对基本有序的序列效率很高，比较次数接近 $n-1$，时间复杂度接近 $O(n)$；越接近逆序越慢。所以它常被用作其他排序的"小区间收尾"，例如快速排序在区间很小时改用插入排序。
  • 是希尔排序的基础：希尔排序先按增量分组做插入排序，最后一趟增量为 1，就退化成直接插入排序。

几个容易错的点：

  1. 每趟不能确定最终位置：直接插入排序每趟只保证有序区内部有序，元素之后还可能被更小的元素挤到后面。判断"第 $k$ 趟后哪些元素已经到位"时，不能按冒泡 / 选择的思路套。
  2. 比较次数与初始序列有关：最好 $n-1$ 次、最坏 $n(n-1)/2$ 次，差别是 $O(n)$ 和 $O(n^2)$。这一点常拿来和简单选择排序对照——简单选择排序无论初始序列如何，比较次数都固定是 $n(n-1)/2$。
  3. 移动次数里包含哨兵复制：最坏情况的 $(n+4)(n-1)/2$ 中，每趟有 2 次是哨兵相关的复制（存进去、取出来），只有 $i-1$ 次是真正的元素后移。题目若只问"元素后移次数"，答案是 $n(n-1)/2$，不要多算哨兵那两次。
  4. 链表上也能做：链式存储时不需要移动元素（只改指针），比较次数仍是 $O(n^2)$ 量级（具体次数会随查找方向不同而变化）；由于单链表不能从后往前，实现时通常从头结点开始找插入位置，思想相同、方向不同。

折半插入排序

折半插入排序 = 直接插入排序 + 折半查找找位置：有序区仍然是 A[1..i-1]，但不再从后往前逐个比较，而是先用折半查找确定 A[i] 该插到哪个位置，再统一后移、回填。

和直接插入最关键的区别：哨兵复制从"按需"变成"必做"。

步骤 直接插入 折半插入
进入本趟 先比 A[i] 与 A[i-1] 不比，直接 A[0] = A[i]
存哨兵 只有 A[i] < A[i-1] 才存 每趟都存
正序时 本趟直接结束，0 次移动 仍要存哨兵、回填，共 2(n-1) 次复制
找位置 从后往前边比边移 先在有序区折半，再统一后移

为什么折半插入不能省这一步：折半过程要反复拿 A[0] 和 A[mid] 比较，哨兵就是待插入关键字的稳定副本；而且后面的后移会覆盖 A[i]，所以必须先把 A[i] 存起来。

每趟最多比较多少次：设有序区有 $k$ 个元素（数组里 $k=i-1$），候选插入位置有 $k+1$ 个——最前面、每两个元素之间、最后面。每比较一次，候选区间减半，所以最多比较

$$\lceil \log_2(k+1) \rceil$$

次。课件把"有序区元素个数"记作 $i$，所以写成 $\lceil \log_2(i+1) \rceil$；换成本文的下标 $i$，就是 $\lceil \log_2 i \rceil$。

这里要分清"最多"和"实际"：折半插入的最坏情况比较次数只与记录个数有关——每趟最多 $\lceil\log_2(k+1)\rceil$，总计 $O(n\log n)$。但实际比较次数与初始排列有关：同一趟里，待插入关键字落在不同空隙，折半路径的长度就不同。准确的说法是"最坏情况的上界与初始排列无关"，不能说"比较次数与初始排列完全无关"。

注意：“最坏情况的上界只由记录个数决定”和“实际比较次数与初始排列无关”是两句话。前者对，后者错；教材若笼统说“无关”，通常指的是最坏情况的上界 / 量级。

一个小例子：对 {1, 2, 3} 排序，

  • 初始 1 2 3：插入 2 比 1 次，插入 3 比 2 次，共 3 次；
  • 初始 3 2 1：插入 2 比 1 次，插入 1 比 1 次，共 2 次。

同样是 3 个记录，实际比较次数却不同——所以“实际次数与初始排列无关”是错的；但每趟的最多次数（$k=1$ 时 1 次，$k=2$ 时 2 次）只由 $k$ 决定，这一点是对的。

课件里同一个最坏情况还写成 $\lfloor\log_2 i\rfloor+1$（这里的 $i$ 是已排序元素个数，也就是本文的 $k$）。换成 $k$ 就是 $\lfloor\log_2 k\rfloor+1$，它和 $\lceil\log_2(k+1)\rceil$ 是同一个数：设 $2^m\le k<2^{m+1}$，则 $2^m<k+1\le2^{m+1}$，所以

$$\lceil\log_2(k+1)\rceil=m+1=\lfloor\log_2 k\rfloor+1$$

只看一趟折半（在 $k$ 个有序元素里找插入空隙）：

情形 比较次数 说明
最少 $\lfloor\log_2(k+1)\rfloor$ 走到最浅的空隙
平均 约 $\log_2(k+1)$ 每次区间减半；确切值与空隙位置有关
最多 $\lfloor\log_2 k\rfloor+1=\lceil\log_2(k+1)\rceil$ 走到最深的空隙

课件里的"最佳情况 1 次"说的是单次折半查找第一次就命中 mid（目标值正好在中间）；折半插入每趟找的是插入空隙，一定走到"失败"分支，所以每趟的比较次数在 $\lfloor\log_2(k+1)\rfloor$ 到 $\lceil\log_2(k+1)\rceil$ 之间，并不存在"每趟固定只比 1 次"的最佳情况。

把所有趟加起来：

$$\sum_{k=1}^{n-1}\lceil \log_2(k+1)\rceil=\sum_{i=2}^{n}\lceil \log_2 i\rceil=O(n\log n)$$

比较次数降到了 $O(n\log n)$，但每趟仍要后移元素，移动次数还是 $O(n^2)$，所以总时间仍是 $O(n^2)$。

展开：⌈log₂(n+1)⌉ 的几次出场

这个式子在前面已经出现过几次，变的只是"n"指什么：

出现位置 式子 这里的 n / k
三、非线性结构（上）· 树形推断 ⑤：完全二叉树的最小高度 $h=\lceil\log_2(n+1)\rceil$ 结点总数
五、查找 · 折半查找：判定树的最多比较次数（600 个元素那题算的就是它） $\lceil\log_2(n+1)\rceil$ 关键字个数
五、查找 · AVL 性质 ②：n 个结点的最小高度 $h_{\min}=\lceil\log_2(n+1)\rceil$ 结点总数
六、排序 · 折半插入：每趟最多比较次数 $\lceil\log_2(k+1)\rceil$ 有序区元素个数 k

联系：它们都在数同一棵"二叉判定树"的层数。

  • 一棵有 $m$ 个内部结点的二叉判定树，必有 $m+1$ 个外部空位（叶子/空隙）。折半查找的 $m$ 个关键字把数轴切成 $m+1$ 段，折半插入的 $m$ 个有序元素也把插入位置切成 $m+1$ 个空隙——这是同一个 $m+1$。
  • 每比较一次，候选区间减半；$t$ 次比较最多区分 $2^t$ 个位置。要覆盖 $m+1$ 个位置，必须 $2^t\ge m+1$，即 $t\ge\log_2(m+1)$，取整就是 $\lceil\log_2(m+1)\rceil$。
  • 完全二叉树 / AVL 那边是从另一头看：$h$ 层二叉树最多 $2^h-1$ 个结点，装下 $m$ 个结点要 $2^h-1\ge m$，同样得到 $h\ge\log_2(m+1)$。所以"n 个结点的最小高度"和"n 个元素的折半查找最多比较次数"是同一个下界。
  • 折半查找的方形失败结点虽然比圆形结点多一层，但失败时最后一次比较发生在它的父结点上，所以"最多比较次数"仍然数到树高，不额外加 1。

形似但别混：

  • B 树的高度下界是 $\log_m(n+1)\le h$：底数是 $m$，因为每个结点最多 $m$ 个分支，不是二叉。
  • 红黑树的高度上界是 $2\log_2(n+1)$：核心还是 $\log_2(n+1)$，前面的 2 是"最长路径不超过最短路径 2 倍"付出的代价。
  • AVL 的最大高度不是这个式子，它由最少结点数 $n_h$ 的 Fibonacci 递推决定；只有 AVL 的最小高度才是 $\lceil\log_2(n+1)\rceil$。

对应的代码：

void BinaryInsertSort(ElemType A[], int n) {
    int i, j, low, high, mid;
    for (i = 2; i <= n; i++) {
        A[0] = A[i];                 // 每趟必做：哨兵保存待插入元素
        low = 1;
        high = i - 1;
        while (low <= high) {
            mid = (low + high) / 2;
            if (A[mid] > A[0])
                high = mid - 1;      // 插入点在左半区
            else
                low = mid + 1;       // 插入点在右半区
        }
        for (j = i - 1; j >= high + 1; --j)
            A[j + 1] = A[j];         // 把插入点之后的元素统一后移
        A[high + 1] = A[0];          // 回填到空位
    }
}
展开：完整代码（1-based 哨兵版） 
// 折半插入排序（1-based，A[0] 当哨兵）
void BinaryInsertSort(ElemType A[], int n) {
    int i, j, low, high, mid;
    for (i = 2; i <= n; i++) {                // 依次把 A[2]～A[n] 插入前面的有序区
        A[0] = A[i];                          // 暂存待插入元素
        low = 1;
        high = i - 1;
        while (low <= high) {                 // 在 A[1..i-1] 中折半查找插入位置
            mid = (low + high) / 2;
            if (A[mid] > A[0]) high = mid - 1;
            else low = mid + 1;
        }
        for (j = i - 1; j >= high + 1; --j)
            A[j + 1] = A[j];                  // 统一后移，空出插入位置
        A[high + 1] = A[0];                   // 回填
    }
}

if (A[mid] > A[0]) 用的是严格大于：遇到相等元素时走 else，插入点落在相等元素的右边，相等记录的相对次序不变，所以折半插入也是稳定的。若改成 >=，就会插到相等元素前面，稳定性被破坏。

移动次数：折半只改变了"找位置"的方式，没有改变"后移"这一步。设本趟插入 A[i]，最终插入位置是 high+1，需要把 A[high+1..i-1] 整体后移，共 i-1-high 次；最坏 i-1 次，合计 $n(n-1)/2$。

再加上哨兵的两步——每趟 A[0]=A[i] 和 A[high+1]=A[0] 各一次，共 $2(n-1)$ 次复制：

  • 最坏情况：$\frac{n(n-1)}{2}+2(n-1)=\frac{(n+4)(n-1)}{2}$，和直接插入的最坏情况完全一样；
  • 最好情况：直接插入是 0 次，折半插入仍有 $2(n-1)$ 次（若只数"元素后移"、不数哨兵存取，则仍是 0 次）。

所以课件说"没有改变移动次数"，准确的理解是：元素后移的总量没变，最坏 / 平均仍是 $O(n^2)$；但哨兵复制从"按需"变成了"每趟必做"，最好情况的移动次数已经回不到 0。

两种插入排序对照：

指标 直接插入 折半插入
比较次数 最好 $n-1$，最坏 $\frac{n(n-1)}{2}$ 每趟最多 $\lceil\log_2 i\rceil$，总计 $O(n\log n)$
元素后移 最坏 $\frac{n(n-1)}{2}$ 最坏 $\frac{n(n-1)}{2}$
哨兵复制 仅需插入时每趟 2 次 每趟 2 次，正序也免不掉
最好情况移动 $0$ $2(n-1)$（只数后移则为 0）
最坏情况总移动 $\frac{(n+4)(n-1)}{2}$ $\frac{(n+4)(n-1)}{2}$
时间复杂度 $O(n^2)$ $O(n^2)$（最坏 / 平均；最好 $O(n\log n)$）
空间 $O(1)$ $O(1)$
稳定性 稳定 稳定
存储结构 顺序表、链表 仅顺序表

为什么只适用顺序表：折半查找要能直接跳到 A[mid]，必须随机访问。链表找第 mid 个结点要从头走，折半一次就退化成 $O(n)$，优化就没了。

一句话总结：折半插入把最坏情况的比较次数从 $O(n^2)$ 压到了 $O(n\log n)$，但它的比较次数始终是 $\Theta(n\log n)$ 量级，不会像直接插入那样在正序时降到 $O(n)$——所以正序或接近正序时，直接插入的关键字比较次数反而更少。它的移动次数仍是 $O(n^2)$，总时间还是 $O(n^2)$；真正省下的是最坏情况的比较，不是移动。

希尔排序

希尔排序（缩小增量排序）：直接插入排序在"基本有序"时很快；希尔排序先用较大的增量把序列粗调到基本有序，再逐步缩小增量，最后一趟增量为 1，做一次完整的直接插入排序。

怎么分组：取一个增量 $dk$，把下标相差 $dk$ 的元素分到同一组——是"隔 $dk$ 个位置"取，不是把数组切成连续的几段。比如 $n=8$、$dk=4$ 时分成四组：(1,5)、(2,6)、(3,7)、(4,8)。每组内部做直接插入排序，然后缩小 $dk$，重复"分组 → 组内插入排序"，直到 $dk=1$。

课件的增量序列：第一轮 $dk=n/2$，之后每轮 $dk=dk/2$，直到 $dk=1$。除法是整数除法（向下取整）：$n=7$ 时依次是 3、1，不是 3、2、1。增量序列不唯一，但最后一趟必须是 1，否则不能保证整体有序。

增量 子序列（下标） 本趟结束后的数组

$dk=4$ (1,5)、(2,6)、(3,7)、(4,8) 49 13 27 50 76 38 65 97

以 $dk=4$ 为例：四组分别是 (49,76)、(38,13)、(65,27)、(97,50)，组内插入排序后变成 (49,76)、(13,38)、(27,65)、(50,97)，再按下标放回去，就得到 49 13 27 50 76 38 65 97。

$dk=2$ 时，(1,3,5,7) 上是 49 27 76 65，排成 27 49 65 76；(2,4,6,8) 上是 13 50 38 97，排成 13 38 50 97，放回后得到 27 13 49 38 65 50 76 97。

最后一趟 $dk=1$ 就是全体直接插入排序；这时序列已经基本有序，移动次数比一开始就做直接插入少很多。

代码（增量按 $n/2, n/4, \dots, 1$ 取）：

void ShellSort(ElemType A[], int n) {
    int dk, i, j;
    for (dk = n / 2; dk >= 1; dk = dk / 2) {
        for (i = dk + 1; i <= n; i++) {
            if (A[i] < A[i - dk]) {       // 在本组内需要前插
                A[0] = A[i];             // 暂存待插入元素
                for (j = i - dk; j > 0 && A[0] < A[j]; j -= dk)
                    A[j + dk] = A[j];    // 组内元素后移 dk 位
                A[j + dk] = A[0];        // 回填
            }
        }
    }
}
展开：完整代码（1-based 暂存版） 
// 希尔排序（1-based，A[0] 是暂存单元）
void ShellSort(ElemType A[], int n) {
    int d, i, j;
    // A[0] 只是暂存单元，不是哨兵；j <= 0 时插入位置已到
    for (d = n / 2; d >= 1; d = d / 2) {       // 步长变化
        for (i = d + 1; i <= n; ++i) {
            if (A[i] < A[i - d]) {             // 需将 A[i] 插入本组有序表
                A[0] = A[i];                   // 暂存在 A[0]
                for (j = i - d; j > 0 && A[0] < A[j]; j -= d)
                    A[j + d] = A[j];           // 记录后移，查找插入位置
                A[j + d] = A[0];               // 插入
            }
        }
    }
}

稳定性：不稳定。 关键字相同的记录可能被分到不同的子序列，跨组移动后相对次序会变。反例：3, 2a, 2b, 1（2a、2b 表示两个关键字相同、只靠下标区分的记录），$dk=2$ 后变成 2b, 1, 3, 2a，最后一趟 $dk=1$ 得到 1, 2b, 2a, 3，两个 2 的次序反了。

注意：不要因为"每组内部用的是直接插入排序"就认为希尔排序稳定——组内稳定，不代表跨组的相对次序也稳定。

复杂度：

  • 时间：与增量序列有关，不能用一个固定式子概括。按课件的折半增量，最坏 $O(n^2)$；平均性能通常优于直接插入，常见教材给的经验值约为 $O(n^{1.3})$（具体取决于增量序列）。408 最常考的是"依赖增量序列"和"最坏 $O(n^2)$"。
  • 空间：$O(1)$，原地排序。
  • 适用性：只适用顺序表。分组要按下标跳 $dk$ 取元素，链表上每次跳 $dk$ 步太贵，失去了希尔排序的意义。

几个容易错的点：

  1. 分组不是连续切块：$dk=4$ 时是 (1,5)、(2,6)……，不是 (1,2,3,4) 和 (5,6,7,8)。
  2. 最后一趟必须是 $dk=1$；少了这一趟，前面做得再好也不能保证整体有序。
  3. 不稳定：这是希尔排序和直接插入排序最重要的区别之一。
  4. 复杂度不能直接套 $O(n\log n)$ 或固定的 $O(n^2)$：它依赖增量序列；最坏是 $O(n^2)$。
  5. 只适用顺序表：需要随机访问相隔 $dk$ 的元素。
  6. 每趟不保证确定某个元素的最终位置：只有最后一趟结束，整体才有序；这一点和冒泡、选择、快速排序不同。

冒泡排序

冒泡排序：反复比较相邻的两个元素，如果逆序就交换。每一趟都会把当前未排序部分的最大值（从左往右扫）或最小值（从右往左扫）"冒"到一端，并确定它的最终位置。

课件的三条：

  1. 不断比较相邻两个元素，每一趟确定一个最小（最大）值的最终位置；
  2. 可以从左往右，也可以从右往左；
  3. 当上一趟没有发生任何交换时，可以直接停止。

方向：下面按"从左往右、把大的往右换"来讲；如果从右往左，就是每趟把最小的往左换，整体镜像。不要在一趟里混用两个方向——交替方向是鸡尾酒排序，不是标准冒泡。

一趟做什么（从左往右，第 $i$ 趟）：

  • 依次比较 A[j] 和 A[j+1]，$j=1,2,\dots,n-i$；
  • 前者大于后者就交换；
  • 这一趟结束，A[n-i+1] 就是当前未排序部分的最大值，位置确定，下一趟不用再比它。

手工模拟：对 5 1 4 2 8 排序：

趟 比较范围 比较次数 交换次数 本趟结束后的序列
初始 — — — 5 1 4 2 8
1 A[1..5] 4 3 1 4 2 5 8
2 A[1..4] 3 1 1 2 4 5 8
3 A[1..3] 2 0 1 2 4 5 8（无交换，停止）

第一趟把 8 送到最后；第二趟把 5 送到倒数第二；第三趟一次交换都没有，说明已经有序，直接结束。

代码（从左往右，把大的送到末尾）：

void BubbleSort(ElemType A[], int n) {
    for (int i = 1; i < n; i++) {
        bool flag = false;                 // 本趟是否发生交换
        for (int j = 1; j <= n - i; j++) {
            if (A[j] > A[j + 1]) {         // 严格大于才交换，保证稳定
                swap(A[j], A[j + 1]);
                flag = true;
            }
        }
        if (!flag) break;                  // 本趟无交换，已经有序
    }
}

// 交换
void swap(ElemType &a, ElemType &b) {
    ElemType temp = a;
    a = b;
    b = temp;
}

// 冒泡排序（0-based，从右往左把小的换到前面）
void BubbleSort(ElemType A[], int n) {
    for (int i = 0; i < n - 1; i++) {
        bool flag = false;                 // 表示本趟冒泡是否发生交换
        for (int j = n - 1; j > i; j--) {  // 一趟冒泡过程
            if (A[j - 1] > A[j]) {         // 若为逆序
                swap(A[j - 1], A[j]);      // 交换
                flag = true;
            }
        }
        if (flag == false) return;         // 本趟无交换，说明表已经有序
    }
}

这段是 0-based、从右往左的镜像版：每趟把当前最小值送到前面。上面可见代码是 1-based、从左往右，把最大值送到末尾；两者等价，别把方向记混。

稳定性：稳定。 只有 A[j] > A[j+1] 才交换，相等元素不会互换，相对次序不变。若改成 >=，相等元素也会交换，稳定性被破坏。

复杂度：

情形 比较次数 交换次数 时间复杂度
最好（正序，带 flag） $n-1$ $0$ $O(n)$
最坏（逆序） $\frac{n(n-1)}{2}$ $\frac{n(n-1)}{2}$ $O(n^2)$
平均 $O(n^2)$ 约 $\frac{n(n-1)}{4}$（期望逆序对数） $O(n^2)$
  • 最好情况：一趟扫完没有交换，flag 为假，直接结束；只比较 $n-1$ 次。
  • 最坏情况：完全逆序，每对相邻元素都要交换，比较和交换都是 $n(n-1)/2$ 次。
  • 平均情况：交换次数等于初始序列的逆序对数，随机排列的期望是 $n(n-1)/4$；比较次数仍是 $O(n^2)$。

几条性质：

  • 每一趟至少确定一个元素的最终位置：从左往右扫，确定当前最大值；从右往左扫，确定当前最小值。$k$ 趟之后，至少有 $k$ 个元素到位。
  • 提前停止的条件是"本趟没有发生任何交换"，不是"本趟比较次数到了某个值"；flag 每趟都要重新置为 false。
  • 空间 $O(1)$，原地排序。
  • 顺序表和链表都能实现：顺序表直接用下标交换；链表上遍历相邻结点、交换数据。链表不能随机访问，所以实现方式不同，但"相邻比较、逆序交换"的思想一样。
  • 冒泡排序的交换次数等于逆序对数；这也是它常被拿来考"最少交换次数"的原因。

和直接插入的区别：

  • 冒泡每趟能确定至少一个元素的最终位置；直接插入不能，只保证有序区内部有序。
  • 两者都稳定，最坏都是 $O(n^2)$，最好都能到 $O(n)$（冒泡靠 flag，直接插入靠正序时一次都不移）。
  • 冒泡的一次交换要三次赋值，直接插入的后移通常更省；实际运行中直接插入一般更快。

快速排序

快速排序：选一个元素作为枢轴（pivot，通常取表中第一个元素），通过一趟划分把表分成左右两部分——左边都不大于枢轴、右边都不小于枢轴，枢轴落到它的最终位置；然后对左右两个子表递归地重复同样的过程。

划分（挖坑填数）：以 A[low..high] 为例，先令 pivot = A[low]。此时 A[low] 空出来，像一个"坑"：

  1. high 从右往左走，跳过所有 >= pivot 的元素；遇到 < pivot 的，把它填到 A[low]，坑变成 high；
  2. low 从左往右走，跳过所有 <= pivot 的元素；遇到 > pivot 的，把它填到 A[high]，坑变成 low；
  3. 重复 1、2，直到 low == high；把 pivot 填进 A[low]。

此时 A[low] 就是枢轴的最终位置，返回 low。枢轴左边都不大于它、右边都不小于它，但左右两边内部还没有排好，需要递归处理。

一次划分至少能确定一个元素的最终位置：枢轴一定到位，左边都不大于它、右边都不小于它。若关键字互不相同，就是左边都比它小、右边都比它大；有重复关键字时只能说"不大于 / 不小于"。例如子表 6 1 17 以 6 为枢轴，划分后是 1 6 17，6 到位。

1 high 从 8 左移（50 ≥ 49 跳过），27 < 49，填到 A[1] 27 38 65 97 76 13 27 50
2 low 从 1 右移（27、38 ≤ 49 跳过），65 > 49，填到 A[7] 27 38 65 97 76 13 65 50

划分的核心代码：

int Partition(ElemType A[], int low, int high) {
    ElemType pivot = A[low];              // 第一个元素作枢轴
    while (low < high) {
        while (low < high && A[high] >= pivot) --high;
        A[low] = A[high];                 // 右边比枢轴小的填到左坑
        while (low < high && A[low] <= pivot) ++low;
        A[high] = A[low];                 // 左边比枢轴大的填到右坑
    }
    A[low] = pivot;                       // 枢轴回填到最终位置
    return low;
}

内层的 >= / <= 不能随便改成 > / <：等于枢轴的元素要跳过，否则 low、high 可能停在相等元素上，划分无法正常收缩。也正因为相等元素会被跨位置搬运，快速排序不稳定。

展开：完整代码（1-based 挖坑法） 
// 用第一个元素把 A[low..high] 划分成左右两部分
int Partition(ElemType A[], int low, int high) {
    ElemType pivot = A[low];              // 第一个元素作为枢轴
    while (low < high) {                  // low、high 相向而行
        while (low < high && A[high] >= pivot) --high;
        A[low] = A[high];                 // 比枢轴小的移到左端
        while (low < high && A[low] <= pivot) ++low;
        A[high] = A[low];                 // 比枢轴大的移到右端
    }
    A[low] = pivot;                       // 枢轴放到最终位置
    return low;
}

void QuickSort(ElemType A[], int low, int high) {
    if (low < high) {                     // 子表长度大于 1 才需要划分
        int pivotpos = Partition(A, low, high);
        QuickSort(A, low, pivotpos - 1);  // 递归左子表
        QuickSort(A, pivotpos + 1, high); // 递归右子表
    }
}

长度为 1 的子表：递归出口是子表为空或只有一个元素。代码写成 if (low < high) 时，长度为 1 的子表不会再发起递归；如果写成"先调用、进函数再判断 low >= high 就返回"，那么会多一次空调用，但函数立刻返回，什么也不做。手动模拟一般忽略这次调用，只数真正做了划分的层。

时间复杂度：每一层划分要把这一层的元素扫一遍，代价 $O(n)$；总时间 = $O(n)\times$ 递归层数。

  • 最好 / 平均：每次选的 pivot 刚好把表分成相对均匀的两份，递归层数 $O(\log n)$，总时间 $O(n\log n)$；
  • 最坏：每次枢轴都落在最边上（例如初始序列已基本有序，正序或逆序，而枢轴取第一个元素），递归层数退化成 $n$，总时间 $O(n^2)$。

写成递推式就是

$$T(n)=T(k)+T(n-1-k)+O(n)$$

其中 $k$ 是枢轴左边元素个数。$k\approx n/2$ 时是 $O(n\log n)$，$k=0$ 或 $k=n-1$ 时退化成 $O(n^2)$。

空间复杂度：快速排序是原地排序，不需要额外数组；但递归要用栈，空间就是递归深度——最好 / 平均 $O(\log n)$，最坏 $O(n)$。递归树的树高和最大递归深度一致：最坏 $n$，最好约 $\log_2 n$（精确地说是 $\lceil\log_2(n+1)\rceil$）。

稳定性：不稳定。 反例：2a, 2b, 1（2a、2b 关键字相同，只靠下标区分）。以 2a 为枢轴，high 遇到 1 后把它填到最前面，最后枢轴 2a 被填到 1 的后面，得到 1, 2b, 2a——两个 2 的次序反了。

适用性：快速排序依赖随机访问——划分要让 low、high 从两端相向走，必须能直接取 A[low]、A[high]。因此它适用于顺序存储；链表上找前驱/后继的方向受限，按 408 的口径不把快速排序列为链表适用。

几个容易错的点：

  1. 枢轴取第一个元素时，正序 / 逆序反而最慢：每次枢轴都是最小或最大，划分极不均匀，退化成 $O(n^2)$。随机取枢轴、取头中尾三数的中位数，都是为了降低这种退化概率。
  2. 一次划分只确定枢轴一个元素的最终位置；左右子表还要继续递归，不能以为一趟划分就排好了。
  3. 空间不是 $O(1)$：虽然没有辅助数组，但递归栈要占空间，最坏 $O(n)$。
  4. 不稳定：不要因为"看起来只是把元素搬到两边"就认为它稳定；相等元素会被跨位置搬运。
  5. 递归终止条件是 low >= high（子表为空或只有一个元素）；代码里写成 if (low < high) 继续划分，等价的写法是先 if (low >= high) return;。
  6. 枢轴回填的位置是 low == high 的位置，不是一开始的 A[low]；最后一定要执行 A[low] = pivot。

408 说的"一趟排序"是对所有尚未确定最终位置的元素处理一遍；一次划分只确定枢轴一个元素。一次划分 ≠ 一趟排序；而"对子表调用一次 QuickSort"会递归处理整个子表，和一次划分也不是一回事。

简单选择排序

简单选择排序：每一趟在无序区 A[i..n] 中找出最小的元素，和无序区的第一个元素 A[i] 交换；有序区从左边逐渐扩大，经过 $n-1$ 趟后整体有序。

一趟做什么（第 $i$ 趟，$i=1,\dots,n-1$）：

  1. 令 min = i，min 指向无序区的第一个元素；
  2. 从 j=i+1 到 n 扫描，遇到 A[j] < A[min] 就更新 min = j；
  3. 扫描结束后，A[min] 就是本趟最小值；若 min != i，交换 A[i] 和 A[min]。

每趟结束时 A[i] 就是第 $i$ 小的元素，位置确定；下一趟从 i+1 开始。

堆排序

堆：一棵完全二叉树，通常用数组顺序存储。1-based 时，结点 $i$ 的左孩子是 $2i$、右孩子是 $2i+1$、父结点是 $\lfloor i/2 \rfloor$；$i\le\lfloor n/2 \rfloor$ 的结点都是分支结点。大根堆要求每个结点都 $\ge$ 左右孩子，小根堆要求每个结点都 $\le$ 左右孩子。

建堆（以大根堆为例）：

  1. 从最后一个分支结点 $i=\lfloor n/2 \rfloor$ 开始，往前到 1；
  2. 对每个 $i$ 做"下坠"（HeadAdjust）：根和较大的孩子比较，根小就交换，并沿着被换下去的位置继续往下调整；根已经不小于较大孩子就停止；
  3. 如果调整较高结点时把一个小元素换进了已经调整好的子树，就继续沿着这个孩子往下调整，把被影响的部分恢复成大根堆——这就是"后面的调整影响前面"的处理。

建堆从下往上，每个结点下坠的距离不超过它的高度，总代价 $O(n)$（比较次数不超过 $4n$）。

选较大孩子时，如果左右孩子相等，代码里的 A[i] < A[i+1] 为假，不执行 i++，所以选左孩子和父亲交换；这是一个约定，避免相等时来回摇摆。

核心代码：

void HeadAdjust(ElemType A[], int k, int len) {
    A[0] = A[k];                         // 暂存子树的根
    for (int i = 2 * k; i <= len; i *= 2) {
        if (i < len && A[i] < A[i + 1]) i++; // 取较大的孩子
        if (A[0] >= A[i]) break;         // 根已经不小于孩子，停止
        A[k] = A[i];                     // 孩子上移
        k = i;                           // 继续沿这个孩子往下检查
    }
    A[k] = A[0];                         // 放回最终位置
}

void BuildMaxHeap(ElemType A[], int len) {
    for (int i = len / 2; i > 0; i--)    // 从最后一个分支结点往前
        HeadAdjust(A, i, len);
}

void HeapSort(ElemType A[], int len) {
    BuildMaxHeap(A, len);                 // 初始建堆
    for (int i = len; i > 1; i--) {       // n-1 趟
        swap(A[i], A[1]);                 // 堆顶最大值放到堆底
        HeadAdjust(A, 1, i - 1);          // 恢复剩余部分的大根堆
    }
}

堆的删除 / 插入：

  • 删除堆顶：用堆底元素补到堆顶，堆长减 1，再从堆顶向下调整；
  • 插入：新元素放到堆底，堆长加 1，再与父结点比较，向上调整（大根堆中比父结点大就交换）。

归并排序

归并：把两个或多个有序子序列合并成一个有序序列。二路归并就是"二合一"：每次比较两个子序列当前的首元素，把较小的放进结果；一个子序列取完后，把另一个剩下的元素直接接上。

二路归并排序：

  1. 初始把 $n$ 个记录看成 $n$ 个长度为 1 的有序子序列；
  2. 两两归并，得到 $\lceil n/2 \rceil$ 个长度为 2 或 1 的有序子序列；
  3. 再两两归并，重复下去，直到只剩一个长度为 $n$ 的有序序列。

从递归角度看，就是先分解：每次从 $\text{mid}=\lfloor(low+high)/2\rfloor$ 把区间分成两半，递归排好左右两个子表；再合并：把两个有序子表 Merge 成一个。分解只是划分，真正干活的是自底向上的合并，两种看法是等价的。

趟数：$N$ 个元素做 $k$ 路归并，趟数为 $\lceil\log_k N\rceil$。二路归并就是 $\lceil\log_2 N\rceil$：$n=7$ 时是 3 趟，$n=8$ 时也是 3 趟。

合并两个有序表：长度分别为 $m$、$n$ 时：

  • 最多比较 $m+n-1$ 次：每次比较输出一个元素，最后剩下一个元素不用再比，直接接上；
  • 最少比较 $\min\{m,n\}$ 次：较短的表先全部输出完，另一个表剩下的直接接上。

例如合并 [1,2] 和 [3,4]，只比 2 次；合并 [1,3] 和 [2,4]，要比 3 次（$m+n-1=3$）。

注意：这里的"最多 / 最少"是一次 Merge 的精确比较次数范围，具体取哪个值取决于两个有序表怎么交错。它会让总比较次数在常数倍内变化，但不会改变整个归并排序的数量级：每一层所有合并的总比较次数都是 $\Theta(n)$（最多不超过 $n$，至少也是 $\Omega(n)$），层数固定为 $\lceil\log_2 n\rceil$，所以总比较次数始终是 $\Theta(n\log n)$。选择题说"比较次数的数量级与初始状态无关"，指的是这个数量级不变，而不是每一次比较次数完全相同。

合并的核心代码：

ElemType *B;  // 辅助数组，大小至少 n+1

void Merge(ElemType A[], int low, int mid, int high) {
    int i, j, k;
    for (k = low; k <= high; k++)
        B[k] = A[k];                       // 先把 A[low..high] 复制到 B
    for (i = low, j = mid + 1, k = i;
         i <= mid && j <= high; k++) {
        if (B[i] <= B[j]) A[k] = B[i++];   // 相等时取左边，保证稳定
        else A[k] = B[j++];
    }
    while (i <= mid) A[k++] = B[i++];      // 左边剩下的直接接上
    while (j <= high) A[k++] = B[j++];     // 右边剩下的直接接上
}

if 里必须写 <= 而不是 <：两个元素相等时先取左边的，相等记录的相对次序才不会变；写成 < 就可能先取右边的，稳定性被破坏。

#include <stdlib.h>

ElemType *B;  // 辅助数组，调用前分配，大小至少 n+1

// A[low..mid] 和 A[mid+1..high] 各自有序，把它们归并成一个有序表
void Merge(ElemType A[], int low, int mid, int high) {
    int i, j, k;
    for (k = low; k <= high; k++)
        B[k] = A[k];                       // 复制到辅助数组
    for (i = low, j = mid + 1, k = i;
         i <= mid && j <= high; k++) {
        if (B[i] <= B[j])
            A[k] = B[i++];                 // 取较小的，相等取左边
        else
            A[k] = B[j++];
    }
    while (i <= mid) A[k++] = B[i++];
    while (j <= high) A[k++] = B[j++];
}

void MergeSort(ElemType A[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;        // 从中间划分
        MergeSort(A, low, mid);            // 递归左半部分
        MergeSort(A, mid + 1, high);       // 递归右半部分
        Merge(A, low, mid, high);          // 合并两个有序子表
    }
}

void MergeSortAll(ElemType A[], int n) {
    B = (ElemType *)malloc((n + 1) * sizeof(ElemType));
    MergeSort(A, 1, n);
    free(B);
}

基数排序

基数排序不比较关键字的大小，而是把关键字拆成 $d$ 位，按每一位的值把记录分配到 $r$ 个队列中，再按队列顺序收集；从最低位到最高位做 $d$ 趟，最后整个序列有序。这是它和前面所有基于比较的排序最本质的区别；在 408 常考的这几大排序里，它就是"不需要比较关键字"的那一个（计数排序也不比较，但通常作为扩展）。

LSD（低位优先）：先按个位分配/收集，再按十位、百位……。之所以从低位开始，是因为每一趟的分配和收集都是稳定的：低位排好的相对次序会被高位保留下来；等最高位处理完，整个关键字就有序了。若从高位开始（MSD），每个桶还要递归处理，通常不作为默认做法，408 默认 LSD。

一趟分配 + 收集：

  1. 分配：顺序扫描记录，按当前位的值 digit = (key / exp) % r 放进第 digit 个队列。队列是 FIFO，同一队列里的记录保持原来的相对次序。
  2. 收集：从第 0 个队列到第 $r-1$ 个队列依次出队，串成一个新序列。

一趟分配 $O(n)$，收集 $O(r)$；一共 $d$ 趟，所以总时间 $O(d(n+r))$。若 $d$、$r$ 都是常数，就是 $O(n)$，这是它比基于比较的排序更快的地方。

  • 十位：分配 2:720,329、3:436,839、5:355,457,657；收集 720 329 436 839 355 457 657。
  • 百位：分配 3:329,355、4:436,457、6:657、7:720、8:839；收集 329 355 436 457 657 720 839。

三趟结束，序列已经按百位、十位、个位整体有序。注意每一趟收集时，同一队列内部都保持了上一趟的相对次序——这就是 LSD 能成立的关键。

入队 / 出队的细节：每个桶是一个 FIFO 队列。分配时只能挂到队尾（空队列时 front = rear = p，否则 rear->next = p; rear = p）；收集时只能从队头出队（front = front->next）。如果插到队头或从队尾取，同一 digit 内的相对次序就反了，LSD 的稳定性会被破坏。

展开：完整代码（数组桶 LSD 版） 
#include <stdlib.h>

// 对非负整数排序：d 是位数，r 是基数（十进制 r=10）
void RadixSort(int A[], int n, int d, int r) {
    int *bucket = (int *)malloc(n * sizeof(int));
    int *count = (int *)malloc(r * sizeof(int));
    int exp = 1;

    for (int pass = 0; pass < d; pass++) {
        for (int i = 0; i < r; i++) count[i] = 0;
        for (int i = 0; i < n; i++)
            count[(A[i] / exp) % r]++;       // 统计当前位各数字的个数

        for (int i = 1; i < r; i++)
            count[i] += count[i - 1];        // 前缀和：每个桶的结束位置

        for (int i = n - 1; i >= 0; i--) {   // 从后往前扫，保证稳定
            int digit = (A[i] / exp) % r;
            bucket[--count[digit]] = A[i];
        }
        for (int i = 0; i < n; i++)
            A[i] = bucket[i];                // 收集回 A

        exp *= r;                            // 处理下一位
    }

    free(bucket);
    free(count);
}

这段用"计数 + 前缀和"模拟 $r$ 个桶：--count[digit] 从桶尾往前放，配合从后往前扫描，效果等价于"按原顺序入队、从队头出队"，所以同一 digit 的记录会按原次序进入桶，收集后仍然稳定。若改成从桶头逆序放，稳定性就没了。

稳定性 稳定
存储 通常链式存储；数组 + 队列也可以
  • $d$ 是关键字位数，$r$ 是每一位的取值个数：十进制 $r=10$，小写字母 $r=26$。
  • 基数排序的时间与初始序列无关：每一趟都要扫描 $n$ 个记录，共 $d$ 趟，$d$ 由关键字位数决定。
  • 链式队列版只开 $r$ 个队列的头尾指针，记录结点复用，所以空间是 $O(r)$；上面的数组桶版额外开了 $n$ 个元素的 bucket，所以是 $O(n+r)$。
