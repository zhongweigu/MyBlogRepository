以 mov eax, dword ptr [ebp-8] 为例（设 [ebp-8] 中存放 80）：源操作数在 [ebp-8] 指向的存储单元，目的操作数是 EAX；执行后 EAX 变为 80，该存储单元不变，标志寄存器不变，PC 指向下一条指令。

x86 通用寄存器。 x86 有 8 个 32 位通用寄存器。为向后兼容 16 位和 8 位架构，EAX、EBX、ECX、EDX 的低 16 位可以作为 16 位寄存器单独使用（记作 AX、BX、CX、DX），每个 16 位寄存器又能拆成高 8 位、低 8 位两个独立的 8 位寄存器（AX 分为 AH、AL）。名字里的 E 表示 Extended，用于标识 32 位寄存器。

32 位 16 位 高 8 位 低 8 位 说明
EAX AX AH AL 累加器；乘除法的隐含操作数；函数返回值
EBX BX BH BL 基址寄存器
ECX CX CH CL 计数寄存器；循环计数、移位次数
EDX DX DH DL 数据寄存器；乘除法的高半部分、除法余数
ESI SI — — 源变址寄存器
EDI DI — — 目的变址寄存器
EBP BP — — 栈帧基址指针，指向当前栈帧底部
ESP SP — — 栈顶指针，指向当前栈顶

EIP 存放下一条要执行指令的地址，EFLAGS 存放标志位，两者不属于通用寄存器。EIP 不能直接用 mov 修改，只能由跳转、调用、返回等指令改变。

常用指令（Intel 格式，操作码 目的, 源）。

类别 指令 作用与要点
传送 mov dest, src dest ← src；不影响标志；两个操作数不能同时是内存
栈 push src ESP ← ESP−4，再令 M[ESP] ← src
栈 pop dst dst ← M[ESP]，再令 ESP ← ESP+4
算术 add/sub dest, src dest ← dest ± src；影响 CF、OF、SF、ZF
算术 inc/dec dest dest ← dest ± 1；影响 OF、SF、ZF，不影响 CF
乘法 mul src 无符号单操作数乘法，乘积在 EDX:EAX
乘法 imul src 有符号单操作数乘法，乘积在 EDX:EAX
除法 div src / idiv src 被除数在 EDX:EAX，商→EAX，余数→EDX
逻辑 and/or/xor dest, src 按位与/或/异或；CF=OF=0
逻辑 not dest 按位取反；不影响标志
逻辑 neg dest dest ← 0−dest；影响标志，dest≠0 时 CF=1
移位 shl/shr dest, count 逻辑左/右移；CF 为最后移出的位
比较 cmp dest, src 做 dest−src，只更新标志，不保存结果
测试 test dest, src 做 dest AND src，只更新标志，不保存结果
控制 jmp label 无条件跳转
控制 jcc label 条件跳转，依据 ZF、SF、OF、CF
过程 call label 返回地址压栈，跳到目标过程
过程 ret 弹出返回地址，跳回调用者

乘法：mul 与 imul。 两者都只有一个显式操作数，被乘数隐含在 EAX，乘积固定放在 EDX:EAX 中（高 32 位在 EDX，低 32 位在 EAX）。

  • mul src（无符号）：乘积的高半部分 EDX 不为 0，说明结果超出 32 位无符号数的范围，置 CF=OF=1；EDX=0 则 CF=OF=0。
  • imul src（有符号）：乘积的高半部分 EDX 不是低半部分 EAX 的符号扩展，说明结果超出 32 位有符号数的范围，置 CF=OF=1；是符号扩展则 CF=OF=0。
  • 单操作数乘法判溢出只看 CF、OF，不靠 SF：SF、ZF、AF、PF 均无定义。乘积的符号看 EDX:EAX 的最高位，也就是 EDX 的最高位。
  • 双操作数形式 imul dest, src 只保留低 32 位；结果能用 dest 的符号扩展表示时 CF=OF=0，否则为 1。

除法：div 与 idiv。 同样只有一个显式操作数（除数），被除数是 EDX:EAX 拼成的 64 位数。

  • div src 无符号，idiv src 有符号；商放 EAX，余数放 EDX，idiv 的余数符号与被除数相同。
  • 32 位被除数做除法前要先准备 EDX：无符号用 xor edx, edx 清零，有符号用 cdq 把 EAX 符号扩展到 EDX。
  • 除数为 0，或商超出 EAX 能表示的范围，都会产生除法异常。

逻辑与移位。

  • and、or、xor 都置 CF=OF=0，按结果置 SF、ZF、PF；xor eax, eax 是清零的常用写法。
  • not 不影响标志；neg 相当于 0−dest，影响标志，dest≠0 时 CF=1。
  • shl、shr 是逻辑移位，最后移出的那一位进 CF；shl 一位相当于乘 2，前提是移出的高位为 0；shr 一位相当于无符号数除 2。
  • 有符号数右移要用算术右移 sar，否则符号位被 0 填掉，负数会变成正数；算术左移与逻辑左移结果相同。

条件转移。

指令 含义 条件
je/jz 相等/为零 ZF=1
jne/jnz 不等/非零 ZF=0
js/jns 负/非负 SF=1 / SF=0
jo/jno 溢出/不溢出 OF=1 / OF=0
jg/jge 带符号 > / ≥ ZF=0 且 SF=OF / SF=OF
jl/jle 带符号 < / ≤ SF≠OF / ZF=1 或 SF≠OF
ja/jae 无符号 > / ≥ CF=0 且 ZF=0 / CF=0
jb/jbe 无符号 < / ≤ CF=1 / CF=1 或 ZF=1

无符号数比较只看 CF、ZF；带符号数比较看 SF、OF、ZF，其中「大于/小于」用 $SF\oplus OF$ 判断。

控制结构的机器级表示。 所有控制结构都由「比较 + 条件转移 + 无条件转移」拼成。下面的 jcc 泛指某个条件转移指令，L1、end 是标号。

if：

    cmp a, b
    jcc else        ; 条件不成立就跳到 else
    ; then 分支
    jmp end
else:
    ; else 分支
end:

没有 else 分支时，条件不成立直接跳到 end，省掉 else 段和那条 jmp end。

for：

    init
L1: cmp i, n
    jcc end         ; 循环条件不成立就结束
    ; body
    step
    jmp L1
end:

while：

L1: cmp a, b
    jcc end
    ; body
    jmp L1
end:

do-while：

L1: ; body
    cmp a, b
    jcc L1          ; 条件成立就回到循环体
end:
  • while 先判断后执行，循环体可能一次都不执行；do-while 先执行后判断，循环体至少执行一次。
  • for 与 while 的机器级表示几乎一样，for 只是把初始化和步进分别放在循环前和循环体末尾。
  • 编译器常把判断挪到循环末尾，先跳进循环体判断一次，再变成 do-while 的形状，这样每轮少一条 jmp。

一个具体例子：

int sum = 0;
for (int i = 0; i < n; i++) sum += a[i];

        mov  eax, 0             ; sum = 0
        mov  ecx, 0             ; i = 0
L1:     cmp  ecx, n
        jge  end                ; i >= n 时结束
        add  eax, [ebx + ecx*4] ; sum += a[i]，ebx 存 a 的首地址
        inc  ecx
        jmp  L1
end:

[ebx + ecx*4] 就是基址 + 变址 × 比例因子的形式：ebx 是数组首地址，ecx 是下标，4 是 int 的字节数。

过程调用与栈帧。 x86 的栈向低地址增长，ESP 始终指向栈顶。每个过程在栈上占一段区域，称为栈帧：EBP 指向当前栈帧的底部，ESP 指向栈顶；参数、返回地址、旧 EBP 和局部变量都在同一个栈帧里，用相对 EBP 的偏移访问。

cdecl 调用约定：

  • 参数从右向左压栈，最后一个参数先入栈，所以进入被调用者后，第 1 个参数在 [ebp+8]、第 2 个在 [ebp+12]；
  • 返回值放在 EAX；
  • 用 push 形式传入的参数由调用者清理（add esp, 4×参数个数）；
  • EAX、ECX、EDX 是调用者保存寄存器，EBX、ESI、EDI、EBP 是被调用者保存寄存器。

源程序：

int add(int x, int y) { return x + y; }

int caller() {
    int temp1 = 125;
    int temp2 = 80;
    int sum = add(temp1, temp2);
    return sum;
}

经 GCC 编译后，caller 对应的汇编代码如下：

caller:
    push ebp                     # 保存调用者 P 的 EBP
    mov  ebp, esp                # 建立新栈帧：EBP ← 当前栈顶
    sub  esp, 24                 # 为局部变量和参数区分配 24 字节
    mov  [ebp-12], 125           # M[R[ebp]-12] ← 125，即 temp1 = 125
    mov  [ebp-8], 80             # M[R[ebp]-8] ← 80，即 temp2 = 80
    mov  eax, dword ptr [ebp-8]  # R[eax] ← M[R[ebp]-8]，加载 temp2
    mov  [esp+4], eax            # 将 temp2 放入参数区高地址
    mov  eax, dword ptr [ebp-12] # R[eax] ← M[R[ebp]-12]，加载 temp1
    mov  [esp], eax              # 将 temp1 放入参数区低地址
    call add                     # 调用 add，返回值保存在 eax
    mov  [ebp-4], eax            # 将返回值存入 sum
    mov  eax, dword ptr [ebp-4]  # 将 sum 作为返回值
    leave                        # 等价于 mov esp, ebp 和 pop ebp
    ret                          # 弹出返回地址并跳回

add 的汇编按同样的约定写出：

add:
    push ebp
    mov  ebp, esp
    mov  eax, dword ptr [ebp+8]   # 参数 1
    add  eax, dword ptr [ebp+12]  # 参数 1 + 参数 2
    pop  ebp
    ret

call 压入的是它下一条指令的地址，也就是 caller 中 mov [ebp-4], eax 的地址；ret 要跳回的就是这里。

栈帧布局。 先看 call add 之前的 caller 栈帧：

call 压入返回地址、add 用 push ebp 保存 caller 的 EBP 之后，从高地址到低地址的完整布局如下：

相对 EBP 地址 内容 写入者
+4 0x0FFC P 调用 caller 时的返回地址 P 的 call caller
0 0x0FF8 P 的 EBP（0x1020） caller 的 push ebp
−4 0x0FF4 sum caller 的 mov [ebp-4], eax
−8 0x0FF0 temp2 = 80 caller 的 mov [ebp-8], 80
−12 0x0FEC temp1 = 125 caller 的 mov [ebp-12], 125
−16 0x0FE8 对齐填充（未使用） —
−20 0x0FE4 参数 2 = 80 caller 的 mov [esp+4], eax
−24 0x0FE0 参数 1 = 125 caller 的 mov [esp], eax
−28 0x0FDC call add 的返回地址 call 指令
−32 0x0FD8 caller 的 EBP（add 的 push ebp） add 的 push ebp

栈是怎么变化的。 设 P 在 call caller 前 ESP = 0x1000、P 的 EBP = 0x1020，call caller 把返回地址压到 0x0FFC，caller 从 ESP = 0x0FFC 开始执行：

  1. push ebp：ESP = 0x0FF8，[0x0FF8] 存入 P 的 EBP（0x1020）；
  2. mov ebp, esp：EBP = 0x0FF8，caller 的栈帧从这里向下展开；
  3. sub esp, 24：ESP = 0x0FE0，24 字节覆盖 0x0FE0～0x0FF7；
  4. mov [ebp-12], 125、mov [ebp-8], 80：0x0FEC ← 125，0x0FF0 ← 80；
  5. 两条 mov [esp+4], eax、mov [esp], eax：0x0FE4 ← 80，0x0FE0 ← 125；
  6. call add：0x0FDC ← 返回地址，ESP = 0x0FDC，EIP 跳到 add；
  7. add 的 push ebp、mov ebp, esp：0x0FD8 ← 0x0FF8，ESP = EBP = 0x0FD8，add 的栈帧建立；
  8. add 的 mov eax, [ebp+8]、add eax, [ebp+12]：取 0x0FE0 的 125 和 0x0FE4 的 80，相加得 205 放在 EAX；
  9. add 的 pop ebp、ret：EBP 恢复为 0x0FF8，ESP = 0x0FDC；ret 弹出 0x0FDC 的返回地址，ESP = 0x0FE0，回到 caller；
  10. caller 的 mov [ebp-4], eax：0x0FF4 ← 205；mov eax, [ebp-4]：EAX = 205；
  11. caller 的 leave：mov esp, ebp 使 ESP = 0x0FF8，pop ebp 取回 0x1020，ESP = 0x0FFC；
  12. caller 的 ret：弹出 0x0FFC 的返回地址，ESP = 0x1000，回到 P。

leave 等价于两条指令：

    mov esp, ebp    # 将栈指针 ESP 设置为当前 EBP 的值，即指向保存旧 EBP 的位置
    pop ebp         # 从栈中弹出旧 EBP 值，恢复过程 P 的基址指针

执行完 leave，EBP 已恢复为 P 中的值，ESP 指向 caller 的返回地址；ret 再从这个位置取出返回地址送进 EIP，ESP 加 4，回到 P 继续执行。

调用前，caller 保存旧 EBP、建立自己的栈帧、把参数写进参数区；call 只多做一件事——压入返回地址并把 EIP 改成 add 的入口。返回时顺序相反：被调用者恢复 EBP，ret 弹出返回地址；caller 用 EBP 找回自己的局部变量，最后 leave + ret 把整个栈帧拆掉。全程 EBP 只在 mov ebp, esp 时改变，ESP 则随 push/pop、call/ret、sub esp 不断变化。

这份代码里参数不是用 push 压栈的，而是提前在 sub esp, 24 划出的参数区里直接写 [esp]、[esp+4]；参数区和局部变量一次分配、一次 leave 回收，返回后不需要再 add esp, 8 清参数。

补充：24 字节和 32 字节是怎么来的

caller 的栈帧从 0x0FDC（call add 压入的返回地址）到 0x0FFB（旧 EBP 的最后一字节），正好 32 字节；再往上的 0x0FFC 已经是 P 调用 caller 时的返回地址，不属于 caller 的栈帧。

  • 旧 EBP：4 字节；
  • 局部变量 temp1、temp2、sum：12 字节；
  • 参数 temp1、temp2：8 字节；
  • call add 的返回地址：4 字节。

合计 $4+12+8+4=28$ 字节。GCC 要求调用发生时栈按 16 字节对齐，栈帧大小取 16 的倍数，28 向上补到 32，多出来的 4 字节就是 [ebp-16] 那格对齐填充——所以 sub esp, 24 而不是 20。

  class D41,D42 lvl3d;
  class D43,D44 lvl3l;
  • 无符号数比较只看 CF、ZF：A < B 有借位，CF=1；A = B 时 ZF=1；A ≤ B 就是 CF=1 或 ZF=1。
  • 有符号数比较看 SF⊕OF 与 ZF：小于对应 SF⊕OF=1，大于等于对应 SF⊕OF=0，相等仍看 ZF。NF 只是 SF 的另一种叫法。

  • 条件转移指令的检测位只决定「哪些标志参与判断」；多个检测位之间是「任一为 1 就转移」还是「全部满足才转移」，按题面说的来。

四*、指令专题

例题：【2010】第 43 题

某计算机字长为 16 位，主存地址空间大小为 128KB，按字编址。采用单字长指令格式，指令各字段定义如下表所示（Ms/Rs 描述源操作数，Md/Rd 描述目的操作数）：

字段 OP Ms Rs Md Rd
位数 4 3 3 3 3
位置 15～12 11～9 8～6 5～3 2～0

转移指令采用相对寻址方式，相对偏移量用补码表示，寻址方式定义见下表：

Ms/Md 寻址方式 助记符 含义
000B 寄存器直接 Rn 操作数 = (Rn)
001B 寄存器间接 (Rn) 操作数 = ((Rn))
010B 寄存器间接、自增 (Rn)+ 操作数 = ((Rn))，(Rn)+1 → Rn
011B 相对 D(Rn) 转移目标地址 = (PC) + (Rn)

注：(X) 表示存储器地址 X 或寄存器 X 的内容。

请回答：

  1. 该指令系统最多可有多少条指令？该计算机最多可有多少个通用寄存器？存储器地址寄存器（MAR）和存储器数据寄存器（MDR）至少各需要多少位？
  2. （原题第 2 问，转移指令的目标地址范围，从略。）
  3. 若操作码 0010B 表示加法操作（助记符为 add），寄存器 R4 和 R5 的编号分别为 100B 和 101B，R4 的内容为 1234H，R5 的内容为 5678H，地址 1234H 中的内容为 5678H，地址 5678H 中的内容为 1234H，则汇编语言为 add (R4), (R5)+（逗号前为源操作数，逗号后为目的操作数）对应的机器码是什么（用十六进制表示）？该指令执行后，哪些寄存器和存储单元中的内容会改变？改变后的内容是什么？
查看答案解析

（1） OP 占 4 位，最多 $2^4=16$ 条指令；Rs、Rd 各占 3 位，最多 $2^3=8$ 个通用寄存器。按字编址时，地址空间 128KB 合 $128\mathrm{KB}\div2\mathrm{B}=64\mathrm{K}$ 个字 $=2^{16}$ 个字，所以 MAR 至少 16 位；MDR 要能存下一个字，至少 16 位。

（3） 先按字段拆开 add (R4), (R5)+：

字段 值 依据
OP 0010 add
Ms 001 源操作数 (R4) 是寄存器间接
Rs 100 R4
Md 010 目的操作数 (R5)+ 是寄存器间接、自增
Rd 101 R5

拼起来是 0010 001 100 010 101B，即 2315H。

指令执行过程：

  • 源操作数 (R4)：寄存器间接，操作数为 $\mathrm{M}[1234\mathrm{H}]=5678\mathrm{H}$；
  • 目的操作数 (R5)+：先读出 $\mathrm{M}[5678\mathrm{H}]=1234\mathrm{H}$，再令 R5 加 1，R5 变为 5679H；
  • 相加：$5678\mathrm{H}+1234\mathrm{H}=68\mathrm{ACH}$，写回目的操作数所在的存储单元，即 $\mathrm{M}[5678\mathrm{H}]=68\mathrm{ACH}$。

所以执行后，R5 的内容变为 5679H，存储单元 5678H 的内容变为 68ACH；R4 仍为 1234H，存储单元 1234H 仍为 5678H。

这个自增到底怎么发生的。 把 (R5)+ 拆成三个问题看：

  • 什么时候自增：在按 (R5) 读出目的操作数之后、本次访存结束时自增，也就是「取完操作数就 +1」。它和 add 的加法本身无关——哪怕把 add 换成只读操作数的 cmp，只要操作数用 (Rn)+，取完操作数照样自增。
  • 自增的是谁：是目的操作数寻址方式里的 Rn，也就是 Rd 字段选中的 R5。源操作数 (R4) 的寻址方式是寄存器间接、不带自增，所以 R4 不变。
  • 结果保存在哪：加法的结果 68ACH 写到自增前的地址 5678H；自增的结果 5679H 写回 R5。写回目的操作数用的是取操作数时已经算出的旧地址，不会因为 R5 刚加过 1 就写到 5679H。

还有两点容易混：自增改的是寄存器里的地址，不是把存储单元的内容加 1；自增的对象是寄存器 R5，不是存储单元 5678H。按字编址时一个地址就是一个字（16 位），「指向下一个字」就是 +1；若按字节编址且操作数占 2 字节，才需要 +2。

例题：【2013】第 44 题

某计算机采用 16 位定长指令字格式，CPU 中有一个标志寄存器，其中包含进位/借位标志 CF、零标志 ZF 和符号标志 NF。假定为该机设计了条件转移指令，其格式如下：

字段 OP C Z N OFFSET
位数 5 1 1 1 8
位置 15～11 10 9 8 7～0

其中，00000 为操作码 OP；C、Z 和 N 分别为 CF、ZF 和 NF 的对应检测位，某检测位为 1 时表示需检测对应标志位，需检测的标志位中只要有一个为 1 就转移，否则不转移。例如，若 C=1、Z=0、N=1，则需检测 CF 和 NF 的值，当 CF=1 或 NF=1 时发生转移；OFFSET 是相对偏移量，用补码表示。转移执行时，转移目标地址为 (PC)+2+2×OFFSET；顺序执行时，下条指令地址为 (PC)+2。请回答下列问题。

  1. 该计算机存储器按字节编址还是按字编址？该条件转移指令向后（反向）最多可跳转多少条指令？
  2. 某条件转移指令的地址为 200CH，指令内容为 00000 0 1 1 11100011，若该指令执行时 CF=0、ZF=0、NF=1，则该指令执行后 PC 的值是多少？若该指令执行时 CF=1、ZF=0、NF=0，则 PC 的值又是多少？请给出计算过程。
  3. 实现“无符号数比较小于等于时转移”功能的指令中，C、Z 和 N 应各是什么？
  4. 以下是该指令对应的数据通路示意图，要求给出图中部件①～③的名称或功能说明。
查看答案解析

（1）按字节编址；向后最多 128 条指令。

指令字长 16 位，即 2 字节。顺序执行时下条指令地址是 (PC)+2，说明 PC 每取一条指令加 2 个编址单位，编址单位是字节；若按字编址（字长 16 位），下条指令地址应当是 (PC)+1。

OFFSET 是 8 位补码，范围 $-128\sim+127$。公式里乘 2，是因为 OFFSET 以指令条数为单位、每条指令 2 字节；取最小值 $-128$，从自增后的 PC 往回最多跨过 128 条指令。

（2） 先拆指令字：C=0、Z=1、N=1、OFFSET=11100011B。OFFSET 按 8 位补码解释，11100011B $=256-227=-29$。

  • CF=0、ZF=0、NF=1：C=0 不检测 CF；Z=1 检测 ZF=0；N=1 检测 NF=1。检测的标志位中有一个为 1，转移。取指后 PC 先自增为 200EH，再加偏移：

$$200\mathrm{EH}+2\times(-29)=200\mathrm{EH}-58=1\mathrm{FD}4\mathrm{H}$$

所以执行后 PC = 1FD4H。

  • CF=1、ZF=0、NF=0：C=0，CF 虽然为 1 也不检测；Z=1 检测 ZF=0，N=1 检测 NF=0，两个都为 0，不转移。PC 顺序加 2，执行后 PC = 200EH。

转移地址的算法：PC 先自增，再叠偏移。 取指结束时 PC 已经变成 (PC)+2，指向顺序执行的下一条指令；转移目标是在这个自增后的 PC 上再加 2×OFFSET，所以公式写成 (PC)+2+2×OFFSET。做题时先写出 PC+2（本题为 200EH），再叠加 2×OFFSET；漏掉 +2 就会少算一条指令，把 1FD4H 错算成 1FD2H。

（3）C=1、Z=1、N=0。

无符号数比较 $A\le B$ 用 $A-B$ 判断：$A<B$ 时有借位，CF=1；$A=B$ 时 ZF=1。所以“小于等于”就是 CF=1 或 ZF=1，C、Z 都要置 1；无符号比较不看符号，N 置 0（若置 1，NF=1 时会误转移）。

（4）① 指令寄存器（IR）；② 移位器（左移一位）；③ 加法器。

  • ① 指令寄存器：暂存当前指令，分出 OP、C、Z、N、OFFSET 五个字段；
  • ② 移位器：把符号扩展后的 OFFSET 左移一位，得到 2×OFFSET；
  • ③ 加法器：把 (PC)+2 与 2×OFFSET 相加，得到转移目标地址。

C、Z、N 分别与 CF、ZF、NF 相与，三个与门的输出再或起来，作为多路选择器的控制信号：条件成立时选 ③ 送来的转移目标，条件不成立时选 (PC)+2，最后写回 PC。

例题：【2014】第 44 题

位数 6 5 5 16

OP 为操作码；Rs 和 Rd 为寄存器编号；OFFSET 为偏移量，用补码表示。请回答下列问题，并说明理由。

  1. M 的存储器编址单位是什么？
  2. 已知 sll 指令实现左移功能，数组 A 中每个元素占多少位？
  3. 表中 bne 指令的 OFFSET 字段的值是多少？已知 bne 指令采用相对寻址方式，当前 PC 内容为 bne 指令地址，通过分析表中指令地址和 bne 指令内容，推断出 bne 指令的转移目标地址计算公式。
  4. 若 M 采用如下“按序发射、按序完成”的 5 级指令流水线：IF（取指）、ID（译码及取数）、EXE（执行）、MEM（访存）、WB（写回寄存器），且硬件不采取任何转发措施，分支指令的执行均引起 3 个时钟周期的阻塞，则 P 中哪些指令的执行会由于数据相关而发生流水线阻塞？哪条指令的执行会发生控制冒险？为什么指令 1 的执行不会因为与指令 5 的数据相关而发生阻塞？
查看答案解析

（1）按字节编址。 指令长 32 位，即 4 字节；表中相邻指令的地址差都是 4（08048100H→104H→108H…），说明一个地址对应 1 字节。

（2）32 位（4 字节）。 sll R4, R2, 2 把下标 i 左移 2 位，相当于乘 4；而 A[i] 的地址 = A 首地址 + i × 元素大小，所以元素大小 = 4B = 32 位。

（3）OFFSET = -6，即 FFFAH；转移目标地址 = (PC) + 4 + 4×OFFSET（PC 为 bne 指令地址）。

先把 1446FFFAH 拆成字段：

字段 值
OP 000101B = 5
Rs 00010B = 2（R2）
Rd 00110B = 6（R6）
OFFSET FFFAH

FFFAH 按 16 位补码解释：$65530-65536=-6$。验证：bne 在 08048114H，目标 loop 在 08048100H，

$$08048114\mathrm{H}+4+4\times(-6)=08048118\mathrm{H}-24=08048100\mathrm{H}$$

正好回到 loop。等价写法：目标地址 = (PC+4) + 4×OFFSET，其中 PC+4 是 bne 的下一条指令地址。

（4）因数据相关阻塞的指令是 2、3、4、6；控制冒险发生在指令 6（bne）。

指令 依赖 类型
2 读 R4（1 写 R4） RAW
3 读 R4（2 写 R4） RAW
4 读 R5（3 写 R5） RAW，且是 load-use
6 读 R2（5 写 R2） RAW

没有转发时，消费者要等生产者 WB 写回后才能读，所以这四条都要停。指令 6 本身是分支，条件/目标确定前继续取指可能取错，属于控制冒险；分支还会让后续取指停 3 个周期。

指令 1 不会因为与指令 5 的相关而停：指令 1 读 R2、指令 5 写 R2。就同一轮看，这是反相关（WAR），指令 1 的读在指令 5 的写之前，不用等；就下一轮看，指令 1 虽然要读指令 5 写回的 R2，但两者之间隔着指令 6 和分支的 3 拍阻塞，等下一轮指令 1 到 ID 时，指令 5 早已写回，也不会停。

例题：【2017】第 44 题

在按字节编址的计算机 M 上，题 43 中 f1 的部分源程序与对应的机器级代码（包括指令的虚拟地址）如下表所示。f1、f2 来自前面的 2017-43：f1 用 int 计算 $f(n)$，f2 把 f1 中的 int 都换成 float。

int f1(unsigned n) {

    for (unsigned i = 0; i <= n - 1; i++) {
        ...
        power *= 2;
        ...
    }
    ...
    return sum;
}

其中，机器级代码行包括行号、虚拟地址、机器指令和汇编指令。请回答下列问题。

  1. 计算机 M 是 RISC 还是 CISC？为什么？
  2. f1 的机器指令代码共占多少字节？要求给出计算过程。
  3. 第 20 条指令 cmp 通过 i 减 n−1 实现对 i 和 n−1 的比较。执行 f1(0) 过程中，当 i=0 时，cmp 指令执行后，进/借位标志 CF 的内容是什么？要求给出计算过程。
  4. 第 23 条指令 shl 通过左移操作实现了 power *= 2 运算，在 f2 中能否也用 shl 指令实现 power *= 2？为什么？
查看答案解析

（1）CISC。 指令长度不固定：push ebp 是 1 字节（55），cmp 是 3 字节（39 4D F4），shl 是 2 字节（D1 E2），ret 是 1 字节（C3）；指令格式也不规整，cmp 还带 [ebp-0Ch] 这样的基址加偏移寻址。RISC 的特征是定长、格式规整、寻址方式少，和表中不符。

（2）96 字节。 第一条指令在 00401020H，最后一条 ret 在 0040107FH、长 1 字节，所以代码的结束边界是 00401080H：

$$00401080\mathrm{H}-00401020\mathrm{H}=60\mathrm{H}=96$$

也可以按「末条地址 − 首地址 + 末条长度」算：0040107FH − 00401020H + 1 = 96。

（3）CF=1。 n 是无符号数，f1(0) 时 $n=0$，$n-1$ 按 32 位无符号回绕成 FFFFFFFFH。cmp 做 $i-(n-1)$，即 00000000H − FFFFFFFFH：被减数小于减数，无符号减法需要借位，所以 CF=1；差值为 00000001H。

（4）不能。 f2 中的 power 是 float，shl 是整数左移，它把 IEEE 754 的 32 位位串整体左移一位：符号位、阶码、尾数都会错位，移完并不是把浮点数值乘 2。f2 里的 power *= 2 要用浮点乘法（或直接把阶码加 1），不能用 shl。

例题：【2023】第 44 题

背景（来自 2023-43）：计算机 M 字长 32 位，按字节编址，采用请求调页的虚拟存储管理，虚拟地址 32 位，页大小 4KB。C 程序段中 int a[24][64] 按行优先存放，首地址为 0042 2000H，sizeof(int)=4；执行前数组 a 不在主存，执行过程中不发生页面置换。

int a[24][64];
for (i = 0; i < 24; i++)
    for (j = 0; j < 64; j++)
        a[i][j] = 10;

请回答下列问题。

  1. 第 20 条指令的虚拟地址是多少？
  2. 已知第 2 条 jmp 和第 7 条 jge 都是跳转指令，其操作码分别是 EBH 和 7DH，跳转目标地址分别为 0040 1084H、0040 10BCH，这两条指令都采用什么寻址方式？给出第 2 条指令 jmp 的跳转目标地址计算过程。
  3. 已知第 19 条 mov 指令的功能为“a[i][j]←10”，其中 ecx 和 edx 为寄存器名，0042 2000H 是数组 a 的首地址，指令中源操作数采用什么寻址方式？已知 edx 中存放的是变量 j，ecx 中存放的是什么？根据该指令的机器码判断计算机 M 采用大端还是小端方式。
  4. 第一次执行第 19 条指令时，取指令过程中是否会发生缺页异常？为什么？
查看答案解析

（1）004010B9H。 第 19 条指令从 004010AEH 开始，机器码占 11 字节（C7 84 82 3 字节 + 4 字节位移 + 4 字节立即数），所以下一条指令地址为

$$004010AE\mathrm{H}+0\mathrm{BH}=004010B9\mathrm{H}$$

（2）两条都采用相对寻址。 转移目标 = 下一条指令地址 + 8 位补码偏移量。第 2 条 jmp 在 00401079H，指令长 2 字节（EB 09），下一条指令地址为 00401079H+2=0040107BH，偏移量为 09H：

$$0040107\mathrm{B}\mathrm{H}+09\mathrm{H}=00401084\mathrm{H}$$

（3）源操作数采用立即数寻址；ecx 中存放 i×64×4，即 i×256（i 左移 8 位）；M 采用小端方式。

  • 第 19 条指令的源操作数是 0Ah，直接写在指令里，属于立即（数）寻址。
  • a[i][j] 的地址 $=00422000\mathrm{H}+(i\times64+j)\times4=00422000\mathrm{H}+i\times256+j\times4$，而指令写成 [ecx+edx*4+00422000h]、edx 中存的是 j，所以 ecx 中存的是 $i\times256$。
  • 机器码中 00422000H 存为 00 20 42 00，低字节在前，是小端；立即数 0Ah 也存成 0A 00 00 00，同样说明是小端。

（4）不会。 第 19 条指令的 11 字节在 004010AEH～004010B8H，位于代码页 00401000H～00401FFFH（4KB）内，取第 1～18 条指令时该页已经调入主存，而且本条取指没有跨页，所以取指令不会缺页。第一次执行时可能缺页的是数据页 00422000H（数组不在主存），但那是取数据，不是取指令。
