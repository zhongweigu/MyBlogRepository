中断：CPU 被“叫走”再回来的全过程

中断是 408 计组和操作系统共同的重点。计组关心的是硬件怎么响应、断点怎么保存、数据怎么流；操作系统关心的是中断处理程序、屏蔽、嵌套和返回。这一节按时间顺序，从设备发出请求开始，一直走到 IRET 返回。

先记住一条主线：中断源请求 → 中断控制器判优/屏蔽 → CPU 在指令边界响应 → 硬件隐指令保存 PSW/PC 并查向量 → 服务程序保护现场、处理设备 → 恢复现场 → IRET 返回断点。

起点：中断源发出请求

中断源可以是外设（键盘、磁盘、网卡）、时钟，也可以是异常（缺页、除零）。以键盘为例：

  1. 按键产生扫描码，键盘控制器把数据放入接口的数据缓冲寄存器，并把状态寄存器的“就绪”位置 1。
  2. 键盘接口向中断控制器发中断请求（IRQ 线）。
  3. 中断控制器检查该请求是否被屏蔽、优先级如何；若允许，向 CPU 发 INTR 信号。
  4. 请求会保持，直到 CPU 响应、接口清除请求（或控制器 EOI）。

多个设备同时请求时，由中断控制器按硬件排队优先级选一个；被屏蔽的请求不会送到 CPU。注意：硬件优先级决定“谁先被响应”，不决定“进入服务程序后谁还能打断谁”，后者看屏蔽字。

CPU 什么时候响应

CPU 不是在任意时刻跳走，通常只在一条指令执行结束时检查中断请求。响应要同时满足：

  • 开中断：IF=1（可屏蔽中断）；不可屏蔽中断不受 IF 影响。
  • 当前指令执行结束：保证断点是一条完整指令的边界；异常可在指令执行中产生，是另一条路径。
  • 有未被屏蔽的中断请求：中断控制器已经把请求送到 CPU。

满足后，CPU 进入中断周期：发出中断应答（INTA），中断控制器把中断类型号送到数据总线。类型号不是入口地址，只是查向量表的索引。

如果 CPU 正在执行更高优先级的中断服务程序，或者 IF=0，当前请求要等待；这就是“中断响应时机”和“中断嵌套”的区别。

硬件隐指令：保存断点、找到入口

CPU 响应后，硬件自动执行一组操作，称为中断隐指令。它不是一条真正的机器指令，而是硬件在中断周期里完成的一组微操作：

  1. 关中断：保存旧 PSW（含 IF、模式位等），把 IF 清 0，防止响应过程被新的中断打断。
  2. 保存断点：把当前 PC（已经被中断指令更新为下一条指令地址）和旧 PSW 压入内存栈，或存入指定单元；SP 随之下移。
  3. 取中断类型号：通过 INTA 从控制器取得类型号。
  4. 查中断向量表：用类型号 × 表项大小得到偏移，从内存读出该中断的服务程序入口地址，送入 PC。
  5. 切换模式/栈：从用户态切到内核态，必要时切换到内核栈。

数据流可以拆成三条：

  • 请求/应答：设备 → 中断控制器 → CPU（INTR / INTA / 类型号）。
  • 保存断点：CPU 的 PC、PSW → 内存栈（写总线）。
  • 取入口：内存中的向量表 → CPU 的 PC（读总线）。

这张图上有四个常考判断：

  • 模式位：响应时还要把 CPU 模式位改为内核态，这一步由硬件自动完成，不是服务程序做的。
  • 隐指令不是指令：中断响应过程不是执行了“中断响应”这条机器指令，而是硬件在中断周期完成的一组微操作。
  • 三个条件：开中断、当前指令执行完成、有未被屏蔽的中断请求，同时满足才响应。
  • 识别中断源：软件查询法用统一的异常/中断查询程序，按优先级查异常状态寄存器，先查到先处理；硬件向量法给每个中断一个类型号，类型号对应一个服务程序，入口地址就是中断向量。CPU 取得类型号后，算出向量表项地址，从表中取出入口地址送 PC。

服务程序：保护现场、处理设备、恢复现场

硬件只保存了 PC/PSW，通用寄存器还没保存。服务程序通常按下面的顺序执行：

  1. 保护现场：把本程序要用的通用寄存器压栈（软件指令）。
  2. 开中断：如果允许中断嵌套，在保护现场后开中断；不允许则保持关中断。
  3. 处理设备：读状态寄存器判断事件，读/写数据端口搬运数据，清除接口的中断请求，必要时向中断控制器发 EOI。
  4. 恢复现场：把通用寄存器弹出栈。
  5. 关中断：防止恢复过程被新的中断打断（具体顺序依系统而定）。
  6. 开中断并 IRET：IRET 从栈中弹出旧 PSW 和旧 PC，回到断点。

键盘例子：CPU 在服务程序里从数据端口读扫描码 → 送键盘缓冲区 → 清接口就绪位/发 EOI → 恢复现场 → IRET。数据从设备接口的数据缓冲寄存器经系统数据总线进入 CPU 寄存器，再写入内存缓冲区；这条数据通路和普通 I/O 读一样。

最后返回到哪里

“返回断点”要分类型，不能一律说当前指令：

类型例子返回地址原因
外中断键盘、磁盘、时钟被中断指令的下一条指令当前指令已执行完，PC 已增量；中断是异步事件
故障 fault缺页、除零、非法操作数当前指令重新执行故障排除后要重试当前指令
陷阱 trap系统调用、断点下一条指令有意陷入，处理完继续
终止 abort硬件故障不返回无法恢复

所以外中断的“断点”是下一条指令地址；故障异常的“断点”是当前指令地址。这是选择题最爱设的陷阱。

单级中断与多重中断：处理顺序差在哪

阶段单级中断多重中断
响应关中断 → 保存断点 → 中断服务程序寻址相同
处理开头保存现场和屏蔽字保存现场和屏蔽字
开中断时机不打开，处理期间不响应新中断保存现场后开中断，允许更高处理优先级中断嵌套
执行服务程序执行期间全程关中断执行期间可被更高优先级中断打断；嵌套返回后继续
处理结尾恢复现场和屏蔽字 → 开中断 → 中断返回先关中断 → 恢复现场和屏蔽字 → 开中断 → 中断返回

为什么多重中断要在恢复现场前先关中断？恢复通用寄存器和屏蔽字的过程中，如果有新中断插入，栈帧会被破坏；所以要先关中断，恢复完再开中断返回。嵌套按栈后进先出：高优先级中断先返回，再回到被打断的服务程序。

多重中断：谁能打断谁

进入服务程序后，如果开中断且当前屏蔽字允许，更高处理优先级的中断可以打断当前服务程序，形成嵌套。判断分两步：

  1. 响应顺序：多个请求同时到达，先看硬件排队优先级。
  2. 处理顺序：进入某个服务程序后，看当前屏蔽字是否允许其他中断；0 允许、1 屏蔽。

嵌套时栈按后进先出：高优先级中断的 PSW/PC/寄存器先入栈，先返回；回到被打断的服务程序，再返回主程序。未被响应的中断要等 CPU 回到主程序后才能再次响应。

例题：4 个中断源同时请求，轨迹怎么画

服务程序ABCD允许谁打断自己
A1101只有 C
B0100A、C、D
C1111都不能
D0101A、C

0 表示允许，1 表示屏蔽。硬件排队顺序是 A>B>C>D；由屏蔽关系推出的处理优先级是 C>A>D>B。

  1. 四个请求同时到达，先按硬件排队选 A，响应 A。
  2. A 的屏蔽字只允许 C（C 位为 0），B、D 都被屏蔽；所以 C 打断 A，响应 C。
  3. C 的屏蔽字全为 1，谁都不能打断 C；C 执行完返回 A。
  4. A 继续执行完，返回主程序。此时 B、D 仍未响应；按硬件顺序 B 先于 D，响应 B。
  5. B 的屏蔽字允许 D（D 位为 0），D 打断 B；D 的屏蔽字不允许 B，D 执行完返回 B。
  6. B 执行完返回主程序，轨迹结束。

所以轨迹是：主程序 → A → C → A → 主程序 → B → D → B → 主程序。

为什么不是一开始就响应 C？ 四个请求同时到达时，硬件只按排队顺序选 A；C 的“处理优先级最高”只决定进入服务程序后能不能打断别人，不参与第一次响应排序。

为什么 A 之后是 C，不是 B？ B 的硬件优先级虽然高于 C，但 A 的屏蔽字把 B 屏蔽了；当前可响应的只有 C。硬件优先级只在“当前未被屏蔽的请求”之间比较。

为什么 A 结束后要回主程序才响应 B？ B 在 A 的服务程序里一直被屏蔽，不能嵌套；A 的返回地址是主程序，A 结束后 CPU 回到主程序上下文。B 仍处于未响应状态，CPU 在回到主程序后、执行下一条主程序指令前响应 B。不是“必须先执行一段主程序”，而是“必须先退出 A 的服务程序”。

例题：请求不同时到达，轨迹又怎么变

这次四个请求不是同时到达，图中箭头顺序是 D → A → B → C。硬件排队仍是 A>B>C>D，处理优先级仍是 C>A>D>B，屏蔽字也不变。

  1. D 先到：此时只有 D 一个请求，没有竞争，CPU 直接响应 D，开始执行 D 的服务程序。
  2. A 到达：D 的屏蔽字中 A 位是 0（允许 A），所以 A 抢占 D。D 的现场留在栈里，CPU 转去执行 A。
  3. B 到达：A 的屏蔽字中 B 位是 1（屏蔽 B），B 不能打断 A，只能等待。
  4. C 到达：A 的屏蔽字中 C 位是 0（允许 C），所以 C 抢占 A。
  5. C 执行：C 的屏蔽字全为 1，谁也不能打断 C；C 执行完返回 A。
  6. A 继续：A 执行完，返回它打断的 D（不是主程序）。
  7. D 继续：D 执行完，返回主程序。此时 B 仍在等待。
  8. B 响应：B 执行完，返回主程序。

所以服务程序序列是：D → A → C → A → D → B。

关键点：

  • 先到先响应：D 到达时只有它一个请求，不需要比较优先级；优先级只在多个请求同时等待时起作用。
  • A 能打断 D：看的是 D 的屏蔽字，不是 A 的优先级；D 的 A 位为 0，所以允许。
  • B 一直等：A 屏蔽 B、D 也屏蔽 B、C 全屏蔽；B 只能等 D 也返回主程序后再响应。
  • A 返回 D，不是直接回主程序：A 是在 D 执行期间打断 D 的，所以 A 的断点是 D 的服务程序；C 返回 A、A 返回 D、D 最后返回主程序。

把整条路径串一遍

  1. 设备完成/需要服务，置请求；中断控制器判优、查屏蔽，向 CPU 发 INTR。
  2. CPU 执行完当前指令，检查 IF、请求和优先级；满足则响应。
  3. CPU 发 INTA，控制器送回中断类型号。
  4. 硬件隐指令：关中断，旧 PSW、旧 PC 入栈，类型号查向量表，入口送 PC，切换内核态。
  5. 服务程序：保护通用寄存器 → 开中断（可嵌套）→ 读状态/读写数据端口/清请求 → 恢复现场。
  6. IRET：从栈弹出旧 PSW、旧 PC；外中断返回到下一条指令，故障返回当前指令重试。

易错点

  • 中断通常在指令边界响应，不是任意时钟周期；异常可在指令执行中产生。
  • 中断隐指令由硬件完成，主要保存 PC/PSW；通用寄存器由服务程序保存。
  • 中断向量是服务程序入口地址；中断类型号只是查表索引。
  • 外中断返回下一条指令；故障异常返回当前指令重新执行。
  • 硬件优先级高 ≠ 一定能打断当前服务程序；能否嵌套看屏蔽字。
  • 中断请求要一直保持到被响应/清除；DMA 请求通常在总线周期结束时响应，优先级通常更高。
  • 中断服务程序要清除设备请求/发 EOI，否则可能刚返回又立刻再次中断。

本考点为新增专题：按 408 计组 I/O 系统与操作系统中断机制整理；重点保留请求、响应、隐指令、服务程序、返回地址和多重中断的完整链路。
