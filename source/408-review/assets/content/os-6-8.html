这七个流程共享一条主线：用户提出逻辑请求 → 内核找到对象 → 驱动操作控制器 → 硬件传送 → 中断/DMA 报告 → 内核唤醒/复制 → 用户继续。差别只在“对象”和“是否缓冲/排队”。

二、键盘输入：进程怎样拿到字符 A

场景：进程 P 正在 CPU 上运行，进程 Q 之前调用 read() 等待键盘输入而阻塞；用户在键盘上按下字符 A。

  1. 按键产生数据：用户按下 A，键盘控制器（I/O 接口）接收到扫描码/字符，暂存在控制器的数据寄存器中，并置“数据就绪”。
  2. 控制器发中断请求：键盘控制器向 CPU 发中断请求；此时 CPU 可能正在执行进程 P，当前指令尚未执行完。
  3. CPU 响应中断：当前指令结束后，若开中断且该中断未被屏蔽，CPU 关中断、保存 PC/PSW（断点）、切换内核态，按中断向量找到键盘 ISR。此时只是执行流进入内核，进程 P 不一定被切换，也可能仍处于运行态。
  4. ISR 读入内核缓冲区：ISR 从键盘控制器的数据寄存器读出 A，放入内核缓冲区。为什么不直接放用户缓冲区？因为中断到达时，目标进程可能已退出、被换出、地址空间变化，或还没准备好接收缓冲区；内核缓冲区始终由 OS 控制。
  5. 唤醒等待进程：OS 检查是否有进程在等待键盘输入。若有进程 Q，Q 期待的事件发生，从阻塞态变为就绪态，插入就绪队列；唤醒不等于立刻获得 CPU。
  6. ISR 返回/可能调度：ISR 结束后，CPU 可能返回进程 P 继续执行，也可能由调度程序从就绪队列选择 Q 上 CPU。中断可能引发调度，但中断本身不等于进程调度。
  7. Q 完成 read：若 Q 被调度，CPU 仍在内核态，恢复 Q 的内核栈/寄存器，继续被挂起的 read()：把内核缓冲区中的 A 复制到 Q 的 buf，read 返回；此时 CPU 才切回用户态，Q 拿到字符 A。

把这个流程压成一句：设备中断把数据送进内核，内核唤醒等待者，等待者被调度后在内核里完成 read 的最后一段复制。最容易错的是把“中断响应”当成“进程切换”，或把“唤醒”当成“立即运行”。

三、读磁盘块：数据怎样进入用户空间

场景：进程调用 read(fd, buf, n) 读取文件的一个数据块。它与键盘流程共享“内核缓冲区 + 唤醒”的思想，但中间多了文件系统、磁盘驱动和 DMA。

  1. 用户层：read 库函数把参数放进寄存器/栈，执行陷入指令，进入内核。
  2. 文件系统层：根据 fd 找到进程打开文件表项 → 系统打开文件表项 → 内存 inode；把用户要读的文件逻辑块号翻译成磁盘逻辑块号。若页缓存/缓冲区已有所需数据，直接复制到用户缓冲区，流程提前结束。
  3. 块设备层/驱动：把磁盘逻辑块号转成柱面/磁头/扇区，构造读命令，写入控制器寄存器，启动磁盘；若磁盘忙，请求挂入队列。
  4. 硬件传送：磁盘控制器执行寻道、旋转、读取；若采用 DMA，数据直接写入内核缓冲区，不需要 CPU 逐字搬。
  5. 完成中断：磁盘/DMA 控制器发出中断；ISR 检查状态、清中断、标记缓冲区有效，唤醒等待该块的进程。
  6. 复制到用户空间：进程被调度后，内核把数据从内核缓冲区复制到用户 buf，更新文件偏移，read 返回。

这个流程的完整 open/read/close 细节在 目录、文件共享与打开文件，文件物理结构和盘块定位在 文件的物理结构。I/O 章节只需抓住：文件系统负责“读哪个块”，驱动负责“怎样读”，DMA/中断负责“读完通知”。

四、多个磁盘请求：选择、定位、读取

场景：P1 要读 55 号磁道，P2 要读 58 号，P3 要读 39 号……多个请求同时到达。

  1. 请求排队：每个请求生成一个 I/O 请求块，挂到磁盘设备队列；磁盘是共享设备，可以交替服务多个进程，但同一时刻只有一个请求真正占用磁头。
  2. 调度选择：按 FCFS/SSTF/SCAN/C-SCAN 等算法从队列选下一个请求；算法只改变服务顺序，不改变磁盘几何。
  3. 逻辑地址定位：把逻辑块号转换为柱面号/磁头号/扇区号；文件系统/驱动完成这一层转换。
  4. 驱动启动：驱动程序设置控制器命令、内存地址、传送长度，启动磁盘；若使用 DMA，设置 DMA 控制器。
  5. 寻道/旋转/传输：磁头径向移动到目标柱面（寻道），盘片旋转到目标扇区（旋转延迟），读写数据（传输）。
  6. 完成与唤醒：DMA/中断报告完成；ISR 标记请求完成，唤醒对应进程，调度器再决定谁继续。

如果题目问“磁盘 I/O 请求的处理流程”，不要把“调度算法”放在“地址转换”之后：通常先由文件系统/驱动得到逻辑块号，磁盘调度决定先服务哪个请求，驱动再把选中请求的逻辑块号转成 CHS 并启动。不同教材的描述顺序可能略有差异，但“请求排队 → 调度 → 地址转换 → 启动 → 传送 → 完成”这条主干不变。

五、连续输入：缓冲区怎样解耦

设备连续产生数据，CPU 一边处理，设备一边输入。没有缓冲区时，两边必须严格同步；有缓冲区后，设备先写入，CPU 稍后取。

  • 单缓冲：每块处理时间 = max(C,T)+M；T>C 时设备是瓶颈，T<C 时 CPU 是瓶颈。
  • 双缓冲：每块处理时间 = max(C+M,T)；C+M<T 时设备可连续输入，C+M>T 时 CPU 不必等设备。

在键盘流程中，缓冲区是“内核缓冲区”；在文件读中，缓冲区可能是页缓存/内核缓冲区；在块设备输入中，DMA 直接把数据送入内核缓冲区。缓冲区的层次和数量改变的是“等待发生在哪”，不改变“数据最终要复制到用户区”这一终点。

六、打印机：SPOOLing 怎样排队

打印机是独占设备。SPOOLing 让多个进程“同时”提交打印任务，但物理打印仍是一份一份串行输出。

  1. 进程提出打印请求，把数据写入内存输出缓冲区。
  2. 输出进程把数据送入磁盘输出井，形成井文件，按队列排队。
  3. 打印机空闲时，输出进程从输出井取出一份数据，经输出缓冲区送到打印机。
  4. 打印完成后释放打印机，输出进程继续取下一份。

关键点：井在磁盘、缓冲区在内存、输出进程负责搬运、井管理程序负责控制；SPOOLing 把“等待打印机”变成“等待输出进程/磁盘空间”，提高的是并发提交能力，不是打印机的物理并行度。

七、新磁盘：怎样变成可启动系统

从裸盘到可启动系统，是一条“格式化 → 分区 → 建文件系统 → 安装 → 引导 → 内核初始化”的链：

  1. 物理格式化：划分磁道/扇区，写入扇区头和校验信息。
  2. 分区：建立分区表，把磁盘划成多个区域；MBR/GPT 记录分区位置。
  3. 逻辑格式化：在目标分区建立引导块、超级块、空闲空间管理、inode 表、根目录。
  4. 安装 OS：写入内核、驱动、系统文件和引导配置。
  5. 引导：固件 → MBR/GPT → 活动分区 PBR → OS loader → 内核；细节见 OS 引导。
  6. 内核初始化：内存管理 → 中断/异常 → 设备/驱动 → 进程/调度 → 文件系统/根挂载 → 第一个用户进程。

这条链和“读磁盘块”共享驱动/中断/DMA，但目标不同：读块是“取一个已有文件的数据”，启动是“把内核和根文件系统装配起来”。不要把 MBR、PBR、引导块、超级块混成一个层次。

八、收束：三条最容易混的边界

容易混正确边界
中断 vs 进程调度中断只把执行流转入内核 ISR；是否切换进程由调度器决定
唤醒 vs 运行阻塞态 → 就绪态只是“可以运行”，还要被调度才 → 运行态
内核缓冲 vs 用户缓冲设备数据先进内核缓冲；read 返回前再复制到用户 buf

把七个流程记成一条链：用户请求 → 内核对象 → 驱动/控制器 → 硬件传送 → 中断/DMA → 内核缓冲/唤醒 → 用户复制。链条上的每一段，都能对应回前面某一页的机制。
