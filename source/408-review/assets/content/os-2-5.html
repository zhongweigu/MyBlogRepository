并发进程/线程共享资源时，最难的不是“同时运行”，而是“同时改同一份数据”。同步与互斥要解决两类问题：互斥——临界资源一次只让一个进程用；同步——多个进程必须按某个先后次序推进。判断一个方法好不好，就看它是否同时满足互斥、进展、有限等待，最好还能让权等待。

一、临界资源、临界区与四条准则

临界资源是一次只允许一个进程使用的资源，例如打印机、共享变量、共享缓冲区。临界区是进程中访问临界资源的那段代码。典型的临界区结构是：

进入区：检查/加锁，确保互斥
临界区：访问共享资源
退出区：解锁，唤醒等待者
剩余区：不访问临界资源

一个正确的互斥方案要满足：

准则含义违反后的现象
空闲让进临界区空闲时，应允许一个请求者立即进入资源闲置，效率低
忙则等待已有进程在临界区时，其他进程必须等待两个进程同时进入，数据被破坏
有限等待请求者应在有限时间内进入，不能无限等饥饿/死等
让权等待进不去时应释放 CPU，不要忙等空转浪费 CPU

“忙则等待”和“让权等待”不矛盾：忙则等待是“不能进”，让权等待是“不能进时别占着 CPU 空转”。很多软件/硬件方法只保证互斥，不保证让权等待。

二、单标志法

用一个 turn 表示“轮到谁进”：

turn = 0;  // 0 表示轮到 P0

P0: while (turn != 0);  // 等
    临界区
    turn = 1;

P1: while (turn != 1);
    临界区
    turn = 0;

它能保证互斥，但只能严格交替：P0 进完把 turn 给 P1，如果 P1 一直不想进，P0 也不能再次进入，即使临界区空闲。这违反空闲让进。所以单标志法“互斥对、进展错”。

三、双标志法

1. 先检查，后设置

flag[0] = flag[1] = false;

Pi: while (flag[j]);   // 先看对方想不想进
    flag[i] = true;    // 再声明自己想进
    临界区
    flag[i] = false;

“检查”和“设置”不是原子操作：P0 检查 flag[1] 为 false，还没来得及设置，P1 也检查 flag[0] 为 false，于是双方都进入。它违反忙则等待（互斥失败）。

2. 先设置，后检查

flag[0] = flag[1] = false;

Pi: flag[i] = true;    // 先声明
    while (flag[j]);   // 再看对方
    临界区
    flag[i] = false;

双方都先设置自己的 flag，再检查对方，结果都看到对方为 true，互相等待。它保证互斥，但可能饥饿/死等，违反进展和有限等待。两个进程“太谦让”也会出问题。

四、Peterson 算法

Peterson 用 flag 表示“想进”，用 turn 表示“谦让”：

flag[0] = flag[1] = false;
turn = 0;

Pi: flag[i] = true;        // 我想进
    turn = j;              // 让对方先
    while (flag[j] && turn == j);  // 对方想进且轮到对方，就等
    临界区
    flag[i] = false;

若双方同时想进，最后写 turn 的人会“让”给对方，自己等待；对方退出后，自己再进。它能满足互斥、空闲让进、有限等待，但仍是忙等，不满足让权等待。它只适用于两个进程；多进程要扩展（如面包店算法）。

五、硬件方法：关中断、TS、Swap

关中断：进入临界区前关中断，退出后开中断。单处理机上，关中断期间不会发生进程切换，因此能保证互斥。但它是特权操作，不能让用户随便用；多处理机上其他 CPU 仍在运行，关本 CPU 的中断并不能阻止它们；而且关中断会影响整个系统的响应。它只适合内核短临界区。

Test-and-Set（TS）：原子地“读出旧值并置 true”：

bool TS(bool *lock) {
    bool old = *lock;
    *lock = true;
    return old;
}

while (TS(&lock));   // 旧值为 true 说明别人占着，继续试
临界区
lock = false;

Swap：原子地交换一个局部变量和 lock 的值；局部变量为 false 时，交换后若旧 lock 为 false，说明拿到锁。两者都保证互斥，但都是忙等；TS 不保证有限等待，可能有人一直抢不到。

六、信号量与 P/V

408 还会考信号量，导图只列了软件/硬件/管程，这里补上。信号量是一个整型变量加一个等待队列，P/V 必须原子执行：

P(S):  S.value--;
       if (S.value < 0) block(S.queue);

V(S):  S.value++;
       if (S.value <= 0) wakeup(S.queue);
  • S.value >= 0 表示还有多少可用资源；
  • S.value < 0 时，绝对值表示等待队列中的进程数；
  • P 可能阻塞，V 可能唤醒；P/V 成对出现。
用途初值P/V 位置
互斥信号量1临界区前后 P/V
同步信号量0 或资源数前驱完成后 V，后继开始前 P
资源计数资源总数申请资源 P，释放资源 V

信号量能实现让权等待（P 阻塞时释放 CPU），但P 的顺序可能死锁：两个进程分别持有 S1、S2，再互相申请对方，形成循环等待。V 的顺序一般不会造成死锁。

七、管程与条件变量

管程把共享数据和对它的操作封装在一起，并保证同一时刻只有一个进程在管程内执行。它像“自动加锁的对象”：进程调用管程过程时自动获得互斥，退出时自动释放。

管程里还有条件变量，用于等待某个条件：

  • x.wait()：释放管程锁并阻塞，进入 x 的等待队列；
  • x.signal()：唤醒 x 等待队列中的一个进程；没有等待者时，信号会丢失（不像信号量会计数）；
  • 被唤醒的进程还要重新竞争管程锁；条件可能又变了，所以通常用 while 重新检查条件。

互斥锁保护“进入管程”，条件变量负责“等条件”。两者不能互相替代：条件变量本身不计数、不提供互斥。

八、方法对比：谁忙等，谁饥饿

九、互斥、同步、生产者-消费者

互斥是“不能同时进”，同步是“必须先 A 后 B”。生产者-消费者是两者叠加的典型：

  • 缓冲区是临界资源，生产者和消费者不能同时改队列 → 互斥信号量 mutex=1；
  • 缓冲区空时消费者要等，满时生产者要等 → 同步信号量 empty=N、full=0；
  • 生产者：P(empty); P(mutex); 放入; V(mutex); V(full);
  • 消费者：P(full); P(mutex); 取出; V(mutex); V(empty);

这里 P 的顺序很关键：如果先 P(mutex) 再 P(empty)，生产者在缓冲区满时会持有 mutex 睡眠，消费者无法进入取数据，可能死锁。一般原则是先 P 同步信号量，再 P 互斥信号量；V 的顺序通常相反，但要看具体资源。

十、易错点

  • “单标志法满足空闲让进”：turn 固定给另一方时，即使临界区空闲，当前进程也不能进。
  • “双标志先检查能保证互斥”：检查和设置不是原子操作，双方可能同时通过检查。
  • “Peterson 满足让权等待”：它仍是忙等；满足互斥、进展和有限等待。
  • “P/V 只是加减计数”：P 可能阻塞、V 可能唤醒，还涉及等待队列和原子性。
  • “管程的条件变量就是锁”：锁保证互斥；条件变量用于等待条件，wait 会释放管程，signal 不计数。
  • “信号量初值随便设”：互斥量通常 1，同步量看初始资源/前驱条件；初值错会导致死锁或互斥失效。

把这一节收成一句话：互斥看“能不能同时进”，同步看“谁先谁后”；软件/硬件方法多忙等，信号量/管程通过阻塞等待把 CPU 让出来。
