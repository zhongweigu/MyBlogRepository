程序只是磁盘上的指令和数据，真正“跑起来”之后，内核要同时维护它的地址空间、寄存器现场、状态、优先级、打开的文件和等待的事件。把这些东西打包起来，才得到一个进程。理解进程，关键是抓住两条线：它由什么组成，以及它在什么状态下、下一步能去哪里。

一、程序与进程：静态与动态

程序是存放在磁盘上的指令和数据集合，是静态的；进程是程序的一次执行实例，是动态的，有创建、就绪、运行、阻塞、终止的生命周期。同一个程序运行两次，会得到两个不同的进程：它们可以有不同的 PID、不同的寄存器和不同的地址空间。

进程和程序不是一一对应：一个程序可以对应多个进程；一个进程也可以通过 exec 换成另一个程序。程序本身不占 CPU，进程才参与调度。

对比程序进程
存在形式静态文件/指令集合运行中的执行实例
生命周期长期存放在磁盘创建到终止，有状态变化
资源不拥有运行资源拥有地址空间、PCB、打开文件等
并发性本身不能并发执行多个进程可以并发/并行

二、进程实体与 PCB

教材通常把进程实体（进程映像）概括为三部分：代码段、数据段、PCB。其中 PCB（Process Control Block，进程控制块）是内核为进程建立的数据结构，也是进程存在的唯一标志：内核靠 PCB 才知道“这个进程是谁、现在什么状态、现场在哪、占了哪些资源”。

PCB 字段内容作用
进程标识符外部标识符（用户可见的名字/编号）、内部标识符（内核用的唯一 PID）区分进程，方便用户访问和内核管理
处理机状态通用寄存器、PC、PSW、用户栈指针/内核栈指针进程被切换出去后，下次能恢复现场继续执行
进程调度信息状态、优先级、等待事件、已等待/已执行时间等调度器据此选进程、判断是否阻塞/唤醒
进程控制信息程序和数据地址、页表起始地址、同步通信机制、资源清单、链接指针定位地址空间、管理资源和队列

PCB 放在内核区，用户程序不能直接读写。进程切换时，内核把当前寄存器现场写回旧 PCB，再从新 PCB 恢复现场；这也是“进程切换比线程切换贵”的原因之一。

三、进程映像：虚拟地址空间里有什么

进程看到的不是物理内存，而是一段虚拟地址空间。操作系统给每个进程造出“我独占一大片内存”的假象，实际由页表把虚拟页映射到物理页框；不同进程可以复用同一份物理内存，但彼此不可见。

从低地址到高地址，典型布局是：

  • 只读代码段（.init/.text/.rodata）：程序的指令和只读常量，可被多个进程共享；
  • 读写数据段（.data/.bss）：全局变量、静态变量；
  • 堆：malloc/new 动态分配，向高地址增长；
  • 共享库映射区：动态链接库（DLL/.so）映射进来，多个进程共享同一份物理副本；
  • 用户栈：函数调用、局部变量、返回地址，从用户空间高地址向低地址增长；
  • 内核空间：内核代码/数据映射在高地址，用户态不可访问；PCB 等内核数据结构也在这里。

“栈向低地址、堆向高地址”不是任意规定：栈需要可预测地向调用链深处扩展，堆需要向空闲区扩展；两者相向生长，中间留出共享库和未使用区。进程的 PCB 不在用户栈里，而在内核区。

四、五种状态与合法转换

进程最基本的状态是三种：就绪（资源够，只差 CPU）、执行（占用 CPU）、阻塞（等待 I/O 或事件，主动让出 CPU）。再加上创建和终止，就是五状态模型。

转换触发说明
创建 → 就绪PCB/资源初始化完成，插入就绪队列进程已具备运行条件
就绪 → 执行调度器选中分配 CPU，恢复现场
执行 → 就绪时间片用完、被更高优先级抢占被动让出 CPU，仍可运行
执行 → 阻塞请求 I/O、等待事件、block 原语主动行为，进入等待队列
阻塞 → 就绪I/O 完成、事件发生、wakeup被唤醒，进入就绪队列
执行 → 终止正常结束或异常终止回收资源与 PCB

两条“不存在的边”要记牢：阻塞不能直接变执行（必须先就绪、再被调度）；就绪不能主动变阻塞（没有 CPU 就无法发起阻塞操作）。

五、创建、终止、阻塞与唤醒

1. 创建

创建进程通常包括：分配唯一 PID、申请 PCB、分配地址空间和资源、初始化 PCB（状态、PC、栈指针、优先级等）、插入就绪队列。父进程创建子进程时，子进程可以继承父进程的打开文件、缓冲区等资源；也可以加载新程序。

类 Unix 的 fork 让子进程成为父进程的副本（现代实现常用写时复制），exec 再把子进程替换成新程序。题目没有明确说 fork/exec 时，不要自行套用“子进程复制父进程全部变量”的细节，按题目给出的语义做。

2. 终止

进程正常结束或异常终止后，内核回收它的内存、打开文件、设备等资源，撤销 PCB，并处理父子关系。教材口径常强调：撤销父进程时通常要同时撤销其子进程；实际系统还有孤儿进程被 init/托孤、僵尸进程等待父进程回收等机制，考试按题目口径。

3. 阻塞与唤醒

阻塞是进程主动调用 block 原语：保存现场，把 PCB 状态改为阻塞，插入相应事件的等待队列，然后调度其他进程。唤醒是等待的事件发生时，由内核（或另一个进程）调用 wakeup：把进程从等待队列移到就绪队列，状态改为就绪；它还要等调度器选中才能运行。

所以 block 是“自己把自己挂起”，wakeup 是“别人/事件把它叫醒”。一个进程不能阻塞另一个进程；它只能通过 V 操作、消息到达等方式间接唤醒。

六、进程通信的三种方式

方式做法优点边界/代价
共享存储通信进程映射同一块共享内存，直接读写最快，适合大量数据必须自己同步互斥，否则数据竞争
消息传递以格式化消息为单位，send/receive适合分布式、天然按消息同步拷贝/系统调用开销；有阻塞/非阻塞、缓冲/无缓冲之分
管道连接读进程和写进程的共享文件（pipe）简单，按字节流半双工、通常有界；空时读阻塞、满时写阻塞

管道同一时刻只能有一个方向传输；如果要双向，通常用两个管道。管道是有界缓冲区：写满后写进程阻塞，读空后读进程阻塞，这本身就是一种同步。

七、进程切换与模式切换

进程切换要保存旧进程的现场（寄存器、PC、PSW、SP、页表基址等）到 PCB，更新队列/状态；再恢复新进程的现场，切换地址空间（页表基址、TLB 等）。模式切换只是 CPU 从用户态进内核态，仍然可能是同一个进程。

对比模式切换进程切换
改变CPU 特权级当前运行的进程
地址空间不换通常换页表，可能刷新 TLB
触发中断/异常/陷入/返回调度器决定换进程
开销保存/恢复部分现场完整上下文 + 地址空间 + 调度开销

一次系统调用可能只发生模式切换；只有内核决定“换另一个进程”时，才是进程切换。把这两件事分开，后面线程切换、调度开销才不会混。

八、进程映像如何落到物理内存

“每个进程以为自己独占整个虚拟内存”只是地址空间抽象：CPU 产生的是虚拟地址，真正访问主存前要经过 MMU 和页表转换成物理地址。所有进程的虚拟地址空间里都有一段内核区，但这些内核区通常映射到同一份物理内核，不是每个进程复制一份内核。

1. 虚拟地址怎么切

设页大小 4KB（2¹²），32 位虚拟地址就切成 VPN（页号） | offset（页内偏移）：低 12 位是 offset，高位是 VPN。页大小必须是 2 的幂，页框也按页对齐，所以：

VPN    = VA >> 12
offset = VA & 0x0FFF
PA     = (PFN << 12) | offset

例如 VA = 0x00403ABC：VPN = 0x00403，offset = 0xABC；若页表项给出 PFN = 0x1A2，则 PA = 0x1A2ABC。转换只替换“页号”，页内偏移原样保留，这就是“按页对齐”的含义。

2. 一次访问的完整路径

  1. CPU 发出虚拟地址：指令取指、load/store 都先产生 VA。
  2. MMU 查 TLB：TLB 是页表项的高速缓存，命中就直接得到 PFN；未命中进入页表遍历。
  3. 页表遍历：MMU 用页表基址寄存器（PTBR/CR3）找到页表，按 VPN 逐级查 PTE；多级页表每一级都取出下一级页表的物理基址。
  4. PTE 有效且权限允许：取出 PFN，与 offset 拼成 PA，访问 Cache/主存；同时可能更新 TLB 和 PTE 的 Accessed 位。
  5. PTE 无效或权限不符：MMU 触发缺页异常/保护异常，CPU 切换到内核态，跳到缺页处理程序。

3. 缺页时操作系统做什么

  1. 内核根据 VA 找到该进程的 VMA（已映射区域），判断地址是否合法、权限是否匹配；不合法就发送 SIGSEGV，进程终止。
  2. 合法但页不在主存：分配一个空闲页框；若没有空闲页框，按页面置换算法选一个受害者页，若脏页先写回磁盘。
  3. 从磁盘/交换区把所需页读入页框；更新 PTE 的 present 位和 PFN；必要时更新页表上级项、刷新 TLB。
  4. 返回用户态，重新执行刚才那条指令；这次 TLB/页表命中，访问完成。

这里软硬件分工很清楚：地址翻译、TLB 查找、触发异常由 MMU/CPU 硬件完成；缺页处理、页面置换、磁盘 I/O、页表更新由操作系统软件完成。TLB 未命中不一定是缺页，可能只是缓存没命中，硬件走页表就能解决。

4. 主存与外存的对换

虚拟存储把主存当磁盘的缓存：页表项的 present 位表示页是否在内存；不在时 PTE 里存交换区位置（或由操作系统另建结构记录）。缺页处理把页换入，内存紧张时把不常用页换出。换出脏页要写回，换出干净页可直接丢弃。页面置换和 medium-term scheduling（进程级挂起/激活）是不同层次：前者换页，后者换整个进程映像。

5. 内核区为什么是共享的

每个进程的页表都把高地址的内核区映射到同一组物理页，因此进入内核后不需要“换一套内核代码”。页表项用 U/S 位标记内核页为 supervisor-only，用户态访问会触发保护异常。注意这是通用模型；x86 的 KPTI 等机制会在用户态切换页表以隔离内核映射，但“内核只有一份”这个事实不变。

问题答案
页内偏移会变吗？不变；VA 和 PA 的 offset 相同，只有页号被替换。
页表本身放在哪？主存中，由 PTBR 指向；多级页表本身也按页对齐。
TLB 命中还要查页表吗？不需要；TLB 就是页表项的缓存。
缺页一定要读磁盘吗？不一定；可能是页表未建立、权限错误或页在交换区，但典型的“不在主存”需要 I/O。
每个进程有独立内核吗？没有；内核代码/数据共享，页表把内核区映射到同一物理内核。

九、挂起、激活与复杂状态模型

三状态/五状态模型假设所有进程都在主存。实际系统内存不够时，会把某些进程的整个进程映像换到外存，这就是“挂起”。挂起不是阻塞：阻塞是等事件，挂起是“暂时不在主存”。一个进程可以既阻塞又被挂起。

状态在不在主存能不能运行说明
就绪在只差 CPU活动就绪
阻塞在不能，等事件活动阻塞
就绪挂起不在激活并调度后能运行映像在外存，事件已满足
阻塞挂起不在不能，等事件映像在外存且仍在等事件

复杂模型通常写成七状态：创建、就绪、运行、阻塞、就绪挂起、阻塞挂起、终止。关键转换：

  • 就绪 → 就绪挂起：内存紧张，换出；
  • 阻塞 → 阻塞挂起：阻塞进程被换出；
  • 就绪挂起 → 就绪：激活（换入），等调度；
  • 阻塞挂起 → 阻塞：先激活但事件还没发生；
  • 阻塞挂起 → 就绪挂起：事件在挂起期间发生，仍在外存，等激活；
  • 运行 → 就绪/阻塞/终止，和简单模型一致；运行态也可能因换出直接进入挂起态（具体系统而定）。

“激活”只把映像换回主存，不等于立刻运行；换入后还要看它是就绪还是仍阻塞。中级调度负责在内存和外存之间挑选进程换入/换出，目标是控制多道程度、缓解内存压力；换得太频繁会抖动。

模型状态适用
三状态就绪、运行、阻塞只考虑 CPU 调度，忽略创建/终止和换出
五状态新建、就绪、运行、阻塞、终止一般 OS 原理题
七状态五状态 + 就绪挂起、阻塞挂起引入虚拟存储/对换、中级调度

十、fork 与父进程撤销

fork() 创建一个子进程。父进程和子进程从同一条 fork 之后继续执行，但返回值不同：子进程得到 0，父进程得到子进程 PID，失败返回 -1。

pid_t pid = fork();
if (pid == 0) {
    /* 子进程 */
} else if (pid > 0) {
    /* 父进程，pid 是子进程号 */
} else {
    /* fork 失败 */
}
维度相同/继承不同/独立
代码与数据逻辑上复制父进程的地址空间写时复制后各自有私有物理页；修改互不影响
打开文件继承文件描述符表，共享同一个打开文件描述文件偏移量共享；各自关闭不影响对方
身份UID/GID、环境变量、当前目录、信号处理方式PID、PPID、返回值、未决信号、资源统计
执行流从 fork 返回处继续父子并发执行；谁先跑由调度决定

父子生命周期：父进程可以 wait/waitpid 等子进程结束并回收退出状态；子进程先结束而父进程没 wait，会留下僵尸进程（PCB/退出状态还在）；父进程先结束，子进程成为孤儿进程，由 init/systemd 或 subreaper 收养。子进程可以 exec 换成新程序，地址空间被替换，但 PID 和部分属性保留。

“撤销父进程时子进程怎么办”在具体实现中不同：经典教材口径常写“撤销父进程要同时撤销其所有子进程”；Unix/Linux 实际是把孤儿进程重新托孤给 init，不一定杀死；Windows 可用 Job Object 把进程组一起终止。考试按题目/教材口径，工程实现按平台语义，不要把两者混成绝对结论。

十一、易错点与收束

  • “程序就是进程”：程序是静态的；进程是执行实例，有 PCB、状态和生命周期。
  • “阻塞可以直接变执行”：阻塞被唤醒后先进就绪队列，必须再被调度。
  • “就绪可以主动变阻塞”：只有正在执行的进程才能主动请求 I/O 而阻塞。
  • “PCB 在用户空间”：PCB 是内核数据结构，放在内核区。
  • “进程切换只保存 PC”：还要保存通用寄存器、PSW、SP、页表基址等，并更新 PCB/队列。
  • “父进程终止，子进程一定自动终止”：取决于系统策略；按题目口径判断，不要绝对化。

把这一节收成一条链：程序 + 数据 + PCB → 进程映像 → 五状态转换 → 创建/阻塞/唤醒/终止 → 通信 → 切换。后面线程、调度、同步和死锁，都是在这条链上继续加问题。
