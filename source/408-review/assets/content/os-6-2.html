三种 I/O 控制方式——程序查询、中断、DMA——解决的是同一个矛盾：CPU 很快，设备很慢，CPU 不应该把时间浪费在“等设备”上。三者的区别不在用户接口，而在谁发起传送、谁搬数据、CPU 何时介入。

从程序查询到中断，是把“等”从 CPU 手里拿走；从中断到 DMA，是把“搬”也从 CPU 手里拿走。理解这条演化线，比背三个定义重要。

二、程序查询方式

程序查询（程序直接控制）的核心是：CPU 不断读取控制器的状态寄存器，检查设备是否就绪；只有就绪时才传送一个单位的数据，然后修改地址/计数器，继续下一次。

  1. CPU 预置数据缓冲区地址、传送长度、方向等参数。
  2. 向控制器发“启动”命令，设备开始工作。
  3. CPU 读状态寄存器，检查“忙/就绪/错误”。
  4. 未就绪则回到第 3 步；就绪则从数据寄存器读/写一个单位。
  5. 修改内存地址和计数器，判断是否传完；未完回到第 3 步。

这种方式实现简单，不需要中断机构，但 CPU 和设备完全串行：设备慢，CPU 就陪着空转。所谓“定时查询”只是把“一直查”改成“隔一段时间查一次”，并没有让 CPU 在等待期间去做别的进程，本质仍是查询。

考试常问“程序查询方式下 CPU 与设备是否并行”。答案是：传送期间 CPU 被占用，不能并行执行其他程序；设备准备数据时 CPU 也在查询，不能算有效并行。

三、中断控制方式

中断方式把“等待”从 CPU 的循环里拿出来：CPU 启动设备后可以继续执行当前进程；设备完成一个单位后向 CPU 发中断请求，CPU 响应后进入中断服务程序，在 ISR 中完成数据传送或缓冲区处理。

  1. CPU 预置参数并启动设备，然后继续执行其他程序。
  2. 设备完成一个单位（一个字符/字）后，控制器置位状态并向 CPU 发中断请求。
  3. CPU 在一条指令结束后检查中断，满足条件则响应：关中断、保存断点和 PSW、转入内核态、按中断向量找到 ISR。
  4. ISR 读取数据寄存器，把数据送入内核缓冲区；必要时唤醒等待进程。
  5. 恢复现场，返回被中断的程序；若传送未完成，设备继续工作、再次中断。

中断方式让 CPU 和设备在设备工作期间并行，但每传送一个单位都要打断一次 CPU。对键盘这种低速字符设备很合适；对磁盘这种高速块设备，如果每字节都中断，CPU 会被中断淹没，所以要用 DMA。

还要区分两个“并行”：CPU 执行与设备工作可以并行；但 CPU 进入 ISR 后，传送数据的动作仍由 CPU 完成，ISR 执行期间不能同时执行用户程序。中断不等于进程切换，也不等于“CPU 把数据搬完了”。

四、DMA 控制方式

DMA（Direct Memory Access）把“搬数据”的工作交给 DMA 控制器。CPU 只做三件事：初始化、启动、处理完成中断；数据块在设备与主存之间直接传送，不需要 CPU 逐字搬运。

DMA 控制器通常包含：

  • 内存地址寄存器 MAR：数据在主存中的起始地址，传送过程中递增。
  • 数据计数器 DC：还要传送多少个字/字节，减到 0 表示完成。
  • 命令/状态寄存器 CR：方向（读/写）、是否启动、是否完成/出错。
  • 数据缓冲寄存器：暂存总线上的一个字。

典型流程：

  1. CPU 把主存起始地址、传送长度、方向写入 DMA 控制器，启动设备。
  2. DMA 控制器向 CPU 申请总线使用权；获得后直接在设备与主存之间传送数据。
  3. 每传送一个字，MAR 加一、DC 减一；DC 为 0 时置完成标志。
  4. DMA 控制器向 CPU 发中断，CPU 进入 ISR 做校验、唤醒进程等收尾工作。

DMA 与中断的区别可以压成一句话：中断是“每传一个单位打断一次”，DMA 是“传完一整块才打断一次”。DMA 传送期间 CPU 仍可执行程序，但 DMA 与 CPU 会竞争总线/内存周期，常见“周期挪用/总线窃取”就是把 CPU 不用的总线周期让给 DMA。

比较项程序查询中断DMA
CPU 等待忙等，浪费大设备工作时可执行其他程序块传送期间 CPU 基本不参与

硬件成本最低需要中断机构需要 DMA 控制器，成本最高
适用场景极低速、简单控制字符设备、低速随机事件磁盘、网卡等高速块设备

选择不是“越高级越好”，而是看传送单位、数据率、CPU 介入成本。一个设备用哪种方式，通常由设备类型和控制器能力决定；操作系统中的驱动程序负责按设备能力选择并配置。硬件层面的详细时序、DMA 总线周期和中断隐指令，见计算机组成原理的 三种 I/O 方式与 DMA 与 中断完整流程；本页只保留 OS 侧必须掌握的判断。
