三种 ARQ 都可以从“窗口”理解：发送窗口 W_T 是发送方允许“已发出但还没被确认”的帧集合；接收窗口 W_R 是接收方允许接收的帧集合。窗口的起点随着 ACK 前移，这就是“滑动窗口”。

n 位序号能表示 0～2^n−1 个编号。窗口不能无限大，否则新旧帧会用到同一个序号，接收方分不清“新帧”和“重传的旧帧”。

一、先看窗口：三种 ARQ 总表

协议发送窗口 W_T接收窗口 W_R序号核心规则
停止等待111 bit（0/1）发一帧，等一个 ACK
GBN>11n bit累积确认，出错回退
SR>1>1n bit逐帧确认，缓存乱序，只重传出错帧

核心约束：W_T + W_R ≤ 2^n。不同协议只是在这个约束下取不同的窗口。

二、停止等待

窗口：W_T=1，W_R=1。发送方发一帧后必须停下，等收到 ACK 才能发下一帧；接收方一次只收一帧。

编号：只需 1 bit 序号（0/1）。因为发送方同一时刻只有一帧在途，接收方只需区分“新帧”和“上一帧的重复”。

  • 数据帧出错或丢失：发送方为数据帧设置计时器；长时间没收到确认，就自动重传。
  • 确认帧出错或丢失：发送方同样超时重传；接收方收到重复帧后丢弃重复帧，并重新发送 ACK，不会重复交付给上层。

窗口推进：初始发送窗口 [0]、接收窗口 [0]；收到 ACK0 后，两者都推进到 [1]。每收一个 ACK，窗口向前 1 格。

停止等待简单，但没有流水线：RTT 大、速率高时，信道大部分时间在等 ACK，利用率低。

三、后退 N 帧（GBN）

窗口：W_R=1，W_T>1。发送方可以连续发送窗口内的多个帧；接收方只按序接收，乱序帧直接丢弃。

编号：n bit 序号，W_T ≤ 2^n − 1。留一个序号不用，接收方才能区分“新帧”和“重传的旧帧”。

  • 发送窗口内的帧可以连续发送，不必每帧都停；
  • 接收方只按序收，收到乱序帧就丢弃；
  • 累积确认：接收方连续收到后，只需返回最大连续帧的 ACK。例如 ACK1 表示 0、1 都收到；
  • 为防止 ACK 丢失，接收方可以重复发送最近一次成功的 ACK，催促发送方继续；
  • 通常只为最早未确认帧设置一个计时器；它超时，就重传该帧及其之后所有已发送但未确认的帧。

窗口推进：发送窗口 [0,1,2,3]，收到 ACK1 后，累积确认 0、1，窗口起点直接跳到 2，变成 [2,3,4,5]；接收窗口始终只跟着“下一个期望帧”走。

GBN 的优点是接收端简单、不需要缓存乱序帧；缺点是出错时可能重传一大段，浪费带宽。

四、选择重传（SR）

窗口：W_T>1，W_R>1。接收方可以接收并缓存“失序但正确到达、且落在接收窗口内”的帧。

编号与约束：

  • n bit 序号；
  • W_T + W_R ≤ 2^n，且 W_R ≤ W_T；
  • 常取 W_T = W_R = 2^(n−1)，两边各占序号空间一半。
  • 只重传出错或超时的数据帧，不重传它后面的正确帧；
  • 接收方必须有和接收窗口一样大的缓冲区，暂存乱序帧；
  • 每个未确认帧有独立的计时器；
  • 如果收到错帧，可以立即返回 NAK，让发送方马上重传，不必等到超时。

窗口推进：初始发送/接收窗口都是 [0,1,2,3]；0、1 被确认，2 丢失，3 被缓存。接收窗口仍覆盖 2、3，但不交付 3；2 到达后，接收方按序交付 2、3，窗口一起向前推进。

六、窗口大小总结与易错点

记住一条主线：所有 ARQ 都受 W_T + W_R ≤ 2^n 约束。

协议W_TW_R由总约束得到
停止等待111+1=2=2^1，n=1
GBN≤2^n−11W_T+1≤2^n
SR≤2^n−W_R≤W_T常取 W_T=W_R=2^(n−1)
  • “GBN 接收窗口等于发送窗口”：错；GBN 的 W_R 始终为 1。
  • “SR 不需要缓存”：错；SR 必须缓存乱序帧，缓冲区至少等于 W_R。
  • “窗口越大越好”：错；受 W_T+W_R≤2^n 限制，过大会新旧序号混淆。
  • “停等不需要序号”：错；至少 1 bit 用来识别重复帧。
  • “GBN 的累积确认表示后面都对”：错；只表示到该序号为止都收到，后面仍可能丢。

收束：停等用 1+1 换简单；GBN 用 W_R=1 换接收端简单、用回退换秩序；SR 用缓存和独立计时器换效率。
