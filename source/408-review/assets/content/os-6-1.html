I/O 管理要回答三个层次的问题：设备怎样被 CPU 看见（控制器、端口、寄存器），操作系统怎样把请求送给设备（I/O 软件层次、驱动程序），以及多个进程怎样共享有限的设备（分配、缓冲、SPOOLing、调度）。这一页先把“设备—控制器—端口—OS 层次”这条硬件与软件的接缝讲清楚，后面的控制方式、中断和磁盘调度才有落点。

一、I/O 管理的目标

操作系统管理 I/O，不是为了“替用户按一下键盘”，而是要在速度差异极大、类型极多、共享冲突的设备之间建立一层可控的抽象。

  • 设备独立性：用户用逻辑设备名和统一接口（open/read/write）访问设备，不必知道具体控制器、端口和寄存器。
  • 提高利用率：让 CPU 与外设尽量并行，减少 CPU 空等；用缓冲、DMA、中断等手段解耦速度。
  • 共享与保护：多个进程竞争设备时，决定谁先使用、能否共享、如何避免死锁和越权。
  • 统一错误处理：设备出错、超时、断线时，由 OS 统一重试、报告或隔离，而不是让每个程序自己处理硬件细节。

这里要区分两个视角：用户视角只看到逻辑设备名和系统调用；内核视角要把它翻译成设备号、控制器命令、端口读写和中断处理。I/O 管理的全部复杂性，就来自这两层视角之间的翻译。

二、I/O 系统的五个层次

408 常用的 I/O 软件层次从外到内是：用户层软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。请求向下逐层具体化，完成/错误向上逐层返回。

层次主要职责典型内容
用户层软件发出 I/O 请求，使用库函数/系统调用printf、scanf、read、write、图形库
设备独立性软件统一接口、设备分配、缓冲、保护、错误处理逻辑设备名、LUT、缓冲区管理、SPOOLing
设备驱动程序把抽象请求翻译成设备命令，启动设备，处理完成读写控制器寄存器、设置参数、等待/中断
中断处理程序响应设备中断，保存现场，完成中断服务ISR、中断向量、中断屏蔽、唤醒进程
硬件执行实际的数据传送设备、控制器、端口、总线、DMA

这张层次图最重要的考点不是背五层名字，而是判断一件事该由哪一层做：

  • “把逻辑设备名翻译成物理设备名”属于设备独立性软件（LUT）。
  • “把逻辑块号翻译成柱面号/磁头号/扇区号”属于设备驱动程序。
  • “保存断点、切换内核态、查中断向量”属于中断响应/中断处理，不是用户层。
  • “把设备控制器收到的字节搬进内核缓冲区”通常由中断服务程序或 DMA 完成，具体看控制方式。

三、设备、控制器与设备寄存器

外设本身（键盘、磁盘、打印机）通常不能直接挂到系统总线上，它要通过设备控制器（I/O 接口）与 CPU 交互。控制器是 CPU 和设备之间的“翻译 + 缓冲 + 状态”部件。

  • 数据寄存器：暂存待传送的数据；CPU 读/写它，控制器再与设备交换。
  • 状态寄存器：至少包含“忙/闲”“就绪”“错误”等状态，CPU 查询或中断时读它。
  • 控制寄存器：CPU 写入命令（读/写、启动、复位）和参数（地址、长度、方向）。

因此，“CPU 访问设备”在硬件上通常不是直接访问设备内部，而是读写控制器上的寄存器。控制器再根据命令去驱动设备，设备完成后把状态写回控制器，必要时发中断。

设备可以按不同维度分类，考法中常见的三组是：

分类维度类型特点/例子
传输单位块设备 / 字符设备块设备以数据块为单位、可寻址（磁盘）；字符设备以字节/字符流为单位（键盘、串口）
共享属性独占设备 / 共享设备 / 虚拟设备打印机通常独占；磁盘可共享；SPOOLing 把独占设备虚拟成共享设备
所属层次输入 / 输出 / 存储 / 网络设备键盘、显示器、磁盘、网卡；网络设备常通过套接字接口访问

设备 ≠ 控制器 ≠ 设备寄存器：设备是机械/物理部件，控制器是接口电路，寄存器是 CPU 能读写的窗口。考试说“设备状态”时，通常指控制器状态寄存器中的状态位，而不是设备内部机械位置。

四、I/O 端口与两种编址

I/O 端口是 CPU 访问设备控制器寄存器的地址。每个控制器可能有一组端口，分别对应数据、状态、控制寄存器。常见两种编址：

方式做法优点缺点
独立编址（I/O 空间）I/O 端口有独立地址空间，用专门的 IN/OUT 指令访问不占主存地址空间，指令能区分访存和 I/O需要专门 I/O 指令，编程稍复杂
统一编址（内存映射 I/O）把控制器寄存器映射到主存地址空间，用普通访存指令访问可用普通 load/store，寻址方式丰富占用主存地址空间，需划出保留区

无论哪种方式，CPU 看到的都是“某个地址上的寄存器”，区别只在指令和地址空间。不要把“端口”理解成网络端口（port），也不要把“统一编址”理解成“设备和内存共用同一块物理存储”。

五、一次 I/O 请求经过哪些层

以用户程序调用 read(fd, buf, n) 为例，请求的大致路径是：

  1. 用户层库函数把参数整理好，执行系统调用陷入内核。
  2. 设备独立性软件根据 fd 找到打开文件/设备，检查权限和参数，决定使用缓冲还是直接传送。
  3. 设备驱动程序把“读第几块/第几个字节”翻译成设备命令，写控制器寄存器，启动设备。
  4. 设备控制器与设备完成数据传送；完成后通过状态寄存器/中断/DMA 报告。
  5. 中断处理程序（或 DMA 完成处理）确认完成，唤醒等待进程；数据可能先进入内核缓冲区。
  6. 系统调用返回，用户层从缓冲区复制数据，继续执行。

这条路径在后面的“键盘输入”“磁盘读块”两个完整流程中会逐段展开。这里先记住：用户只提交逻辑请求，驱动程序才接触硬件，中断处理程序负责完成通知。

六、易错点与收束

  • “用户程序直接读写设备寄存器”：用户程序通过系统调用/库函数间接访问；直接访问硬件通常需要内核态或映射权限。
  • “设备独立性就是设备无关”：不是没有设备差异，而是把差异屏蔽在驱动/独立性软件之下，向上提供统一接口。
  • “控制器就是设备”：控制器是接口，设备是执行部件；一个控制器可能连接多个同类设备。
  • “I/O 端口就是网络端口”：这里是 CPU 访问控制器寄存器的地址，不是 TCP/UDP 端口。
  • “层次越高越靠近硬件”：恰好相反：用户层最高，硬件最低；请求向下翻译，完成向上返回。

收束成一句话：I/O 管理是在“用户逻辑请求”和“控制器寄存器时序”之间做翻译、缓冲、分配和保护。下一节把这层翻译具体到程序查询、中断和 DMA 三种控制方式。
