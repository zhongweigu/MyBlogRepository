生产者-消费者是 PV 题最基本的模型：一个大小为 N 的缓冲区，生产者放、消费者取；缓冲区不满才能放，不空才能取，而且缓冲区是临界资源。它同时包含同步（先生产后消费）和互斥（不能同时改缓冲区）。

一、问题与约束

一组生产者进程和一组消费者进程共享一个初始为空、大小为 N 的缓冲区：

  • 缓冲区不满时，生产者才能放入；否则阻塞；
  • 缓冲区不空时，消费者才能取出；否则等待；
  • 缓冲区是临界资源，放入/取出必须互斥。

把约束拆成两句话：“有没有空位/产品”是同步（状态），“能不能同时改缓冲区”是互斥。这两件事要用不同的信号量，不能用一个 mutex 全包。

二、先解决“能不能做”

如果没有同步，生产者可能覆盖未取走的数据，消费者可能读取空缓冲区。设：

semaphore empty = N;   // 空位数
semaphore full  = 0;   // 产品数

producer() {
    while (1) {
        生产一个产品;
        P(empty);       // 等一个空位
        放入缓冲区;
        V(full);        // 产品数 +1
    }
}

consumer() {
    while (1) {
        P(full);        // 等一个产品
        从缓冲区取产品;
        V(empty);       // 空位数 +1
        消费;
    }
}

empty 和 full 不是“锁”，它们记录系统状态：现在有没有空位/产品。P 是“消耗一个状态”，V 是“产生一个状态”。

三、再解决“能不能同时做”

上面的代码只保证“有空位/有产品”，不保证多个生产者/消费者同时改缓冲区时的互斥。例如两个生产者同时拿到空位，可能同时写同一个下标。加一把锁：

semaphore mutex = 1;   // 保护缓冲区

放入/取出的具体操作要放在 P(mutex) 和 V(mutex) 之间。注意：P(empty)/P(full) 要放在 P(mutex) 之前，原因见下一节。

四、完整代码

#define N 8
semaphore mutex = 1;
semaphore empty = N;
semaphore full  = 0;

int buffer[N];
int in = 0, out = 0;

producer() {
    while (1) {
        item = produce();
        P(empty);           // 1. 等空位
        P(mutex);           // 2. 进缓冲区
        buffer[in] = item;
        in = (in + 1) % N;
        V(mutex);           // 3. 释放缓冲区
        V(full);            // 4. 通知消费者：有产品了
    }
}

consumer() {
    while (1) {
        P(full);            // 1. 等产品
        P(mutex);           // 2. 进缓冲区
        item = buffer[out];
        out = (out + 1) % N;
        V(mutex);           // 3. 释放缓冲区
        V(empty);           // 4. 通知生产者：有空位了
        consume(item);
    }
}

in/out 是共享下标，必须在 mutex 内更新；如果只把数组元素操作放进锁，而把 in++ 留在锁外，仍然会丢更新。

五、P/V 顺序：最容易错的地方

1. 为什么先 P(empty) 再 P(mutex)

假设缓冲区已满（empty=0），生产者先执行 P(mutex) 拿到锁，再执行 P(empty) 被阻塞。此时它持有 mutex 睡眠；消费者想取产品，必须先 P(mutex)，但锁在生产者手里，消费者也进不去。双方互相等待：生产者等 empty，消费者等 mutex，形成死锁。

先 P(empty) 时，生产者在进入临界区之前就因没有空位而阻塞，不会占着 mutex；消费者可以正常进入、取走产品、V(empty)，把生产者唤醒。

2. V 的顺序

标准写法是 V(mutex) 后再 V(full/empty)：先释放缓冲区，再通知对方。反过来通常不会死锁，但被唤醒的消费者可能马上又阻塞在 mutex 上，多一次切换；逻辑上也不如“先出临界区再通知”清晰。

七、多生产者/多消费者与收束

多生产者/多消费者不需要新增信号量：每个生产者/消费者都是同一套代码的循环实例，共享 empty/full/mutex。真正要保证的是：

  • 每个生产者都先 P(empty) 再 P(mutex)，每个消费者都先 P(full) 再 P(mutex)；
  • 缓冲区下标 in/out 的更新在 mutex 内；
  • V 的顺序与 P 对称，且每个分支都释放。

生产者-消费者的本质是：empty/full 管“能不能做”，mutex 管“能不能同时做”。把这两层分开，代码就不会乱。
