操作系统是覆盖在裸机上的第一层软件，也是所有程序运行时共同依赖的环境。它的历史不是“功能越堆越多”，而是围绕三对矛盾展开：CPU 快、外设慢，机器快、人慢，以及多道程序之间互相争用资源。把这三对矛盾看清楚，单道/多道、批处理/分时/实时的区别就不会混。

一、操作系统到底在做什么

没有操作系统时，程序要自己面对裸机：把磁道号、扇区号、设备状态寄存器、中断向量都写进代码，换一台机器就可能重写。操作系统的第一件事，是把硬件抽象成一组可编程的对象：

  • 把 CPU 抽象成进程/线程，程序不必关心“下一时刻 CPU 会不会被别的程序抢走”；
  • 把主存抽象成地址空间，程序不必关心自己实际落在哪几个物理页框；
  • 把磁盘抽象成文件与目录，程序不必直接操作盘面；
  • 把外设抽象成设备接口，用统一的 read/write/ioctl 访问不同设备。

所以操作系统有两个经典视角。第一个是资源管理器：CPU、内存、文件、设备都是资源，OS 负责分配、回收、保护和调度。第二个是虚拟机：OS 在裸机之上再建一层“更好用的机器”，让用户感觉自己独占一台计算机。两个视角说的是同一件事的两面：抽象让程序好用，管理让资源有序。

操作系统的目标也不止“方便”。它还要提高资源利用率、提高系统吞吐量、保证公平性和响应性、提供保护与安全，并让系统容易扩展。这些目标经常互相冲突：吞吐量大的策略可能响应慢，公平的策略可能开销大。后面每一种操作系统类型，本质上都是在这些目标之间选了一组不同的优先级。

二、人工操作方式：没有操作系统的年代

早期计算机没有操作系统，程序员直接把程序和数据表示成纸带、卡片或插线板。上机流程大致是：预约机器 → 手工装入纸带/卡片 → 设置开关 → 启动 → 在控制台前观察 → 取走结果 → 下一个人再来。整个过程用户独占全机，机器在一段时间内只服务一个人。

这种方式的问题不只是“麻烦”，而是CPU 的大量时间在等人。人装纸带、拔插头、记录结果的速度以秒计，而 CPU 执行一条指令以纳秒计，二者相差几个数量级。只要人还在操作，CPU 就只能空转。于是出现了第一对核心矛盾：人机速度矛盾。

人工操作方式不是一种“操作系统类型”，而是操作系统出现之前的状态。它没有资源管理，也没有程序之间的切换；后来的一切发展，都是想办法把“人”从每道作业的执行路径里拿出去。

三、脱机 I/O：把慢设备从主机旁边移开

“脱机”是相对主机而言的：输入/输出操作不直接受主机控制，而由一台专门的外围计算机控制。典型做法是：

  • 脱机输入：外围机控制输入设备，把纸带/卡片上的程序和数据先写到磁带；主机需要时，再从磁带高速读入内存。
  • 脱机输出：主机先把结果写到磁带；外围机再把磁带上的结果打印或输出，主机不必等待慢速打印机。

这一步的关键不是“磁带比纸带快”这么简单，而是把主机和慢速设备解耦。主机只和磁带打交道，磁带是顺序、成块、相对高速的介质；慢速的纸带机、打印机交给外围机。若有多台磁带机，外围机还可以在主机计算的同时准备下一批输入，形成一定程度的主机计算与外围 I/O 的重叠。

但脱机 I/O 仍然不是多道程序。内存里通常还是只有一道用户程序，作业之间仍然串行；装卸磁带仍要人工参与；它也没有解决“一道程序等待 I/O 时，CPU 能否去跑另一道程序”的问题。它只是把“等待慢设备”改成了“等待磁带”，并把一部分等待转移到了主机之外。

四、单道批处理：让作业自动接着跑

单道批处理系统在内存中只保留一道用户程序，但把多个作业事先排成一批，由常驻内存的监督程序（monitor）自动装入下一道。用户不再需要每跑完一个程序就重新装带、按开关；一批作业可以连续处理。

“单道”和“批”要分开看：单道说的是内存里同时只有一道用户程序；批说的是作业被成批组织、自动衔接。它解决的是“人工干预太多”，不是“CPU 等 I/O”。

因为只有一道程序，CPU 和外设只能串行工作：程序发起 I/O 后，CPU 只能等 I/O 完成；I/O 期间内存里的其他空间也闲置。于是资源利用率仍然很低，尤其是 I/O 密集的作业会把 CPU 拖住。它的优点则是作业自动过渡、减少人工操作、吞吐量比人工方式高，并为后来的多道批处理打下了“作业队列 + 监督程序”的结构。

五、多道批处理：用“切换”填满 CPU 的空闲

多道批处理的核心动作只有一句话：当一道程序因为 I/O 等原因不能继续运行时，把 CPU 切换给另一道已经驻留在内存的程序。内存中同时存放多道程序，它们交替占用 CPU；从宏观上看，多道程序都在“推进”，从微观上看，单 CPU 在任意时刻仍然只执行一道。

这套机制不是“把程序放进去”就自动成立的，它需要一整套硬件和软件支撑：

  • 中断机制：I/O 完成、时钟到期时，CPU 要能被“叫回来”，否则切出去就回不来；
  • 调度：多道程序都就绪时，选谁运行；一道程序阻塞时，选谁接替；
  • 存储保护与地址转换：不能让 A 程序读写 B 程序的内存；程序装入位置变化后还要能正确访存；
  • 设备管理：多道程序可能同时申请设备，必须排队、分配、避免死锁；
  • 并发控制：多个程序共享变量/文件时，要有同步互斥机制。

因此，“多道”不仅是一个加载技术，它把操作系统从“批处理监督程序”推向了真正的资源管理者。后面的进程管理、内存管理、文件管理、设备管理，几乎都是多道程序带来的问题。

维度单道批处理多道批处理
内存中的用户程序一道多道
CPU 与 I/O串行，CPU 等 I/O一道等 I/O 时切换另一道，CPU 与 I/O 可重叠
优点自动、简单、比人工方式利用率高资源利用率高、吞吐量大、能跑较大作业
缺点CPU 空闲多、内存浪费、无交互无交互、周转时间长、调度与保护复杂
关键支撑监督程序、作业队列中断、调度、地址转换、保护、并发控制

多道批处理的“批”还带来一个容易被忽略的后果：用户提交作业后，要等到作业被调度、运行完才能拿到结果，期间无法在运行中干预，周转时间很长。这不是实现得不好，而是“成批 + 无交互”的定义决定的。要交互，就必须让用户终端和正在运行的程序之间频繁切换，这就进入了分时。

六、分时：把 CPU 切成时间片

分时系统把 CPU 时间划分成一个个时间片，按某种轮转策略分给各个终端用户。一个用户的时间片用完，时钟中断把 CPU 收回，交给下一个就绪用户；每个用户轮流得到一小段 CPU，感觉上像“独占”了一台机器。

如果只考虑 n 个用户、每个用户每轮只得到一个时间片 q，忽略切换开销，那么一个用户从本次时间片结束到下次再被调度，大约要等 (n−1)q；一轮的总长度约为 nq。这就是为什么用户数一多，时间片必须变小，否则响应会明显变慢；但时间片太小，进程切换、寄存器保存、Cache 失效等开销又会占比过高。时间片的选择是“响应”与“开销”的折中。

分时系统通常强调四个特征：

  • 多路性：多个用户/终端同时使用一台主机；
  • 独立性：每个用户感觉自己独占一台机器，彼此不干扰；
  • 及时性：用户请求能在较短时间内得到响应；
  • 交互性：用户可以随时输入命令、修改程序、观察结果。

“及时”是相对用户操作而言的，不是硬实时。分时系统可以容忍偶尔的响应变慢，只要用户不觉得卡死；它也不保证某个任务在绝对截止期前完成。把“分时”当成“实时”，是后面最常见的概念混淆之一。

七、实时：重要的不是平均快，而是不误期

实时系统要处理的是“事件来了，必须在规定时间内做完”的任务。这里的“规定时间”叫截止期（deadline）。实时系统追求的不是平均响应时间最短，而是最坏情况下也有时间上界，并且这个上界可预测。

按错过截止期的后果，实时系统分为两类：

类型约束超时后果典型场景
硬实时必须在绝对截止期前完成可能造成灾难、设备损坏或人身伤害飞行控制、起搏器、汽车 ABS/安全气囊、工业机器人
软实时尽量在截止期前完成，允许偶尔超时服务质量下降，但系统仍可接受视频播放、语音通话、在线交易、交互式游戏

实时系统的设计重点因此落在可预测性上：中断延迟要小且可界定，内核临界区要短，调度算法要能保证高优先级任务及时抢占，时钟精度要足够。为了可预测，实时系统往往牺牲吞吐量和通用性：它可能不做复杂的缓存、不做激进的延迟写回、不允许长临界区。这也是“实时 OS 不一定比通用 OS 跑分高”的原因。

还要区分“硬实时”和“软实时”的边界：软实时不是“没有截止期”，而是“偶尔错过可以接受”；硬实时也不是“所有任务都最快”，而是“关键任务绝不能错过”。判断时看错过之后的后果，不要看任务本身的计算量大不大。

八、微机、网络、分布式与嵌入式

除了按“批处理/分时/实时”这种工作方式分类，还可以按硬件平台和应用环境分类。两组分类会重叠，不是同一条进化链上的前后阶段。

  • 微机操作系统：面向个人计算机。早期常见单用户单任务（如 MS-DOS），后来发展为单用户多任务（Windows、macOS），也有多用户多任务的类 Unix 系统。它的重点是图形界面、易用性、外设兼容和能效。
  • 网络操作系统：在各自独立的计算机上运行，提供网络通信、文件共享、远程登录等能力；每台机器仍有自己的 OS，用户能感知到“多台机器”。
  • 分布式操作系统：把多台计算机组织成一个统一的系统，追求单一全局视图、透明访问、分布式调度和容错；用户不必关心任务实际在哪台机器上执行。
  • 嵌入式操作系统：运行在资源受限的专用设备中，常与实时性结合（家电、汽车电子、工业控制、物联网终端）。

“微机 OS 就是单任务”是过时印象；“网络 OS 就是分布式 OS”也不对：前者是“多台独立机器 + 资源共享”，后者是“多台机器呈现为一台”。考试若问分类，先看题目按什么维度问：按工作方式，还是按平台/应用。

十、辨析与易错点

容易混的一对关键区别一句话判断
单道 vs 多道内存中同时驻留几道用户程序单道是一道跑完再下一道；多道是一道阻塞时切另一道
多道批处理 vs 多道程序设计前者是系统形态，后者是技术/思想多道程序设计也可用于分时、实时；多道批处理只是“多道 + 成批 + 无交互”
分时 vs 实时分时追求交互公平和较短响应；实时追求截止期保证分时允许偶尔慢；硬实时不允许错过
并发 vs 并行并发是宏观同时、微观交替；并行是同一时刻真正同时单 CPU 多道是并发；多核/多机才可能并行
脱机 I/O vs 多道脱机只把慢设备移出主机；多道要让多道程序交替占用 CPU脱机仍是单道串行，不解决“CPU 等 I/O 时跑谁”
批处理 vs 分时批处理成批、无交互；分时按时间片轮转、强交互看用户能不能在运行中介入

几个常见错误，背后都是把“手段”当成了“目的”：

  • “多道就是多 CPU 并行”：多道程序设计的原始场景就是单 CPU。它靠切换制造宏观并行，任意时刻只有一个程序真正占用 CPU。
  • “分时就是实时”：分时的“及时”是让人等得不难受；实时的“及时”是不能错过截止期。前者是体验指标，后者是正确性指标。
  • “脱机 I/O 就是多道批处理”：脱机 I/O 只是把输入输出搬到外围机，内存里仍可能只有一道程序；多道批处理的关键是“多道驻留 + 切换”。
  • “批处理就是一次把所有作业都装进内存”：批处理是成批组织作业，真正装入内存的只是被调度到的那几道；多道批处理也受内存容量限制。
  • “实时系统一定更快”：实时系统可能为了可预测性牺牲平均性能；它保证的是最坏情况的时间上界。
  • “微机 OS 都是单任务”：那是早期微机的特征；现代微机 OS 普遍支持多任务、多用户。

把这一节压缩成一条演化线：人工操作解决不了人机速度矛盾 → 脱机 I/O把慢设备移走 → 单道批处理让作业自动衔接 → 多道批处理用切换填满 CPU 空闲 → 分时把“批”拆成交互 → 实时把“响应”升级为“截止期”。每一步都在解决前一步留下的新问题，而不是简单地把上一代淘汰掉。
