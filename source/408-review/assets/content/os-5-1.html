文件管理的第一问不是“磁盘怎么分块”，而是“用户怎样用一个名字找到一份数据”。这条链是：文件名 → 目录项 → inode → 数据块。目录负责“按名查找”，inode 负责“记住文件在哪里、有多大、谁能用”。

一、文件是什么

文件是以文件名标识、由若干记录组成的有序集合，是外存上的逻辑存储单位。它有两个不同层面：

  • 逻辑结构：从用户视角看，记录怎样排列、是否定长、是否按关键字组织；
  • 物理结构：从磁盘视角看，文件占用哪些盘块、盘块之间怎样连接或索引。

文件管理系统要同时解决三件事：按名找到文件（目录）、记住文件属性与位置（FCB/inode）、把文件逻辑块映射到磁盘块（物理结构）。

二、FCB：文件控制块

FCB（File Control Block）是操作系统为文件建立的属性集合。常见字段分三类：

类别字段作用
基本信息文件名、物理位置、逻辑结构、物理结构标识文件、找到数据、说明组织方式
存取控制文件主、用户权限（读/写/执行）决定谁能怎样访问
使用信息创建时间、修改时间、当前打开/使用计数管理生命周期和共享

早期系统把 FCB 直接放在目录项里，目录项很大，查目录时要读大量属性。引入 inode 后，目录项通常只保留文件名 + inode 号，把大部分属性移到 inode，目录更小、检索更快。

三、索引结点 inode

inode 是文件的“元数据 + 数据块入口”。磁盘 inode 常驻外存的 inode 区；文件被打开时，inode 调入内存形成内存 inode。

字段含义
文件类型/权限/文件主普通文件、目录、设备；读/写/执行权限
文件长度文件字节数或块数
链接计数指向该 inode 的目录项/硬链接数
时间信息创建、修改、访问时间
数据块指针直接块、一级/二级/三级间址
访问计数（内存 inode）当前有多少打开实例引用它

inode 数量决定文件个数上限：磁盘再大，inode 用完也不能再创建新文件。inode 号是文件的内部编号；目录项保存它，文件名只是用户看到的别名。

四、目录：文件名到 inode 的映射

目录本身也是文件，目录项是目录文件的记录。引入 inode 后，一个目录项至少包含：

文件名 | inode 号

按名查找时，系统从根目录或当前目录开始，逐级读目录文件，拿到下一级 inode 号，直到目标文件。路径越长，查目录的磁盘 I/O 越多；目录项越小、目录越集中，查找越快。

目录结构特点
单级目录全系统一张目录表；实现简单，但文件不能重名、查找慢、不便于多用户隔离
两级目录主目录 + 用户目录；不同用户可使用相同文件名
树形目录按路径逐级查找，支持同名文件分布在不同目录；便于分类和权限控制
无环图目录允许共享子目录/文件，用链接计数管理；实现复杂

在 UNIX 类文件系统中，目录项只存文件名和 inode 号，意味着文件名与文件数据解耦：同一个 inode 可以有多个名字（硬链接），同一个文件也可以被不同路径访问。

虚拟文件系统 VFS 是内核中的抽象层：它定义统一的文件/目录/inode 操作接口，让 ext4、FAT、NFS 等不同文件系统都能被同一套系统调用访问。VFS 不等于“运行在虚拟内存里的文件系统”，也不必然加快访问速度；它的价值是统一接口、屏蔽具体文件系统差异。

五、FCB、inode、目录、目录项辨析

先把结论放在前面：FCB 是“文件元数据集合”这个概念，inode 是它在 UNIX 类文件系统中的实现；目录是存放目录项的特殊文件，目录项是目录里的一条“名字 → 文件”记录。四者是不同层次，不是四个互相排斥的东西。

概念内容存在哪里怎么被读到
FCB（广义）文件名、属性、物理位置、大小、时间、权限等文件元数据不同系统不同：FAT 放在目录项里；UNIX 类放在 inode 里；打开后内存中还有副本查目录时随目录项读入，或由目录项给出的 inode 号读 inode；open 后进系统打开文件表/内存 inode
inode（索引结点）文件类型、权限、文件主、大小、链接计数、时间、数据块指针（直接/间接）磁盘 inode 区；打开后调入内存 inode 表/缓存目录项只给 inode 号；按 inode 号在 inode 区定位，读入内存；不按文件名直接找 inode
目录一张“文件名 → inode 号/FCB”的映射表；目录本身也是文件目录文件的数据块在磁盘；目录自己的 inode/FCB 描述它从根目录/当前目录开始，读目录文件的数据块，逐项比较文件名
目录项UNIX：文件名 + inode 号（+ 记录长度/文件类型）；FAT：文件名 + 属性 + 起始簇 + 大小等，本身就是 FCB目录文件的数据块中；随目录块读入内存读目录块后按名字匹配；命中后拿 inode 号/起始簇继续访问

是相容还是互斥？

不是互斥，是“抽象与实现、整体与部分”的关系。

  • FCB 与 inode：inode 是 FCB 在 UNIX 类文件系统中的具体实现。可以说“inode 是一种 FCB”，但不能反过来说“所有 FCB 都是 inode”——FAT 的目录项也是 FCB，却没有 inode。
  • 目录项与 inode：目录项负责“名字”，inode 负责“元数据 + 数据块”。UNIX 下二者配合才相当于一个完整 FCB；目录项本身不是 inode。
  • 目录与目录项：目录是容器/特殊文件，目录项是其中的记录；目录由许多目录项组成，不是并列概念。
  • 目录与 inode：目录有它自己的 inode；目录的数据块里放的是子项的目录项。二者一个是“特殊文件”，一个是“该文件的元数据”。

所以考试里如果问“FCB 和 inode 是否等价”，要加前提：在 UNIX 类文件系统中，inode 是 FCB 的主体；在 FAT 中，目录项就是 FCB，没有独立 inode。离开文件系统实现谈“互斥”没有意义。

不同文件系统下的存在形式

文件系统目录项内容FCB 在哪里是否有独立 inode
FAT（DOS/Windows）文件名、属性、起始簇号、文件大小、时间等；长文件名另有 LFN 目录项目录项本身就是 FCB；FAT 表负责簇链没有 UNIX 式 inode
UNIX/ext2/3/4文件名 + inode 号（+ 记录长度/文件类型）inode 表保存元数据；目录项只保存名字和编号有，inode 是核心
NTFS目录是名字 → MFT 记录号的索引（B+ 树）MFT 记录是 FCB 类结构，保存属性和数据运行没有叫 inode，但有等价的 MFT 记录
CP/M 等早期系统目录项记录文件名、扩展名、块分配等FCB 可由程序在内存建立，目录项保存文件入口没有

按路径读取时到底读了什么

以 UNIX 类文件系统的 /home/bok/a.txt 为例：

根目录 inode（已知/常驻）
  → 根目录数据块：找 home → 得 home 的 inode 号
  → home inode → home 数据块：找 bok → 得 bok 的 inode 号
  → bok inode → bok 数据块：找 a.txt → 得 a.txt 的 inode 号
  → a.txt inode → 数据块指针 → 读文件内容

每一步都是“读目录文件的数据块，按名字匹配目录项，拿到 inode 号；再读 inode，进入下一层”。文件名只在目录项里出现；inode 里通常不存文件名。FAT 系统则把“inode 号”换成“目录项里的起始簇号 + FAT 簇链”，路径查找的框架相同，只是元数据存放位置不同。

六、易错点与收束

  • “目录项就是 inode”：目录项是“名字 + inode 号”，inode 是属性/数据块指针，二者不是一回事。
  • “一个文件名对应一个 inode”：硬链接让多个文件名共享同一个 inode；软链接是另一个文件，有自己的 inode。
  • “inode 里存文件名”：通常不存；文件名在目录项里，inode 存属性和数据块指针。
  • “inode 越多越好”：inode 占外存，数量在格式化时确定；太多浪费空间，太少限制文件个数。

把这一节收成一句话：目录负责“名字→inode”，inode 负责“属性→数据块”，文件管理就是沿着这条链把名字变成磁盘上的数据。
