考点2-内部排序总结

稳定性

稳定性：如果表中有两个关键字相同的元素，排序前 A 在 B 前面，排序后 A 仍然在 B 前面，就说这个排序算法是稳定的；否则是不稳定的。

稳定性看的是相同关键字的相对次序，不是"排序结果是否唯一"，也不是"算法快不快"。同一个算法换一种实现，稳定性也可能变——比如把严格比较改成带等号的比较，就可能把相等元素换过去。

算法 稳定性 关键原因
直接插入排序 稳定 只有严格小于才后移，相等元素停在它右边
折半插入排序 稳定 相等时走右半区，插入点在相等元素之后
希尔排序 不稳定 跨组移动，相等元素可能被分到不同组
冒泡排序 稳定 只有严格大于才交换，相等不换
快速排序 不稳定 划分时相等元素可能被跨位置搬走
简单选择排序 不稳定 最小值与前面交换时可能越过相等元素
堆排序 不稳定 堆顶 / 堆底远距离交换，顺序可能被打乱
归并排序 稳定 相等时先取左边子表
基数排序 稳定 队列 FIFO，入队尾、出队头

本章这 9 个排序里：稳定的有 5 个（直接插入、折半插入、冒泡、归并、基数），不稳定的有 4 个（希尔、快速、简单选择、堆）。

口诀：不稳定的只有四个——希、快、选、堆（"希快选堆"）。课件把它编成"选艾希堆攻速"：选 = 简单选择，希 = 希尔，堆 = 堆，速 = 快速（"艾""攻"是凑句子的字）。

几个容易错的点：

  1. 稳定性不是"排序结果唯一"：有重复关键字时，稳定和不稳定的算法都能得到有序序列，区别只在相同关键字的先后。
  2. 直接插入 / 折半插入 / 冒泡的稳定性依赖严格比较：把 A[j] > temp 改成 >=、把 A[mid] > A[0] 改成 >=、把 A[j] > A[j+1] 改成 >=，相等元素就会被换过去，稳定性被破坏。
  3. 归并的稳定性依赖 <=：相等时先取左边；写成 < 就可能先取右边。
  4. 基数排序的稳定性依赖队列 FIFO：分配挂队尾、收集从队头；顺序反了就不稳定。
  5. 简单选择排序不稳定：虽然每趟最多交换一次，但交换可能跨过相等元素；不要因为"交换少"就误以为稳定。
  6. 快速排序不稳定，但通常很快：稳定性和平均性能是两件事，不能因为快排不稳定就否定它。

一趟排序能确定一个元素最终位置的算法

算法 能否保证一趟定死一个？
直接插入排序 不能
折半插入排序 不能
希尔排序 不能
冒泡排序 能
简单选择排序 能
快速排序 能（一次划分定死枢轴）
堆排序 能（建堆后每趟交换定死当前最大值）
归并排序 不能
基数排序 不能

注：这里按课件的"一趟"口径——快速排序指一次划分（只定死枢轴），堆排序指建堆后的每一趟交换；408 严格定义的"一趟排序"可能一次确定多个元素，别和"一次划分"混。

展开：③ 的原因
  • 冒泡：每趟把当前未排序部分的最大（或最小）值冒到一端，位置确定。
  • 简单选择：每趟选出无序区最小值放到最前面，位置确定。
  • 快速：一次划分把枢轴放到最终位置；左右子表还要递归。
  • 堆：建好大根堆后，每趟把堆顶最大值换到当前堆底，最大值到位；建堆阶段本身不算。
  • 直接插入 / 折半插入：只保证有序区内部有序，后面的更小元素还可能插到前面。
  • 希尔：中间趟只按增量局部有序，只有最后一趟 $dk=1$ 才整体有序。
  • 归并：合并只让子表有序，单个元素要等最后一次合并才定死。
  • 基数：一趟只按一位分配/收集，高位还会改变次序。

比较次数与初始状态无关的算法

这张表要特别注意括号里的条件：折半插入和归并的"无关"只指数量级；冒泡的"无关"只指未优化版本。

算法 是否无关 条件 / 口径
折半插入排序 数量级无关 精确次数随插入空隙变化
冒泡排序（未优化） 无关 不带 flag；带 flag 时最好 O(n)，有关
简单选择排序 无关 固定 n(n-1)/2
归并排序 数量级无关 精确次数随合并交错变化
基数排序 无关 不比较关键字，比较次数为 0
直接插入排序 有关 最好 n-1，最坏 n(n-1)/2
希尔排序 有关 与增量序列、初始顺序有关
快速排序 有关 最好 / 平均 O(n log n)，最坏 O(n²)
堆排序 有关 精确次数随建堆/下坠路径变化（数量级仍 O(n log n)）

所以"与初始状态无关"不能一句话套：先看它说的是精确次数还是数量级，再看冒泡有没有带 flag。

展开：④ 的条件与原因
  • 折半插入：比较次数的上界由有序区长度决定，总量级 Θ(n log n)；但待插入关键字落在不同空隙，实际次数会变。
  • 冒泡（未优化）：没有 flag，永远比较 n-1+…+1 = n(n-1)/2 次；带 flag 后最好一趟就停，最好 O(n)。
  • 简单选择：每趟都要把无序区扫完，比较次数固定 n(n-1)/2。
  • 归并：每层合并总比较次数 Θ(n)，层数固定 ⌈log₂ n⌉，所以量级 Θ(n log n)；单次 Merge 在 min{m,n} 到 m+n-1 之间。
  • 基数：不比较关键字，比较次数为 0。
  • 直接插入 / 希尔 / 快速：最好与最坏的数量级不同（或依赖增量/枢轴），所以有关。
  • 堆：建堆和下坠的路径随数据变化，精确次数会变；但数量级始终 O(n log n)。

移动次数与初始状态无关的算法

算法 是否无关 说明
归并排序 无关 每层固定复制/写回 n 个元素
基数排序 无关 每趟固定分配/收集 n 个记录
直接插入排序 有关 最好 0，最坏 O(n²)
折半插入排序 有关 最好 2(n-1) 次哨兵复制，最坏 O(n²)
希尔排序 有关 与增量、初始顺序有关
冒泡排序 有关 交换次数等于逆序对数
简单选择排序 有关 交换 0~n-1 次
快速排序 有关 划分位置影响交换/移动
堆排序 有关 建堆/下坠路径随数据变化

移动次数和比较次数要分开看：简单选择比较次数固定，但交换次数会变；归并/基数的移动次数固定，不等于它们的比较次数也固定——归并的比较次数只固定量级，基数的比较次数恒为 0（不比较）。

展开：⑤ 的原因
  • 归并：每层把 n 个元素复制到 B、再写回 A，层数固定，总移动次数固定。
  • 基数：每趟分配/收集都处理 n 个记录，d 趟固定。
  • 直接插入：正序 0 次移动，逆序 O(n²)。
  • 折半插入：正序也要每趟存哨兵/回填，共 2(n-1) 次；逆序 O(n²)。
  • 希尔：组内后移次数随增量和初始顺序变化。
  • 冒泡：交换次数等于逆序对数，正序 0、逆序 n(n-1)/2。
  • 简单选择：每趟最多交换一次，交换次数 0~n-1。
  • 快速：划分时元素搬移次数取决于枢轴位置。
  • 堆：建堆和每次下坠的交换次数取决于数据。

总趟数与序列初始状态有关的算法

算法 总趟数是否有关 说明
直接插入排序 无关 固定 n-1 趟
折半插入排序 无关 固定 n-1 趟
希尔排序 无关 固定增量序列的轮数，由 n 和增量决定
冒泡排序（优化后的） 有关 本趟无交换就提前停；最好 1 趟，最坏 n-1 趟
简单选择排序 无关 固定 n-1 趟
快速排序 有关 划分均匀时约 log n 层，极端时 n 层
堆排序 无关 建堆一次 + n-1 趟取堆顶
归并排序 无关 固定 ⌈log₂ n⌉ 趟
基数排序 无关 固定 d 趟

注意：冒泡排序只有优化后（带 flag、无交换就提前停）才与初始状态有关；不带 flag 的冒泡永远做 n-1 趟。希尔排序是跟增量序列有关，不是跟初始排列有关——增量序列固定时，趟数只由 n 决定。

这里说的是"趟数"（扫描/划分的轮数），不是时间复杂度；趟数固定不代表每趟的代价相同。快速排序的"趟数"按递归层数算，不是总划分次数。

展开：⑥ 的原因
  • 直接插入 / 折半插入：外层 i 从 2 到 n，固定 n-1 趟，和输入无关。
  • 希尔：趟数等于增量序列的长度；固定序列时只由 n 决定。
  • 冒泡（优化后）：本趟无交换就 break；正序 1 趟，逆序 n-1 趟。
  • 简单选择：i 从 1 到 n-1，固定 n-1 趟。
  • 快速：每次划分的枢轴位置决定子问题大小；均匀时约 log n 层，极端时 n 层。
  • 堆：建堆一次，之后 n-1 次"交换堆顶 + 下坠"，趟数固定。
  • 归并：每层对半分，固定 ⌈log₂ n⌉ 层。
  • 基数：按 d 位做 d 趟，固定。

例题：【2009】（第二趟排序后的结果）

【2009】若数据元素序列 {11, 12, 13, 7, 8, 9, 23, 4, 5} 是采用下列排序算法之一得到的第二趟排序后的结果，则该排序算法只能是

  • A. 冒泡排序
  • B. 插入排序
  • C. 选择排序
  • D. 二路归并排序
查看答案解析

选 B（插入排序）。

插入排序前两趟只处理前三个元素：先放入 11，再插入 12、13，得到 11,12,13，后面的元素原封不动——正好是题干的序列。

其余三个都对不上：

算法 两趟后的特征 本题序列
插入排序 前 3 个有序，后面不动 11,12,13 有序，符合
冒泡排序 左→右：末尾是最大两个 13、23；右→左：开头是最小两个 4、5 末尾是 4、5、开头是 11、12，不符合
选择排序 前两个是最小的两个 4、5 开头是 11、12，不符合
二路归并排序 第二趟后每 4 个一组应有序 11,12,13,7 不是有序，不符合

所以只能是插入排序，选 B。

注：二路归并这里按自底向上的口径（第一趟长度 2、第二趟长度 4）；递归实现的中间分组可能不同，但这道题按考试口径判断。

例题：【2022】（为什么选直接插入而不是快排）

【2022】对数据进行排序时，若采用直接插入排序而不采用快速排序，则可能的原因是

  • I. 大部分元素已有序
  • II. 待排序元素数量很少
  • III. 要求空间复杂度为 O(1)

  • IV. 要求排序算法是稳定的

  • A. 仅 I、II

  • B. 仅 III、IV
  • C. 仅 I、II、IV
  • D. I、II、III、IV
查看答案解析

选 D（I、II、III、IV）。

  • I 大部分元素已有序：直接插入排序接近 O(n)；快排如果枢轴取得不好（例如总取首元素），在基本有序时容易退化。
  • II 元素数量很少：插入排序常数小、没有递归开销，通常比快排更合适。
  • III 要求空间 O(1)：直接插入是 O(1)；快排的递归栈平均 O(log n)、最坏 O(n)。
  • IV 要求稳定：直接插入稳定；标准原地快排不稳定。

四条都可能，选 D。

注：这里讨论的是标准原地快排；如果允许额外空间或特殊实现，稳定性和空间结论可能改变。

例题：【2017】（为什么选归并而不是插入）

【2017】在内部排序时，若选择了归并排序而未选择插入排序，则可能的理由是

  • I. 归并排序的程序代码更短
  • II. 归并排序的占用空间更少

  • III. 归并排序的运行效率更高

  • A. 仅 II

  • B. 仅 III
  • C. 仅 I、II
  • D. 仅 I、III
查看答案解析

选 B（仅 III）。

  • I 错：归并排序要写递归、合并和辅助数组，代码通常比直接插入长。
  • II 错：归并排序需要 O(n) 的辅助数组，插入排序只要 O(1)。
  • III 对：归并排序是 O(n log n)，插入排序最坏 / 平均是 O(n²)。

所以只有 III，选 B。

注：如果数据已经基本有序，插入排序可能达到 O(n)，这时它可能更快；但题目问的是一般理由，III 成立。

例题：【2019】（快排第二趟不可能的结果）

【2019】排序过程中，对尚未确定最终位置的所有元素进行一遍处理称为一趟。下列序列中，不可能是快速排序第二趟结果的是

  • A. 5, 2, 16, 12, 28, 60, 32, 72
  • B. 2, 16, 5, 28, 12, 60, 32, 72
  • C. 2, 12, 16, 5, 28, 32, 72, 60
  • D. 5, 2, 12, 28, 16, 32, 72, 60
查看答案解析

选 D。

题干说的"一趟"是：把所有尚未确定最终位置的元素处理一遍。快排第一趟定下第一个枢轴；第二趟要把第一趟分出的每个当前子表都划分一次（如果第一趟枢轴在端点，就只有一边）。

最终有序序列是 2,5,12,16,28,32,60,72。逐个看：

选项 可作第一枢轴 第二趟 结论
A 72 左段以 28 为枢轴 可能
B 2 右段以 28 为枢轴 可能
C 28 左段以 2、右段以 32 为枢轴 可能
D 12 或 32 12 的左侧 [5,2] 没有到位元素；32 的右侧 [72,60] 没有到位元素 不可能

D 无论第一枢轴选 12 还是 32，都会有一侧的非空子表找不到能当枢轴的到位元素，所以不可能，选 D。

注：判断"能不能"时，枢轴可以选任意元素，只要存在一种选法即可；A、B、C 都能找到对应的枢轴安排。
