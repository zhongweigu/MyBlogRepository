进程既是资源分配单位，又是调度单位。但一个进程里如果只有一条执行流，它一旦阻塞，整个进程就停住；创建/切换进程又要换地址空间，代价高。线程把这两件事拆开：资源仍然归进程，CPU 调度交给线程。理解线程，重点不是“线程更轻”，而是看清哪些资源共享、哪些私有、谁来调度。

一、为什么需要线程

如果进程既是资源单位又是调度单位，会有两个问题：

  • 切换贵：进程切换要换页表、刷新 TLB、保存完整现场；
  • 并发粒度粗：一个进程只有一个执行流，进程内某段代码阻塞，整个进程都停。

线程把“执行流”从进程里拆出来：同一进程可以有多个线程，它们共享地址空间和打开文件，但各自有寄存器、PC、栈和 TCB。这样，一个线程等待 I/O 时，另一个线程还可以继续跑；线程切换通常不用换地址空间，开销比进程切换小。

但“轻”不是免费的：线程共享地址空间，任何线程都能读写其他线程的栈和全局变量，数据竞争和同步问题比进程更直接。

二、进程与线程的分工

维度进程线程
定位资源分配的基本单位调度/分派的基本单位
地址空间独立同一进程内共享
拥有资源地址空间、文件、设备等基本不拥有资源，依附于进程
私有内容PCB、页表、地址空间寄存器、PC、栈、TCB
切换开销较大，可能换页表/TLB较小，同进程内通常不换页表
通信需要共享存储/消息/管道直接读写共享变量（需同步）
健壮性进程间隔离较好一个线程崩溃可能拖垮整个进程

所以“线程是轻量级进程”这个说法只对了一半：它轻在切换和资源共享，但代价是隔离性变差。

三、共享什么，私有什么

共享私有
代码段、数据段、堆寄存器现场（通用寄存器、PC、PSW）
打开的文件、当前目录用户栈和内核栈
信号处理函数、地址空间线程 ID、TCB、优先级/调度信息
进程的资源和权限线程局部存储（TLS）

“共享堆、私有栈”意味着：一个线程 malloc 出来的内存，其他线程可以直接访问；但一个线程的局部变量在它自己的栈上，其他线程要拿到地址才能访问——而语言/运行时通常不鼓励这样。线程之间没有 MMU 保护，栈溢出或野指针可能破坏其他线程的数据。

四、ULT：用户级线程

ULT（User-Level Thread）把线程的创建、切换、调度都放在用户空间的线程库里，内核只看到一个普通的单线程进程。线程库维护线程表和 TCB，切换时保存/恢复用户寄存器，不需要陷入内核。

优点：

  • 线程切换不需要模式切换，开销小；
  • 进程可以为自己的线程选择专用调度算法；
  • 线程库在用户空间实现，可移植，甚至能在不支持线程的 OS 上运行。

缺点：

  • 内核只识别进程，每次只能把一个 CPU 分给整个进程；同一进程的多个 ULT 无法在多核上真正并行；
  • 一个 ULT 发起阻塞系统调用（如 read）时，内核会阻塞整个进程，其他 ULT 也跑不了；
  • 内核级事件（时钟、I/O）只能打断进程，线程库再决定切换哪个线程。

五、KST：内核级线程

KST（Kernel-Level Thread）由内核直接管理：每个线程有内核中的 TCB，内核调度器直接调度线程。用户线程通过系统调用创建/销毁内核线程，线程切换要进入内核。

优点：

  • 多核/多处理机上，同一进程的多个线程可以分到不同 CPU，真正并行；
  • 一个线程阻塞时，内核可以调度同进程其他线程，或调度其他进程；
  • 内核可以直接利用时钟中断做抢占式线程调度。

缺点：

  • 线程切换要进内核，模式切换和调度开销更大；
  • TCB 放在内核空间，占内核内存；
  • 线程创建/销毁/同步更多依赖系统调用。

六、多线程模型

模型用户线程 : 内核线程特点
多对一多个 ULT → 一个 KST接近 ULT；切换快，但一个阻塞全阻塞，不能多核并行
一对一一个 ULT → 一个 KST并发/并行好，但线程创建和切换开销大，内核线程数量受限
多对多多个 ULT → 多个 KST复用内核线程，兼顾并行和开销；实现复杂

很多系统还会用“两层模型”：既有多对多，也允许某些线程绑定到专用内核线程。模型的选择本质上是并行度、切换开销、内核资源三者的折中。

七、切换、同步与易错点

线程切换保存/恢复寄存器、PC、SP 和 TCB；同一进程的线程共享页表，所以通常不换地址空间、不刷新 TLB。进程切换则可能换页表，代价更高。

线程共享地址空间，必须用互斥锁、信号量、条件变量等保护共享数据。一个线程打开的文件，其他线程也能读写；这也意味着“线程安全”不是自动的。

  • “线程有独立地址空间”：同一进程的线程共享地址空间；只有进程之间独立。
  • “ULT 切换一定要进内核”：ULT 的线程切换由用户库完成，不需要模式切换。
  • “ULT 一个线程阻塞不影响其他线程”：ULT 的阻塞系统调用会让整个进程阻塞。
  • “KST 没有开销”：KST 切换要进内核，TCB 也占内核资源。
  • “线程越多越好”：线程创建/切换/同步都有开销，还会争用 CPU、Cache 和内存。

把这一节收成一句话：进程管资源，线程管执行；ULT 在用户空间调度、快但怕阻塞，KST 在内核调度、能并行但有切换开销。
