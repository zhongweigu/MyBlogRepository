不同文件系统在磁盘上的布局完全不同：ext4 用 inode 表，NTFS 用 MFT，FAT 用目录项 + FAT 表。如果每个应用都直接面对这些差异，系统调用就没法统一。VFS 的作用就是在系统调用和具体文件系统之间加一层统一接口。

一、VFS 解决什么问题

VFS（Virtual File System）位于用户进程的系统调用和具体文件系统之间：

  • 向上：提供统一的 open/read/write/close 等接口，用户不用关心底层是 ext4、NTFS 还是 FAT；
  • 向下：把统一请求转发给具体文件系统的实现函数；
  • 它本身不是一种真正的磁盘文件系统，只存在于内存，不占磁盘空间，随系统启动建立、关机释放。

VFS 不“消除”文件系统差异，只是把差异藏在操作函数指针后面。挂载、路径查找、缓存、权限检查等通用逻辑由 VFS 做；具体读写、分配盘块由下层文件系统做。

二、VFS 的四个对象

对象表示什么典型内容生命周期
超级块对象 superblock一个已挂载的文件系统块大小、总块数、空闲块、文件系统类型、操作函数挂载时建立/读入，卸载时释放
inode 对象 / vnode一个具体的文件或目录类型、权限、大小、时间、指向底层 inode 的指针、操作函数首次访问时创建/复用，引用计数为 0 后可回收
目录项对象 dentry路径中的一个组成部分名字、父目录、子目录项、指向 vnode 的指针路径解析时建立，进入 dentry 缓存
文件对象 file一个进程的打开实例当前偏移、打开方式、引用计数、指向 dentry/vnode 的指针open 创建，close 且引用计数为 0 时销毁

四者关系可以记成：超级块管“哪个文件系统”，vnode 管“哪个文件”，dentry 管“路径中的这个名字”，file 管“这次打开”。同一条路径的 dentry 可以缓存；同一个文件可以被多个 file 对象打开，各自偏移不同。

三、vnode 与磁盘 inode 的区别

这是最容易被含糊过去的一点：

维度vnode（VFS inode 对象）磁盘 inode
层次VFS 的内存抽象具体文件系统的磁盘元数据
位置内存 inode 表/缓存外存 inode 区
内容统一属性 + 操作函数指针 + 指向底层 inode 的指针文件类型、权限、大小、链接计数、数据块指针
作用让上层用统一方式操作不同文件系统记录该文件在具体文件系统中的实际位置
数量/生命周期按访问动态创建/缓存，可回收格式化时确定，长期存在

所以：vnode 不是磁盘 inode，也不是 FCB 的简单别名。 vnode 是“统一接口对象”，它通过指针关联具体文件系统的 inode；在 ext4 中最终落到 ext4 inode，在 NTFS 中落到 MFT 记录。考试如果问“VFS 的 inode 对象是否就是磁盘 inode”，答案是否定的。

四、write 怎样经 VFS 分发

  1. 用户调用 write(fd, buf, n)，CPU 陷入内核，进入 VFS 的 sys_write。
  2. 用 fd 找到进程打开文件表中的文件对象。
  3. 文件对象指向 dentry/vnode；VFS 检查打开方式、权限。
  4. VFS 调用 vnode 上挂的具体文件系统 write 函数指针。
  5. 具体文件系统完成逻辑块到磁盘块的映射、页缓存/缓冲区写入，必要时分配新块。
  6. 数据最终由设备驱动写入磁盘；VFS 返回实际写入字节数。

VFS 只负责“统一入口 + 分发 + 通用缓存/权限”，不负责 ext4 的 inode 布局或 NTFS 的 MFT 细节。这正是它“屏蔽差异”的含义。

五、易错点与收束

  • “VFS 是一种磁盘文件系统”：VFS 是内存抽象层，不占磁盘；ext4/NTFS/FAT 才是具体文件系统。
  • “vnode 就是 inode”：vnode 是 VFS 的统一对象，inode 是具体文件系统的磁盘元数据，两者通过指针关联。
  • “VFS 会加快所有文件访问”：VFS 主要统一接口，不必然加速；性能取决于缓存、具体 FS 和设备。
  • “dentry 就是目录项”：dentry 是 VFS 在内存中缓存“路径名 → vnode”的对象，不等于磁盘上的目录项记录。

把这一节收成一句话：VFS 用超级块、vnode、dentry、file 四个内存对象，把不同文件系统统一到同一套系统调用接口；vnode 是抽象，磁盘 inode 是实现。
