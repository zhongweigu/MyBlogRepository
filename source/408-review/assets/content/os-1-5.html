虚拟机不是“模拟一台机器”这么简单。它要在同一套物理硬件上，让多个客户操作系统都以为自己独占 CPU、内存和设备，同时又要保证它们彼此隔离。完成这件事的核心是 VMM（Virtual Machine Monitor，虚拟机管理程序），也叫 hypervisor。理解 1 型和 2 型的区别，关键是看VMM 站在硬件的哪一层、谁掌握真正的内核态。

一、先分清四个角色

角色位置职责
宿主 OS（host OS）直接运行在物理硬件上管理真实硬件；2 型 VMM 依赖它
VMM / Hypervisor硬件与客户 OS 之间虚拟 CPU、内存、I/O；调度、隔离、截获特权操作
客户 OS（guest OS）虚拟机内部以为自己运行在裸机上，管理虚拟机内的进程和资源
虚拟机（VM）VMM 创建的逻辑机器包含 vCPU、虚拟内存、虚拟设备，运行一个客户 OS

“宿主”和“客户”是相对概念：宿主 OS 跑在真实硬件上；客户 OS 跑在 VMM 造出来的虚拟硬件上。VMM 本身既不是客户 OS，也不一定是一个完整的通用 OS。

二、1 型 VMM：直接站在硬件上

1 型 VMM（裸金属 / bare-metal）直接运行在物理硬件上，不需要先安装一个通用宿主 OS。它自己就是最靠近硬件的那层特权软件，负责把硬件切分给多个虚拟机。

在 1 型结构里，真正处于物理内核态的是 VMM；客户 OS 运行在所谓的虚拟化内核态：它以为自己有内核权限，但它执行敏感/特权指令时，硬件或 VMM 会把它截获，交给 VMM 模拟或代理。客户 OS 里的用户程序则运行在虚拟化用户态。

典型例子：VMware ESXi、Xen、Microsoft Hyper-V（Type 1）。这类结构层次少，通常用于服务器、云平台，性能和控制力更接近硬件。

三、2 型 VMM：寄居在宿主 OS 上

2 型 VMM（寄居 / hosted）作为宿主 OS 上的一个应用（或配合内核模块）运行。物理硬件先由宿主 OS 管理，VMM 再在宿主 OS 之上创建虚拟机。

在 2 型结构里，真正处于物理内核态的是宿主 OS；VMM 通常是用户态应用，客户 OS 仍在虚拟化内核态。客户 OS 的特权指令先被 VMM 截获，VMM 再通过宿主 OS 的系统调用/驱动访问硬件。典型例子：VMware Workstation、Oracle VirtualBox、Parallel Desktop。

2 型的优点是安装方便、能复用宿主 OS 的驱动和文件系统；代价是路径更长：客户 OS → VMM → 宿主 OS → 硬件，I/O 开销和调度层次通常更多。

四、虚拟化内核态与虚拟化用户态

“客户 OS 运行在内核态”是一种虚拟化的错觉。从物理 CPU 的角度看，特权级只有一套；VMM 必须保证客户 OS 不能直接改页表、关中断、控制真实设备。于是就有了三层身份：

  • 虚拟化用户态：客户 OS 里的普通应用程序；它和普通用户程序一样受限。
  • 虚拟化内核态：客户 OS 内核“以为”自己在内核态；它执行特权指令时会被 VMM 截获。
  • 真正的内核态：1 型里是 VMM，2 型里是宿主 OS；它们才直接控制物理硬件。

这种“截获—模拟—返回”的机制叫 trap-and-emulate（陷入并模拟）：客户 OS 执行一条敏感指令，CPU 触发异常/陷入到 VMM，VMM 检查这条指令想做什么，替它完成或返回一个合理结果。现代 CPU 还提供硬件辅助虚拟化（Intel VT-x、AMD-V），用 root/non-root 模式减少模拟开销，但“客户 OS 不是真正的物理内核态”这一点不变。

五、VMM 到底虚拟化了什么

资源VMM 做的事关键难点
CPU为每个 VM 提供 vCPU，调度 vCPU 上物理 CPU，保存/恢复虚拟 CPU 状态特权指令截获、中断注入、时间虚拟化
内存把客户物理地址映射到宿主物理地址；维护影子页表或 EPT/NPT两级地址转换、隔离、换页、MMIO
I/O模拟设备、virtio 半虚拟化、设备直通性能、设备兼容、DMA 隔离
其他快照、迁移、克隆、资源限额、故障隔离一致性、状态保存、安全边界

所以 VMM 不只是“跑一个 OS 的软件”，它要同时扮演 CPU 调度器、内存管理器、设备模型和安全隔离层。也正因为如此，VMM 的代码质量和攻击面非常关键。

七、虚拟机、容器与模拟器的边界

  • 虚拟机：VMM 虚拟整套硬件，每个 VM 运行独立的客户 OS；隔离边界强，启动较重。
  • 容器：共享宿主 OS 内核，用命名空间做隔离、用 cgroups 限制资源；没有独立客户 OS，启动轻，但隔离边界与 VM 不同。
  • 模拟器：用软件解释另一套指令集（如在不同架构上运行程序）；它和同 ISA 的硬件虚拟化不是一回事。

判断“是不是虚拟机”，看它有没有 VMM/虚拟硬件和独立客户 OS；只看“能不能隔离”不够，容器也能隔离，但机制不同。

八、常见误区

  • “1 型 VMM 就是客户 OS”：VMM 是直接管理硬件的虚拟化层；客户 OS 是它上面运行的虚拟机操作系统。
  • “客户 OS 真的在物理内核态”：客户 OS 处在虚拟化内核态，特权指令会被 VMM 截获；真正的物理内核态由 VMM（1 型）或宿主 OS（2 型）掌握。
  • “2 型 VMM 一定在内核态”：2 型 VMM 通常是宿主 OS 上的应用；它可能配合内核模块，但不能笼统说 VMM 本身在物理内核态。
  • “虚拟机就是容器”：虚拟机有独立客户 OS 和虚拟硬件；容器共享宿主内核。
  • “1 型一定比 2 型快”：层次少通常开销低，但还取决于硬件辅助、I/O 路径和负载，不能绝对化。

九、收束：看“谁在真内核态”

把两种结构压成一句话：1 型是 VMM 直接站在硬件上，VMM 在真内核态；2 型是 VMM 站在宿主 OS 上，宿主 OS 在真内核态。两种结构里的客户 OS 都只是在“虚拟化内核态”里以为自己有特权。

再往上追一层：客户 OS 的特权指令如何被截获、VMM 如何模拟，仍然是“用户态/内核态/特权指令”这套机制在虚拟化场景下的延伸。把 OS 的模式切换理解透，虚拟机这一节就只是多了一层“谁替谁执行特权操作”的问题。
