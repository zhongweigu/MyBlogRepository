队列是“先进先出”的线性表：只允许在一端插入（队尾 rear），在另一端删除（队头 front）。它本身不难，408 主要考三件事：顺序/循环/链式队列的判空判满、队列在算法中的角色、BFS 为什么需要队列。

一、队列的 ADT 与三种实现

ADT Queue {
    InitQueue(&Q)
    QueueEmpty(Q)
    EnQueue(&Q, x)   // 入队，队尾
    DeQueue(&Q, &x) // 出队，队头
    GetHead(Q, &x)
} ADT Queue
实现结构判空/判满特点
顺序队列数组 + front/rearfront==rear 空；rear==MAXSIZE 溢出简单，但会出现“假溢出”
循环队列数组首尾相接牺牲一个单元/设 tag/设 size解决假溢出，408 最常考
链队列带头尾指针的链表front==NULL 或 front==rear动态增长，入队 O(1)

顺序队列的“假溢出”不是真满：出队让 front 后移，前面空出位置，但 rear 已到数组末尾，不能绕回。循环队列把 `rear = (rear+1) % MAXSIZE`，空出的位置就能继续用。

循环队列的判空/判满有三种常用方案：

  • 牺牲一个单元：最多存 MAXSIZE−1 个元素；队空 `front==rear`，队满 `(rear+1)%M==front`（rear 指向队尾下一个位置时）。
  • 设 tag：`front==rear` 时，tag=0 为空、tag=1 为满；入队置 1，出队置 0。
  • 设 size：直接记录元素个数，size==0 空、size==M 满。

链队列通常带头结点：front 指向头结点，rear 指向队尾结点；入队在 rear 后插，出队删 front 的后继。注意只有一个元素时出队后要把 rear 重新指回头结点，否则 rear 会悬空。

二、队列的典型应用

场景为什么用队列
二叉树的层次遍历按“一层一层”的顺序处理，先访问的结点先展开孩子
图的 BFS先发现的顶点先扩展，保证按距离层次访问
操作系统的就绪/阻塞/设备请求队列按到达顺序排队，保证公平
缓冲区/打印队列生产者放入、消费者按 FIFO 取出
多级反馈队列调度多个就绪队列按优先级和轮转规则排队

队列在算法题里通常不是“目的”，而是维护“待处理顺序”的容器：谁先进队列，谁就先被扩展。BFS、层序遍历、拓扑排序（入度为 0 的顶点队列）都是这个思想。

三、BFS 与“无权图最短路”

BFS 从起点开始，先访问所有距离为 1 的顶点，再访问距离为 2 的顶点……它用队列保证“先发现的先扩展”。在无权图（或所有边权相同）中，BFS 第一次到达某顶点时经过的边数就是最短路径长度。

BFS(G, s):
    visited[s] = true; Q.push(s)
    while Q 非空:
        u = Q.pop()
        for v in Adj(u):
            if not visited[v]:
                visited[v] = true
                dist[v] = dist[u] + 1
                Q.push(v)

关键限定：普通 BFS 只适用于无权图/边权相等的最短路；带权图（边权不全相同）要用 Dijkstra/Floyd，不能直接套 BFS。若题目说“BFS 求单源最短路径”，默认图是无权的。

例：无权图 $s\to a,s\to b,a\to c,b\to c$。BFS 顺序是 $s,a,b,c$，$dist[c]=2$（$s\to a\to c$ 或 $s\to b\to c$），不会因为 $c$ 先被 $b$ 发现就得到更长路径。

四、易错点与收束

  • “队列就是先进先出，所以任何最短路都能用 BFS”：错；BFS 只保证无权图/等权图的最短路。
  • “循环队列 front==rear 一定是空”：不一定，也可能是满；要结合牺牲单元/tag/size 的约定。
  • “链队列出队只改 front”：删除最后一个结点时还要把 rear 指回头结点。
  • “队列只能用于 BFS”：队列还用于层序遍历、拓扑排序、缓冲区、调度等。

把这一节收成一句话：队列维护“先来先处理”的顺序；循环队列解决假溢出；BFS 用队列做层次扩展，但只有无权图才能直接当最短路。
