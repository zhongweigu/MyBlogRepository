## 1.2 计算机系统层次结构

### 1.2.1 计算机系统的组成

计算机系统由**硬件**和**软件**两部分组成。硬件是计算机的物理实体，软件是程序、数据及相关文档的集合。两者缺一不可：没有软件，硬件只是电子器件；没有硬件，软件也没有运行载体。

因此，**主机 = 主存 + CPU**，**CPU = 运算器 + 控制器**。输入设备和输出设备不属于主机。

冯·诺依曼结构首次提出“存储程序”概念，并以运算器为中心；现代计算机则通常以存储器为中心。程序和数据都先放入主存，CPU 按地址取指令、按顺序执行，遇到转移指令时才改变执行顺序。

![现代计算机以存储器为中心：输入设备、主存储器、运算器、控制器和输出设备之间的数据流与控制流](408计算机组成原理/1.2计算机系统层次结构-1.2.2计算机硬件(1).png)

> 注：图中实线表示数据或指令的流动，虚线表示控制器发出的控制信号。

从内部组成看，主存、运算器和控制器各自包含一组关键部件：

| 部件 | 寄存器或单元 | 作用 |
| --- | --- | --- |
| 主存 | 存储体 | 按地址存放指令和数据 |
| 主存 | MAR | 地址寄存器，存放要读写的存储单元地址；位数反映存储单元数量 |
| 主存 | MDR | 数据寄存器，暂存读出或写入的数据；位数等于存储字长 |
| 运算器 | ACC | 累加器，存放操作数或运算结果 |
| 运算器 | MQ | 乘商寄存器，进行乘、除法时使用 |
| 运算器 | X | 通用寄存器，存放操作数 |
| 运算器 | ALU | 算术逻辑单元，用电路实现算术运算和逻辑运算 |
| 控制器 | PC | 程序计数器，存放下一条指令的地址 |
| 控制器 | IR | 指令寄存器，存放当前正在执行的指令 |
| 控制器 | CU | 控制单元，分析指令并发出控制信号 |

程序开始运行时，指令和数据已经装入主存，PC 指向第一条指令。取指阶段把指令从主存送入 IR，PC 自动指向下一条指令；分析阶段由 CU 识别操作码；执行阶段再由 CU 指挥各部件完成操作。下面 1.2.6 会用一条具体的取数指令展开这个过程。

**主存按地址访问。** 每个地址对应一个存储单元，MAR 负责给出地址，MDR 负责暂存数据。

![主存结构：存储体按地址划分存储单元，MAR 选择地址，MDR 暂存数据；MAR=4 位时有 2^4 个单元，MDR=16 位时每个单元的字长为 16 位](408计算机组成原理/1.2计算机系统层次结构-1.2.2计算机硬件(4).png)

| 概念 | 含义 |
| --- | --- |
| 存储元 | 存放 1 位二进制的电子元件，每个存储元可存 1 bit |
| 存储单元 | 每个地址对应的单元，存放一个存储字 |
| 存储字 | 存储单元中二进制代码的组合 |
| 存储字长 | 存储字包含的二进制位数 |
| 地址 | 存储单元的编号 |

若 MAR 有 $n$ 位，则可编址的存储单元数为 $2^n$；若 MDR 有 $m$ 位，则每个存储单元的字长为 $m$ 位。因此：

$$
\text{存储容量}=2^{n}\times m\ \text{bit}
$$

例如 MAR 为 4 位、MDR 为 16 位时，共有 $2^4=16$ 个存储单元，每个单元 16 bit，总容量为

$$
2^4\times 16\ \text{bit}=256\ \text{bit}=32\ \text{B}
$$

> 注：教材例子默认“按字编址”，所以一个存储单元就是一个存储字；若按字节编址，一个地址对应 1 B，存储字长和存储单元大小要分开看。

==1 B = 8 bit，1 b = 1 bit==。`B` 表示字节（Byte），`b` 表示位（bit），这两个单位在容量题里经常被拿来设陷阱。

### 1.2.3 计算机软件

计算机软件分为两类：

| 类别 | 作用 | 典型例子 |
| --- | --- | --- |
| <span style="white-space:nowrap">系统软件</span> | 管理计算机硬件资源，向上层应用程序提供服务，提供运行环境 | 操作系统、编译器、汇编器、链接器、数据库管理系统 |
| <span style="white-space:nowrap">应用软件</span> | 按具体应用场景编制，直接为用户提供服务 | 办公软件、浏览器、游戏、各类业务程序 |

按照与硬件的接近程度，编程语言可分为三个级别：

| 语言 | 形式 | 能否被硬件直接执行 | 特点 |
| --- | --- | --- | --- |
| <span style="white-space:nowrap">机器语言</span> | 由 0 和 1 组成的指令序列 | 能 | 唯一能被计算机直接识别和执行的语言，编写和记忆困难 |
| <span style="white-space:nowrap">汇编语言</span> | 用英文助记符或缩写代替二进制指令，如 `mov`、`add` | 不能 | 可读性比机器语言好，但仍依赖具体机器结构，需经汇编程序翻译 |
| <span style="white-space:nowrap">高级语言</span> | 接近自然语言的程序设计语言，如 C、C++、Java | 不能 | 与具体硬件关系较弱，开发效率高，需经编译程序或解释程序处理 |

把源程序转换成机器语言程序的系统软件叫**翻译程序**，转换后得到的程序叫**目标程序**。三种常见翻译程序的区别如下：

| 翻译程序 | 输入 | 输出或结果 | 工作方式 |
| --- | --- | --- | --- |
| <span style="white-space:nowrap">汇编程序（汇编器）</span> | 汇编语言源程序 | 机器语言目标程序 | 把汇编指令翻译成机器指令 |
| <span style="white-space:nowrap">编译程序（编译器）</span> | 高级语言源程序 | 汇编语言或机器语言目标程序 | 一次性翻译，生成独立的目标程序 |
| <span style="white-space:nowrap">解释程序（解释器）</span> | 高级语言源程序 | 不生成独立目标程序 | 逐条翻译并立即执行 |

> 注：广义的“编译过程”还包括预处理、汇编和链接；408 题目里说“编译程序”时，通常特指把高级语言翻译成汇编语言或机器语言的那一环。

**软件和硬件在逻辑功能上是等价的**：同一个功能既可以用硬件实现，也可以用软件实现。例如乘法既可以用硬件乘法器完成，也可以用加法与移位程序完成。硬件实现通常速度快、成本高、灵活性差；软件实现通常灵活、成本低，但速度较慢。

**指令集体系结构（ISA）**是软件和硬件之间的关键接口。它从程序员和编译器的视角，定义一台计算机可以支持哪些指令、每条指令的作用是什么、指令格式和寻址方式如何、可以访问哪些寄存器等。ISA 是软件能够“感知”到的计算机功能视图，也叫**软件可见部分**。

### 1.2.4 计算机系统的层次结构

计算机系统是分层构建的。越往上越接近用户和问题，越往下越接近电路和器件；ISA 位于软件和硬件的交界处。

| 层次（自下而上） | 主要工作 | 一个小例子 | 典型角色 |
| --- | --- | --- | --- |
| <span style="white-space:nowrap">电路与器件</span> | 门电路、存储器件、逻辑电路 | 用 MOS 管搭成反相器，实现“非”运算 | 电子工程师 |
| <span style="white-space:nowrap">功能部件 / RTL</span> | 用寄存器传输级描述部件 | 用 `R1 ← R2 + R3` 描述一次寄存器之间的加法传送 | 电子工程师 |
| <span style="white-space:nowrap">微体系结构</span> | 数据通路、控制器、流水线、Cache、分支预测 | 同一条 `ADD` 指令可做成单周期执行，也可拆成五级流水线 | 架构师 |
| <span style="white-space:nowrap">指令集体系结构（ISA）</span> | 指令格式、操作类型、寻址方式、寄存器等 | 规定 `ADD R1,R2,R3` 的操作码、寄存器编号和 `R1 ← R2 + R3` 的含义 | 架构师、编译器开发者 |
| <span style="white-space:nowrap">操作系统 / 虚拟机</span> | 管理资源、抽象硬件、提供运行环境 | 程序调用 `read()` 读文件，由操作系统把文件操作映射为磁盘 I/O | 系统程序员 |
| <span style="white-space:nowrap">算法与编程</span> | 把问题抽象为算法，再编写程序 | 用 C 写循环 `for(i=0;i<n;i++) sum+=a[i]` 求数组元素之和 | 应用程序员 |
| <span style="white-space:nowrap">应用</span> | 面向最终用户完成具体任务 | 用浏览器打开网页，用户只关心页面内容，不关心底层如何传输 | 最终用户 |

**ISA 与微体系结构要分清。** ISA 回答“机器能做什么”，微体系结构回答“内部怎么做”。ISA 对软件可见，微体系结构对软件不可见；同一套 ISA 可以有多种不同的微体系结构。例如 Intel 的 Core、Skylake、Alder Lake 都遵循 x86 ISA，但内部的数据通路、流水线、缓存和分支预测设计并不相同。

| 对比项 | ISA | 微体系结构 |
| --- | --- | --- |
| 回答的问题 | 做什么 | 怎么做 |
| 是否对软件可见 | 可见 | 不可见 |
| 主要内容 | 指令格式、操作类型、寻址方式、寄存器、数据类型 | 数据通路组织、控制器实现、流水线级数、Cache 层次、分支预测 |
| 二者关系 | 同一 ISA 可有多种实现 | 某种 ISA 的具体硬件实现 |

> 注：这里的“透明”是“上层看不见、也不需要关心”，不是“能看穿”。ISA 以下的硬件实现对高级语言程序员是透明的。

操作系统是对硬件的抽象，它把底层硬件包装成一台可供程序员使用的“虚拟机”；各种语言处理程序也都在操作系统提供的运行环境中执行。应用程序员通常只面对高级语言和操作系统接口，不需要了解 ISA 以下的电路细节。

### 1.2.5 计算机系统的不同用户

按照使用计算机完成任务的性质，可以把用户分为四类：

| 角色 | 工作层面 | 主要职责 |
| --- | --- | --- |
| <span style="white-space:nowrap">最终用户</span> | 应用层 | 直接操作应用程序完成特定任务，如办公、浏览网页；不需要了解底层技术细节 |
| <span style="white-space:nowrap">系统管理员</span> | 操作系统层 | 配置、管理和维护计算机系统，如安装软硬件、管理账户、备份数据、系统升级 |
| <span style="white-space:nowrap">应用程序员</span> | 高级语言层 | 使用高级语言开发应用程序，满足办公、娱乐等领域的特定需求 |
| <span style="white-space:nowrap">系统程序员</span> | 机器语言 / ISA 层 | 设计并开发操作系统、编译器、数据库管理系统等核心系统软件 |

同一个用户在不同场景下可以承担多种角色。例如，一名计算机专业的学生：网上购物时是最终用户，管理磁盘和备份数据时是系统管理员，编写应用程序作业时是应用程序员，参与操作系统开发时是系统程序员。

系统程序员直接面向 ISA；系统管理员工作在操作系统层；应用程序员工作在高级语言层；最终用户位于最上层，通过应用程序完成任务。

取指阶段对所有指令都是相同的；分析阶段由操作码决定指令类型；执行阶段则因指令不同而走不同的数据通路。

一个 C 程序从源文件到可执行文件，通常要经过下面几个阶段：

![hello.c 经预处理、编译、汇编、链接生成 hello.exe 的流程；编译生成 hello.s，汇编生成 hello.o，链接器再把 hello.o 与 printf.o 等目标模块合并](408计算机组成原理/1.2计算机系统层次结构-1.2.6计算机系统的工作原理.png)

| 阶段 | 输入 → 输出 | 主要工作 |
| --- | --- | --- |
| <span style="white-space:nowrap">预处理</span> | `hello.c` → `hello.i` | 展开宏、包含头文件、处理条件编译、删除注释 |
| <span style="white-space:nowrap">编译</span> | `hello.i` → `hello.s` | 词法、语法、语义分析，生成汇编代码并优化 |
| <span style="white-space:nowrap">汇编</span> | `hello.s` → `hello.o` | 把汇编指令翻译成机器指令，形成可重定位目标模块 |
| <span style="white-space:nowrap">链接</span> | `hello.o` + 其他目标模块 → `hello.exe` | 符号解析、重定位，合并代码段和数据段，生成可执行文件 |

==目标模块还不是可执行文件==，它里面可能还有未确定的外部符号和待重定位的地址；链接器把这些模块合并、定位之后，才得到可以直接装入运行的 `hello.exe`。

一条指令通常由**操作码**和**地址码**组成：操作码指出要做什么，地址码给出操作数或下一条指令的地址。下面用一条“取数”指令，把取指、分析、执行三个阶段串起来。主存 0～4 号单元放指令，5～8 号单元放原始数据；PC 初值为 0，指向第一条指令。

![取数指令执行示例：主存 0～4 放指令、5～8 放数据；PC=0，指令 000001 0000000101 表示把地址 5 中的数取到 ACC](408计算机组成原理/1.2计算机系统层次结构-1.2.2计算机硬件(3).png)

| 阶段 | 微操作 | 结果 |
| --- | --- | --- |
| 取指 | `(PC) → MAR` | MAR = 0 |
| 取指 | `M(MAR) → MDR` | MDR = `000001 0000000101` |
| 取指 | `(MDR) → IR` | IR 中装入取数指令 |
| 取指 | `(PC) + 1 → PC` | PC = 1，指向下一条指令 |
| 分析 | `OP(IR) → CU` | CU 识别出这是“取数”指令 |
| 执行 | `Ad(IR) → MAR` | 地址码 5 送入 MAR |
| 执行 | `M(MAR) → MDR` | MDR = 2 |
| 执行 | `(MDR) → ACC` | ACC = 2 |

之后 PC = 1，CPU 取下一条乘法指令，把 ACC 中的 2 与地址 6 中的 3 相乘，ACC 变为 6；再执行加法，ACC 变为 7；执行存数指令后，地址 8 中的结果为 7；最后执行停机指令。整段程序的指令和数据都放在主存里，CPU 只是按 PC 逐条取指、译码、执行。

> 注：取指阶段对所有指令都一样，执行阶段才由操作码决定。把“取数”换成“乘法”“加法”或“存数”，分析阶段仍然相同，执行阶段的数据通路不同。

## 1.3 计算机的性能指标

描述存储容量、文件大小时，K、M、G、T 按 2 的幂递增；描述频率、速率时，按 10 的幂递增。两套单位不能混用。

| 用途 | K | M | G | T |
| --- | --- | --- | --- | --- |
| 存储容量、文件大小 | $2^{10}$ | $2^{20}$ | $2^{30}$ | $2^{40}$ |
| 频率、速率 | $10^{3}$ | $10^{6}$ | $10^{9}$ | $10^{12}$ |

==同样是 1K，表示容量时是 1024，表示频率时是 1000==。

主存容量由“存储单元数”和“每个存储单元的位数”共同决定。MAR 的位数决定存储单元数量，MDR 的位数反映每个存储单元的大小：

$$
\text{主存容量}=2^{\text{MAR 位数}}\times \text{MDR 位数}\ \text{bit}
$$

若结果要写成字节，再除以 8。MAR 位数决定的是地址空间中的单元数，不是容量本身；容量还要乘上每个单元的位数。

CPU 的时间指标围绕时钟周期、主频、CPI 和指令条数展开：

| 指标 | 含义 |
| --- | --- |
| 时钟周期 $T$ | CPU 中最小的时间单位，每个动作至少需要一个时钟周期 |
| 主频 $f$ | 时钟频率，$f=1/T$，单位为 Hz |
| CPI | 执行一条指令平均所需的时钟周期数 |
| CPU 执行时间 | 运行一个程序所花费的时间 |
| IPS | 每秒执行的指令条数 |
| FLOPS | 每秒执行的浮点运算次数 |

设程序共有 $IN$ 条指令，平均每条指令需要 $CPI$ 个时钟周期，主频为 $f$，则：

$$
T_{\text{CPU}}=\frac{IN\times CPI}{f}=IN\times CPI\times T
$$

$$
IPS=\frac{f}{CPI},\qquad IPC=\frac{1}{CPI}
$$

如果程序中包含多种指令，平均 CPI 按各类指令的比例加权：

$$
CPI=\sum_i CPI_i\times p_i
$$

其中 $p_i$ 是第 $i$ 类指令占总指令数的比例。`IPC` 表示每个时钟周期完成的指令数，在同一程序、同一 ISA 下，IPC 越大通常越快。

> 例：主频 $f=2\ \text{GHz}$，平均 $CPI=4$，执行 $10^9$ 条指令，则
>
> $$
> T_{\text{CPU}}=\frac{10^9\times 4}{2\times 10^9}=2\ \text{s}
> $$

~~主频越高，计算机一定越快~~。程序执行时间还取决于指令条数和 CPI；主频只是其中一个因素。

除了容量和速度，常见的性能指标还有：

| 指标 | 含义 |
| --- | --- |
| 数据通路宽度 | 数据总线或数据通路一次能传输的位数 |
| 吞吐量 | 单位时间内完成的任务量 |
| 响应时间 | 从发出请求到得到响应的时间 |
| 基准程序 | 用一组有代表性的标准程序评测计算机性能 |

几个“字长”容易混：

| 名称 | 含义 |
| --- | --- |
| 机器字长 | CPU 一次整数运算能处理的二进制位数，通常与通用寄存器、ALU 的宽度对应 |
| 存储字长 | 一个存储单元存放的二进制位数，通常与 MDR 宽度对应 |
| 指令字长 | 一条指令包含的二进制位数，不一定等于存储字长 |
| 数据通路宽度 | 一次数据传输能并行传输的位数 |

1. MAR 有 20 位、MDR 有 32 位，按字编址的主存容量是多少？

   答：$2^{20}\times 32\ \text{bit}=2^{20}\times 4\ \text{B}=4\ \text{MB}$。

2. 主频 3 GHz、平均 CPI 为 2，IPS 是多少？

   答：$IPS=3\times10^9/2=1.5\times10^9$ 条/秒。

3. “ISA 对软件透明”这句话对吗？

   答：不对。ISA 是软件可见的接口；对软件透明的是 ISA 以下的微体系结构和电路实现。

   答：不一定。PC 增加的是一个指令长度或地址单位；只有定长指令且按字编址时，才恰好是加 1。

## 2.1 数制与编码

### 2.1.1 进位计数制

`r` 进制数有 `r` 个不同数码，基数为 `r`，每一位的权是 `r` 的整数次幂。一个 `r` 进制数的数值等于各数码位与对应位权乘积之和。

设一个 `r` 进制数为

$$
(K_nK_{n-1}\cdots K_0.K_{-1}\cdots K_{-m})_r
=\sum_{i=-m}^{n}K_i r^i
$$

例如，$(1011.101)_2=8+2+1+0.5+0.125=11.625$。

二进制与八进制、十六进制之间可以按位分组转换：

| 转换 | 分组方法 | 例子 |
| --- | --- | --- |
| 二进制 → 八进制 | 每 3 位一组 | `1011010.1011` → `132.54₈` |
| 二进制 → 十六进制 | 每 4 位一组 | `1011010.1011` → `5A.B₁₆` |

分组时，整数部分从右向左分，小数部分从左向右分；不足一组时在小数点外侧补 0。以 `1011010.1011` 为例，转八进制要看成 `001 011 010 . 101 100`，转十六进制要看成 `0101 1010 . 1011`。

十进制转 `r` 进制时，整数和小数分开处理：

| 部分 | 方法 | 读数方向 |
| --- | --- | --- |
| 整数部分 | 除基取余，直到商为 0 | 先得到的余数是低位，最后从下往上读 |
| 小数部分 | 乘基取整，直到小数部分为 0 或达到所需精度 | 先得到的整数是高位，从上往下读 |

例如，$(13.625)_{10}=(1101.101)_2$：整数部分 $13$ 反复除以 2 得到 `1101`；小数部分 $0.625\times2=1.25$、$0.25\times2=0.5$、$0.5\times2=1.0$，依次取整数部分得到 `.101`。

**真值**是带正负号的实际数值，例如 $-1011_2$；**机器数**是把符号也数字化后存进机器的编码，例如用最高位 `1` 表示负数、用数值位表示绝对值。后面的原码、反码、补码和移码，讨论的就是机器数怎样表示真值。

### 2.1.2 定点数的编码表示

定点数的小数点位置固定。设机器字长为 $n+1$ 位，其中最高位 $x_0$ 是符号位，其余 $n$ 位是数值位。

四种常见编码的构造和表示范围如下：

| <span style="white-space:nowrap">编码</span> | 负数的构造 | 零的表示 | 表示范围 |
| --- | --- | --- | --- |
| <span style="white-space:nowrap">原码</span> | 符号位为 1，数值位不变 | `+0=00…0`，`-0=10…0` | $-(2^n-1)\le x\le 2^n-1$ |
| <span style="white-space:nowrap">反码</span> | 符号位为 1，数值位按位取反，末位不加 1 | `+0=00…0`，`-0=11…1` | $-(2^n-1)\le x\le 2^n-1$ |
| <span style="white-space:nowrap">补码</span> | 符号位为 1，数值位取反后加 1 | 只有一种 `00…0` | $-2^n\le x\le 2^n-1$ |
| <span style="white-space:nowrap">移码</span> | $[x]_{\text{移}}=2^n+x$；在字长相同且偏置为 $2^n$ 时，等于补码符号位取反 | 只有一种 `10…0` | $-2^n\le x\le 2^n-1$ |

正数的原码、反码和补码相同；负数的补码也可以写成 $[x]_{\text{补}}=2^{n+1}+x$（$x<0$）。==原码和反码有 $+0$、$-0$ 两种零，补码和移码的零唯一==。

四种编码不只是写法不同，它们在机器中的用途也不同：

| <span style="white-space:nowrap">编码</span> | 作用与体现 |
| --- | --- |
| <span style="white-space:nowrap">原码</span> | 符号位加绝对值，最直观，便于由真值写出编码；但加减法要单独处理符号，运算电路较复杂。浮点数的符号位与尾数绝对值分开存储，也体现了这种“符号—绝对值”思想。 |
| <span style="white-space:nowrap">反码</span> | 可以看成从原码求补码的中间形式：负数把原码的数值位取反，末位不加 1；现代计算机很少直接用它作为整数表示。 |
| <span style="white-space:nowrap">补码</span> | 现代计算机表示有符号整数的标准编码。它把减法统一成加法，符号位可以和数值位一起参加运算；零唯一，而且比原码、反码多表示一个最小负数 $-2^n$。 |
| <span style="white-space:nowrap">移码</span> | 把真值整体加上偏移量，编码大小顺序与真值大小顺序一致，便于比较阶码。408 中移码通常用于整数；IEEE 754 的阶码也用偏移编码的思想，但偏置取 127 或 1023，是移码的特例。 |

以 8 位机器数为例，$n=7$：

| 真值 | 原码 | 反码 | 补码 | 移码 |
| --- | --- | --- | --- | --- |
| $+5$ | `0000 0101` | `0000 0101` | `0000 0101` | `1000 0101` |
| $-5$ | `1000 0101` | `1111 1010` | `1111 1011` | `0111 1011` |

从表里可以直接看出：正数的前三种编码相同，移码与补码的符号位相反；负数的反码是原码数值位取反，补码是反码再加 1。移码全 0 对应最小真值 $-2^n$，全 1 对应最大真值 $2^n-1$，所以无符号比较移码的大小，就能比较真实数值的大小。

> **补充：移码与补码的符号位关系有前提。**
>
> 只有在**字长相同**、并且采用教材定义 $[x]_{\text{移}}=2^n+x$（偏置为 $2^n$）时，才有“移码 = 补码符号位取反”。IEEE 754 的阶码偏置是 127 或 1023，不能直接把补码符号位翻一下就当成阶码，必须按具体的 $x+\text{偏置值}$ 计算。

> **补充：补码为什么能把减法变成加法？**
>
> 在 $n+1$ 位机器中，所有运算按模 $M=2^{n+1}$ 进行。对负数 $x$，有 $[x]_{\text{补}}=M+x$，所以
>
> $$
> a-b\equiv a+(M-b)\equiv a+[-b]_{\text{补}}\pmod M
> $$
>
> 也就是说，减去 $b$ 等价于加上 $b$ 的相反数的补码；最高位产生的进位直接丢弃。以 8 位为例，$5-3=5+(-3)$：$[5]_{\text{补}}=$ `0000 0101`，$[-3]_{\text{补}}=$ `1111 1101`，相加得到 `1 0000 0010`，丢掉最高进位后是 `0000 0010`，即 2。实际电路中可用“把减数按位取反，再让加法器最低位进位输入 1”实现 $A+\overline B+1$。

**双符号位**（也叫变形补码）是在补码符号位前面再增加一位符号位，用两个符号位共同表示正负和溢出：

| 双符号位 | 含义 |
| --- | --- |
| `00` | 正数 |
| `11` | 负数 |
| `01` | 正溢出 |
| `10` | 负溢出 |

双符号位不是“两种符号”，而是给符号位增加一位冗余。正常结果的两个符号位必须相同；如果运算后出现 `01` 或 `10`，说明结果超出当前字长能表示的范围，发生了溢出，结果不能直接当作真实数值使用。例如用 5 位双符号补码：$+5$ 写成 `00 101`，$+4$ 写成 `00 100`，相加得到 `01 001`，表示正溢出；$-5$ 写成 `11 011`，$-4$ 写成 `11 100`，相加并舍去最高进位后得到 `10 111`，表示负溢出。

### 2.1.3 整数的表示

| 类型 | $n$ 位表示范围 | 8 位例子 | 典型用途 |
| --- | --- | --- | --- |
| 无符号整数 | $0\sim 2^n-1$ | `0000 0000` 到 `1111 1111`，即 $0\sim255$ | 地址、指针、只涉及非负数的计数 |
| 有符号整数（补码） | $-2^{n-1}\sim2^{n-1}-1$ | `1000 0000` 到 `0111 1111`，即 $-128\sim127$ | 一般带正负号的整数运算 |

无符号整数的所有二进制位都用来表示数值，没有符号位，所以在相同字长下最大值比有符号整数更大，但不能表示负数。无符号整数常用于地址运算、指针和不会产生负值的场景。

有符号整数通常把最高位作为符号位：`0` 表示正数，`1` 表示负数。现代计算机统一采用补码表示有符号整数，因为它具有三个优势：零的表示唯一；符号位可以和数值位一起参加运算，使减法统一成加法；比同字长的原码、反码多表示一个最小负数 $-2^{n-1}$。

同一个二进制串按不同类型解释，数值可能完全不同。例如 8 位 `1111 1111` 按无符号整数是 255，按补码有符号整数是 $-1$；==数据内容没有变，变的是解释方式==。

### 2.1.4 C语言中的强制类型转换

C 语言中的定点整数通常用补码存储。强制类型转换时，先要区分两种情况：宽度不变时，通常只是改变解释方式；宽度改变时，则会发生扩展或截断。

**位扩展、符号扩展和零扩展**：

| <span style="white-space:nowrap">操作</span> | 适用对象 | 规则 | 例子 |
| --- | --- | --- | --- |
| <span style="white-space:nowrap">位扩展</span> | 加宽数据宽度 | 是一个总称；有符号数按符号扩展，无符号数按零扩展 | 8 位扩展到 16 位 |
| <span style="white-space:nowrap">符号扩展</span> | 有符号补码 | 把原符号位复制到所有新增加的高位 | `1111 1011`（$-5$）→ `1111 1111 1111 1011` |
| <span style="white-space:nowrap">零扩展</span> | 无符号数 | 新增加的高位全部填 0 | `1111 1011`（251）→ `0000 0000 1111 1011` |

如果把位数变窄，就是**截断**：保留低位、丢掉高位，数值可能改变，也可能发生溢出。扩展和截断都只改变数据的位宽，不改变内存中已有的低位内容。

![C语言强制类型转换示例：同宽度的有符号/无符号重解释、int 到 short 的高位截断，以及 short 到 int 的符号扩展和零扩展](408计算机组成原理/2.1数制与编码-2.1.4C语言中的强制类型转换.png)

| 代码 | 位级变化 | 结果 |
| --- | --- | --- |
| `short x=-4321; unsigned short y=(unsigned short)x;` | 16 位内容不变，按无符号重新解释 | `0xEF1F` 表示 61215 |
| `int a=165537; short c=(short)a;` | 保留低 16 位，高 16 位截断 | `0x86A1`，按 16 位补码是 $-31071$ |
| `int b=-34991; short d=(short)b;` | 保留低 16 位，高 16 位截断 | `0x7751`，按 16 位补码是 30545 |
| `short x=-4321; int m=x;` | 负数做符号扩展 | `0xEF1F` → `0xFFFFEF1F`，真值仍为 $-4321$ |
| `unsigned short n=(unsigned short)x; unsigned int p=n;` | 先重解释为无符号，再做零扩展 | `0xEF1F` → `0x0000EF1F`，真值为 61215 |

> 注：该例按 `short` 16 位、`int` 32 位讲解；C 标准并没有在所有平台上固定这些类型的宽度，408 题目通常按题目给出的宽度计算。
