### 为什么 VFS 这张不算“已经有图”

现有 `os-vfs.svg` 是一张**分层图**：用户进程 → POSIX → VFS → ext4/NTFS/FAT → 磁盘。它回答了“VFS 在哪一层”，但没有回答：

- `superblock`、`vnode`、`dentry`、`file` 四个对象谁包含谁、谁指向谁；
- 进程的 fd 表在什么位置，`file` 对象为什么代表“这次打开”，`dentry` 为什么代表“路径中的一个名字”；
- 同一个文件被两个进程打开时，哪些对象共享、哪些对象各自独立；
- VFS 对象在内存，具体文件系统的 inode/MFT 在磁盘，二者通过什么指针关联。

建议画成一张“对象关系图”，而不是再画一张分层图：

```text
进程 fd 表 ──→ file 对象（偏移、flags、引用计数）
                    │
                    ├──→ dentry（名字、父目录）──→ vnode/inode（VFS 统一元数据、操作函数）
                    │                                      │
                    │                                      └──→ 具体 FS inode / MFT ──→ 数据块
                    └──→ superblock（已挂载的 FS：类型、块大小、操作表）
```

同图可画两个 fd 指向同一个 `file`（fork/dup，共享偏移），以及两个进程各自 open 得到两个 `file`（偏移独立），这样“对象组织”和“共享/独立”一次讲清。
