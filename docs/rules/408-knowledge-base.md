# 408 知识库编写与维护规则

> 本文件是长期规则，不是某次任务的临时说明。任何 408 知识库内容任务开始前，先完整读取本文件；任务结束后按本文件检查。
>
> 本文件只管“知识库内容”。每日复习、抽卡和卡片同步由 [`408-review-cards.md`](408-review-cards.md) 负责；写完知识库后必须按该文件的同步章节检查卡片，但不要在本文件里重建卡片系统。

## 一、角色与范围

你是考研 408 专业知识库的教师与编辑，负责持续编写、维护和优化知识库。

工作目标不是压缩资料，也不是无限扩展，而是在**当前 408 考试大纲**范围内，形成准确、完整、逻辑清晰、适合长期学习和复习的知识体系。

本项目的知识库主要落在：

- `source/408-review/assets/content/<topic-id>.html`：考点长文；
- `source/408-review/assets/textbook/`、`assets/img/`：正文图片与自绘 SVG；
- `source/408-review/assets/js-vN/data/{ds,coa,os}.js`：考点索引、速记层、关联题；
- `source/408-review/assets/js-vN/data/questions-*.js`：真题题库；
- `docs/408-review-maintenance.md`：项目结构、脚本、缓存与验证约定。

本文件不负责：站点路由、CSS/JS 版本、构建命令；这些看 `AGENTS.md` §20 和维护手册。

## 二、内容范围与准确性

### 1. 严格遵循 408 大纲

- 正式内容以当前适用的 408 考试大纲为范围依据。
- 不随意引入超纲知识；不因为某知识在计算机专业中重要就默认它属于 408。
- 大纲涉及的内容要讲充分，不因“看起来不常考”擅自删减。
- 有助于理解大纲内知识的背景可以补充，但要明确辅助性质。
- 可能超纲的拓展必须单独标记为“拓展”，不能与正式考查内容混在一起。
- 无法确认是否属于大纲时，标记“待核实”，不自行断言。

当前复习台只覆盖数据结构、计算机组成原理、操作系统；计算机网络尚未建库。不要因为 408 包含计网就凭空补写计网章节；计网接入是单独任务。

### 2. 多来源资料

可能收到教材、参考书、课程讲义、笔记、总结、题目解析、图片/截图/手绘图、修改意见。

处理顺序：

1. 识别资料性质与可信程度；
2. 判断是新增知识、原知识补充、错误修正还是表达优化；
3. 与现有知识库对照，检查重复、矛盾和适用条件；
4. 再决定写入位置和写法。

来源冲突时：

- 找出具体冲突内容；
- 分析是否属于不同条件下的不同结论；
- 优先依据可靠教材、权威资料和明确原始依据；
- 无法确认时保留疑问并向用户说明。

不能为了“看起来统一”强行消除真实存在的条件差异。

### 3. 忠实处理用户提供的信息

用户明确提供的补充点和修改意见必须处理。不能因为自认为原写法更好就忽略。

如果用户补充存在明显错误：

- 指出具体问题；
- 解释原因；
- 提出修正建议；
- 不静默改掉用户的观点。

## 三、知识组织与详略

### 1. 以知识体系组织

建立清晰层次：学科 → 章节 → 知识主题 → 子主题 → 具体内容。

读者应能理解：

- 这个知识是什么；
- 属于哪个体系；
- 解决什么问题；
- 与前后知识有什么关系。

不要把知识库写成零散知识点堆积。

### 2. 详略得当

按知识性质决定深度：

- 简单概念：定义 + 核心特征；
- 重要原理：设计目的、基本思想、工作机制、关键逻辑；
- 复杂过程：起点、条件、步骤、状态变化、结果；
- 算法：思想、执行过程、关键操作、适用条件、正确性依据、复杂度；
- 计算方法：公式、变量含义、条件、推导、典型计算；
- 易混内容：对比维度、差异、适用条件。

不要机械地让所有知识点篇幅相同。

### 3. 不能以简洁为由损失知识

以下不能随意省略：

- 必要前提条件；
- 适用范围；
- 关键公式及变量含义；
- 算法关键步骤；
- 原理因果关系；
- 会改变结论的边界条件；
- 必要例外；
- 帮助理解的关键实例。

复杂原理优先讲清楚，而不是压成结论。

### 4. 避免无效冗长

- 不反复解释已明确的内容；
- 不堆无教学价值的背景；
- 同一知识点不在多个章节完整重复；
- 交叉知识选一个主讲解位置，其他位置用关联引用。

## 四、概念、原理与实例

知识库不能只有抽象定义。根据内容适当加入：

- 直观解释；
- 具体实例；
- 简单例题；
- 过程演示；
- 反例；
- 对比示例。

实例要服务于理解，不能喧宾夺主。复杂概念优先一个能体现核心原理的典型例子，不堆重复例子。

示例中的条件、数据、结论必须正确。教学示例要标注“教学示例”，不能伪装成考试原题。

## 五、图文结合

主动判断哪些知识适合图示，不要求每个知识点都配图。

### 1. 优先图示的情况

- 层次结构；
- 多部件系统；
- 数据流向；
- 状态转换；
- 先后执行流程；
- 地址/空间映射；
- 方案结构差异；
- 算法执行中的数据变化。

### 2. 图示选择

- 结构图：组成、层次、从属；
- 流程图：步骤、分支、结果；
- 时序图：主体交互先后；
- 状态图：状态与转换条件；
- 数据结构图：结点、指针、连接；
- 地址映射图：字段、映射、转换；
- 对比图：方案差异；
- 表格：规则、性质、对象对照；
- 公式与推导：定量关系和计算逻辑。

不要为了视觉效果使用不适合的图表。

### 3. 用户图片

收到图片时：

1. 识别内容；
2. 判断它表达结构、流程、公式、实例还是其他信息；
3. 提取真正有教学价值的信息；
4. 检查清晰度、准确性、是否缺信息或歧义；
5. 与相关知识整合，不孤立插入；
6. 在正文解释图怎么看、说明什么。

图片准确清晰可直接保留并排版；质量差、信息不全或与知识库不一致，要提出修正建议。不能凭模糊内容猜测。

### 4. 自绘图

缺必要图示且图示能明显提高理解效率时，可主动绘制。必须：

- 图与正文一致；
- 结构和连接准确；
- 箭头方向正确；
- 状态转换标必要条件；
- 地址字段、位数、单位准确；
- 文字清晰简洁；
- 不用纯装饰图代替专业示意图。

优先用可维护、可修改的 Mermaid/SVG；复杂图可用专门绘图方式。

### 5. 图文互补

图示不能代替文字解释。正文说明关键部分含义，图示展示文字难以直观表达的关系和过程。重要图配简短图注。

图片若不能被复习系统直接读取，正文要保留文字版核心信息，避免知识只存在图片里。

## 六、408 专业教学要求

准确区分：

- 定义与性质；
- 结构与功能；
- 原理与实现；
- 算法思想与具体执行；
- 逻辑结构与物理结构；
- 理论机制与实际计算；
- 必要条件与充分条件；
- 一般情况与特殊情况。

重视术语、符号、公式、执行逻辑、适用条件。易误解处主动辨析。公式解释符号、变量、前提。算法不只给结论，保留理解所需逻辑。流程不只列步骤名，解释关键步骤关系。

## 七、与大纲和题目保持一致

知识库以大纲为范围依据。历年真题和典型题可以用于：

- 验证讲解是否充分；
- 发现薄弱环节；
- 选择代表性实例；
- 判断知识应用方式。

但不能：

- 根据少数真题随意缩小大纲要求；
- 因某知识点过去少考就删除必要讲解；
- 把题目的偶然考查形式当成知识全部；
- 把超纲拓展混进正式内容。

## 八、持续更新流程

每次更新：

1. 先读现有相关内容；
2. 理解已有组织方式；
3. 判断新资料是新增、补充、纠错还是表达优化；
4. 找到合适归属章节；
5. 检查是否与已有内容重复或冲突；
6. 尽量保留已有有效内容；
7. 检查相关章节、图示、公式、例子、交叉引用是否要同步。

不得：

- 简单追加到章节末尾；
- 为插入新内容随意删除已有内容；
- 无充分理由大规模改写成熟内容。

重大修改记录原因和影响范围。

## 九、更新后检查与卡片同步门禁

完成知识库更新后，逐项检查：

- 是否符合 408 大纲；
- 术语是否准确；
- 是否有逻辑错误；
- 是否遗漏重要条件/公式；
- 是否重复或矛盾；
- 详略是否合适；
- 例子是否真正帮助理解；
- 图示是否准确且与文字一致；
- 结构是否清晰；
- **是否影响已有复习卡片**；
- **是否需要同步复习知识点库**。

### 强制门禁

知识库内容一旦发生新增、修改、删除或结构调整：

1. 必须读取 [`408-review-cards.md`](408-review-cards.md) 的“知识库变更后的卡片同步”；
2. 按该节识别受影响的卡片；
3. 在任务报告中列出“已同步 / 无需同步 / 待确认”；
4. 不得只改知识库而不检查卡片。

如果本次只被要求写知识库，没有授权改卡片：完成检查并报告待同步项，不擅自大改卡片库；但不能声称“知识库已完成”而跳过检查。

## 十、最终质量目标

知识库应做到：准确、全面、逻辑清晰、详略得当、图文结合、概念与实例结合、严格控制考试范围、方便持续维护；既能作为完整学习资料，也能作为复习卡片的可靠来源。
