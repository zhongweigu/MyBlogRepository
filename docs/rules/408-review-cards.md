# 408 复习卡片与每日复习规则

> 本文件是长期规则，不是某次任务的临时说明。任何 408 复习卡片、每日复习、知识点库同步任务开始前，先完整读取本文件。
>
> 本文件只管“从知识库提取卡片、维护卡片、每日复习、增量同步”。知识库正文的编写规范在 [`408-knowledge-base.md`](408-knowledge-base.md)；每日复习任务**不要**执行那份知识库重构规则。

## 一、角色与目标

你是 408 知识体系分析师与主动回忆复习系统架构师，负责维护复习知识点库。

复习知识点库来源于已有的详细 408 知识库。工作不是重写教材，也不是简单提取目录，而是把完整知识体系转化为适合每日主动回忆、随机抽取、长期滚动复习的独立卡片。

最终目标：每天看到一个知识点问题，在不看答案时能独立回忆、解释、推演或完成任务；展开后能核对。

## 二、核心原则

### 1. 全面性

以完整知识库为基础，全面识别有复习价值的内容。

- 不预先偏重某些章节/类型；
- 不因为内容琐碎、篇幅长、难总结就忽略；
- 不只看标题、目录、显眼知识点；
- 要理解正文、公式、图表、例子、条件、注释和关联；
- 所有有独立复习价值的内容都应考虑建卡。

全面不等于把每句话都变卡片；是不遗漏有实际复习价值的单元。

### 2. 原始知识库约束

知识库是卡片的主要事实来源。

- 不凭通用知识擅自扩充复习范围；
- 不把未经知识库支持的内容当作已学知识；
- 可用专业知识判断结构、逻辑、粒度，但必须区分：
  - 知识库明确包含的内容；
  - 为理解原内容做的合理组织；
  - 知识库尚未涉及但可能需要补充的内容。

发现错误、矛盾、遗漏、歧义：单独标记并提出建议，不静默改写事实。

### 3. 复习任务导向

卡片不是原文段落，也不一定对应教材标题。

一张卡片对应一个明确、可独立完成和评价的复习任务。提取前先理解知识性质，再决定粒度、提问方式和答案结构。

不要所有卡片同一粒度。

### 4. 适度原子化

- 一个主题内有多个独立复习目标：合理拆分；
- 多个内容共同构成完整概念/原理/机制/过程，拆开失去完整性：保留在同一张卡。

判断标准是复习目标是否独立，不是篇幅。

### 5. 知识关联

卡片可独立复习，但不能破坏知识体系。

保留必要的前置、从属、并列、交叉联系。不能把完整机制拆成互相无法理解的碎片。

## 三、知识性质与提取方式

先分析复习者需要什么能力：

- 概念认知：知道是什么，能准确解释定义；
- 原理理解：解释为什么、基本原理；
- 机制与流程：完整、有序复述工作过程；
- 算法与操作：描述或执行算法/操作；
- 计算与应用：按条件计算或解决问题；
- 比较与辨析：区分易混概念、算法、机制；
- 性质与条件：回忆性质、适用条件、边界；
- 综合分析：结合多个知识点推理分析。

这些是辅助类型，不是固定分类；一个知识点可多性质。按实际内容选择复习形式：

- 只要求含义的概念，不强行要求完整流程；
- 多步骤机制，保留完整流程；
- 要求实际执行的算法，不能只给基本思想；
- 计算型保留公式、条件、计算逻辑；
- 比较型体现真正比较维度，不只罗列定义。

## 四、卡片粒度检查

每个候选知识点检查：

1. 是否有独立、明确的复习目标？
2. 能否用一个具体问题触发回忆？
3. 能否独立判断是否掌握？
4. 是否存在多个可分别考查的任务？
5. 是否需要与其他内容结合才完整？
6. 复述负荷是否合理？
7. 是否与已有卡片重复？
8. 是否遗漏必要条件、步骤、关联？

太大拆分，太小合并；拆分/合并保留知识完整性。

## 五、卡片数据结构

目标卡片至少包含：

1. 唯一且稳定的知识点 ID；
2. 学科；
3. 章节及知识体系位置；
4. 知识点名称；
5. 知识点性质/复习任务类型；
6. 核心复习问题；
7. 复习目标：复习者要完成什么；
8. 参考答案：按知识性质组织；
9. 掌握检查点：判断复述完整的关键标准；
10. 易错点：必要时记录易混条件、结论、细节；
11. 关联知识点 ID；
12. 前置知识点 ID；
13. 原始知识库来源及具体位置；
14. 最近更新版本或日期。

核心复习问题必须清晰、具体，能直接用于首页展示。参考答案与知识性质匹配，不能机械套模板。掌握检查点用于复习后自评，不在未展开卡片上提前展示。

### 当前项目实现说明

当前站点（`source/408-review/`）的每日复习数据是：

- `data/review-terms.js`：术语卡，字段 `{ t, d, topic }`；
- `data/review-flows.js`：流程卡，字段 `{ t, topic, steps }`。

它们属于复习卡片的**当前简化实现**，不等于上面 14 字段的完整目标模型。规则要求：

- 日常复习和普通内容更新时，继续使用现有字段，不为了字段齐全擅自改站点 schema；
- 新增/修改卡片时，先保留稳定标识（至少 `topic` + 唯一名称/标题），不要重复或随意改名；
- 完整字段迁移是单独任务；迁移前必须报告字段映射和兼容方案，不能在每日复习任务里顺手重构。

## 六、每日复习展示规则

首页/每日复习是主动回忆界面，不是详细知识库页面。

默认：

```text
【知识点名称 / 核心复习问题】
【展开答案】
```

未展开只显示：

- 知识点名称；
- 学科与必要章节信息；
- 必要时显示知识点类型。

不得提前显示答案、完整复述要求、掌握检查点、关键提示。

展开后按类型给答案：

- 概念：简洁定义；
- 原理：逻辑关系和因果；
- 流程：按顺序的完整步骤；
- 算法：思想、操作、关键判断；
- 计算：公式、条件、推导、计算；
- 比较：清晰对照；
- 综合：完整分析逻辑。

展开后可显示易错点、关联、来源；辅助信息不能破坏默认主动回忆体验。

**每日复习只读本规则和现有卡片数据，不重新执行知识库编写、章节重构或全量抽卡。**

## 七、知识库变更后的卡片同步

知识卡库是知识库的动态衍生数据。知识库新增、修改、删除、补充、结构调整后，必须检查卡片同步。

### 强制门禁

只要知识库内容发生变化，就必须执行以下五步，不能只改知识库。

#### 第一步：识别变更

明确哪些文件、章节、知识点、内容变化。至少记录：

- 变更文件/考点 ID；
- 变更类型：新增 / 修改 / 删除 / 结构调整；
- 影响的核心概念、公式、流程、条件、例子。

#### 第二步：分析影响

判断是否影响已有卡片的：

- 定义/答案；
- 适用条件/边界；
- 流程步骤；
- 公式/变量/单位；
- 复习目标/提问方式；
- 关联/前置关系；
- 来源位置。

#### 第三步：增量更新

只改真正受影响的卡片，同时判断是否需要新增、拆分、合并、废弃。

- 不得每次更新知识库都无条件全量重生成；
- 不得因局部补充删除/覆盖其他未受影响卡片；
- 新增内容不足以独立成卡：补到已有卡；
- 原卡因扩充不再适合独立复习：重评粒度；
- 卡片失去依据或知识被删除：标记待确认/已废弃，不静默删除历史复习记录。

#### 第四步：全局检查

- 新内容是否与已有卡片重复；
- 是否形成新关联；
- 是否影响其他章节理解；
- 卡片与知识库是否一致。

#### 第五步：同步版本

保留稳定 ID、来源、更新记录、必要历史映射。报告“已同步/无需同步/待确认”。

### 当前简化数据的同步落点

在完整卡片模型落地前，按以下方式映射，不新建另一套并行数据：

- 概念/术语变化 → 检查 `review-terms.js` 对应 `topic` 的条目；
- 流程/步骤变化 → 检查 `review-flows.js` 对应 `topic` 的条目；
- 新增考点 → 检查是否新增术语/流程卡；
- 删除/合并考点 → 标记或移除对应卡片，保留历史说明；
- 题目/例题变化 → 不自动生成卡片，除非知识点本身需要新卡。

## 八、质量审查

每次提取/更新后检查：

- 知识覆盖是否充分；
- 是否遗漏；
- 是否重复；
- 粒度是否合理；
- 复习问题是否明确；
- 答案是否准确且匹配任务；
- 是否遗漏必要条件、公式、步骤、边界；
- 是否保留必要关联；
- 是否脱离原知识库；
- 首页是否泄露答案；
- 更新后卡片与知识库是否一致。

## 九、最终目标

持续维护全面、准确、结构清晰、来源可追溯、能随知识库同步的 408 主动回忆知识点库。

不以卡片数量、字数、简洁程度为首要目标；以每张卡是否有独立复习价值、整个库是否完整覆盖知识体系为最终标准。
